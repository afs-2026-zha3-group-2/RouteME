## 1. Intent

在行程详情页告诉用户「还有谁适合一起去」，并把「为什么」拆成可以逐项核对的分：目的地 +50、日期 +30 / 差一天 +20、共同兴趣每项 +10（最多 +20）。分数只由后端产出。

## 2. Actors

| 角色 | 澄清 |
|---|---|
| 查看者 | 打开任一已发布行程详情；看到推荐列表或明确空状态；可打开候选资料 / 行程。 |
| 发布者 | 同样能看推荐，用于主动寻找同行者；不会看到自己。 |
| 系统 | 以当前行程 + 当前用户兴趣计算；候选只取开放行程；同人去重；稳定排序。 |
| 其他旅行者 | 只暴露公开资料摘要与公开行程摘要，不暴露联系方式。 |

## 3. In / Out scope

**In scope**

- `GET /api/trips/{tripId}/recommendations`：只读，返回 `reference` + `items[]`。
- 评分：目的地相同 50、日期相同 30、相差一天 20、共同兴趣每项 10 且合计 ≤20，总分 ≤100。
- 候选：开放行程（未结束 / 未取消）、排除当前用户、排除参照行程自身、排除 0 分。
- 去重：同一发布者保留最高分行程；同分按日期差、再按行程 id。
- 排序：总分倒序，同分旅行日期更接近者优先。
- 响应字段：`user`、`trip`、`score`、`breakdown[]`、`reasons[]`、`shared_interests[]`。
- 详情页推荐区块：加载 / 成功 / 空状态 / 失败可重试；切换行程或资料兴趣变化后重新请求。
- 契约：`openapi.yaml` 0.19.0 + 路径与 4 个 schema。
- 测试：规则纯函数、接口行为、契约断言、前端格式化纯函数、E2E 推荐区块。

**Out of scope**

- 机器学习 / LLM 打分；推荐理由生成模型。
- 预算、路线重合度、天气偏好、信用分、旅行节奏等特征（仅保留扩展结构）。
- 邀请 / 申请 / 聊天链路改造。
- 地图探索页 Mock 同行者面板（路线重合展示线）。
- 数据库迁移与数据回填。
- 推荐结果缓存、分页、A/B 实验。
