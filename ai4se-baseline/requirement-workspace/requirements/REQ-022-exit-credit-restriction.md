# REQ-022 — 退出同行扣分与低信用自动限制（Ready 需求草稿）

- **能力：** `credit-enforcement`（ADDED）；依赖 `user-credit`（账户 / 账本）、`trip-companions`（退出关系）、`trip-cancellation`（行程取消，未归档）
- **对应 OpenSpec change：** `add-credit-exit-restriction`
- **草稿日期：** 2026-11-17 ｜ **状态：** P1 drafted（blocking OQ 0，DoR BLOCKER 0）
- **故事来源：** 用户当次会话 P0 卡片「[P0] 退出同行扣减信用分」；Story 4（信用系统迭代 2 / 5 点 / 详情页 + 我的旅行）与 Story 5（信用系统迭代 3 / 3 点 / 用户详情页 + 个人主页）
- **证据：** `requirement-workspace/intents/REQ-022-exit-credit-restriction.md`；`docs/sdd/add-credit-exit-restriction/p0-baseline.md`

## Discovery Decision

**Go（light intake，2026-11-17）。** 两个故事共享同一条信用执行链：退出产生扣分 → 分数跌破 60 → 自动限制。拆成两个 change 会让「扣分后限制」无法在一次验收内观察；按用户裁决合并为一个 change、一个 REQ、两个故事文件。能力边界为新 `credit-enforcement`，不改未归档的 `user-credit` / `trip-cancellation` / `trip-companions` Delta。

## 1. Intent

一句话：让「退出同行」不再是无成本动作——退出前先看清本次会扣多少分，确认后按规则记账；分数跌到 60 以下时账号自动进入只读状态，先把未完成的同行关系和已发布行程安全收口，等分数回到 60 再自动解除，但被清退的关系不会自动回来。

## 2. Actors

| 角色 | 权限边界 |
|---|---|
| 已接受同行者（退出者） | 可发起退出；必须选择原因；可看到本次预计影响；退出成功后该行程关系解除；不能是发布者；不能对已完成/已取消行程退出。 |
| 受限用户 | 可查看首页、详情、我的旅行、个人主页、信用状态与聊天历史；可举报 / 使用安全入口；不可发布、申请、发体验、编辑行程/体验、发消息、改资料/头像。 |
| 其他用户 / 发布者 / 申请者 | 在五个信用展示面看到分数、等级与「限制中」徽标；MUST NOT 看到限制原因或加扣分明细。 |
| 系统内部信用执行 | 唯一可写信用分与限制记录的一方；负责退出扣分、限制触发、自动清理、自动解除；不向客户端暴露写入口。 |
| 管理员 | 本 change **不存在**管理员角色、后台接口、核实页面或人工封禁入口。 |
| 未来管理员核实（后续 change） | 只作为领域行为预留：待核实退出可被后续 change 核实为真/不属实；本 change 不提供任何客户端或后台入口。 |

## 3. In / Out scope

**In scope**

- 退出原因：`personal`（个人原因）/ `force_majeure`（不可抗力）/ `safety`（安全原因）；必选；安全原因在退出后引导到既有举报入口。
- 预计信用影响：服务端计算并返回；三个入口共用；确认时服务端重新校验并返回实际结果。
- 扣分阶梯：出发前 ≥7 天 0；[3 天, 7 天) -3；[24 小时, 3 天) -5；[12 小时, 24 小时) -8；[0, 12 小时) -10；旅行中 -15。
- 出发基准：`meeting_time` 有值时以它为基准；为空时用 `start_date` 00:00（Asia/Shanghai）。
- 月度累进：按退出动作所在自然月；只有已生效的出发前退出扣分计入；旅行中、≥7 天免责、待核实免责不计入；第 2 次及之后翻倍（-6 / -10 / -16 / -20）；0 分下限裁断为实际 0 的事件仍计入次数。
- 待核实：不可抗力 / 安全原因退出暂不扣分，写零值信用记录并标记待核实；本 change 不提供核实入口；未来核实为真 → 不扣分、不计数；核实不属实 → 按实际退出时间补扣，按核实当时该月已有扣分次数取下一序号（不是第一次则翻倍），不追溯调整其他已结算退出。
- 信用记录：每次退出事件写一条 `credit_ledger`（含原因、实际变化量、前后分数、时间、关联行程、幂等键）；0 分裁断与免责也留痕。
- 限制触发：分数 <60 自动建立限制记录（原因 `CREDIT_SCORE_BELOW_60`）；分数 =60 不触发。
- 限制记录：用户、触发原因、触发分数、触发时间、解除时间、解除原因、类型（本 change 只产生自动限制；人工封禁为未来独立类型）。
- 只读守卫：发布新行程、申请加入、发布/编辑体验、编辑行程、发送聊天消息、编辑资料/头像；查看与举报/安全入口保留。
- 限制触发联动：撤回全部待处理申请；解除全部未结束（招募中/已满员/旅行中）的已接受同行关系；自动取消全部未结束的已发布行程；系统清退不扣分、不计入当月次数；已完成/已取消保留历史。
- 系统取消原因：新增「信用分低于 60，账号受限」；发布者与已接受同行者可见，其他用户只看到「已取消」。
- 限制展示：本人个人主页显示限制状态、原因、自动解除说明；五个信用展示面给他人显示「限制中」徽标，不显示原因。
- 自动解除：分数回到 ≥60 时限制记录置为已解除；只读守卫解除；不恢复原申请与同行关系。
- 合同与迁移：`openapi.yaml` 升次版本；新增 `V21` 迁移（限制表 + 退出事件/申请退出原因 + 必要索引）。
- 测试：后端单元/集成/迁移双引擎；前端纯函数 + 组件；E2E 覆盖退出与限制主路径；OpenSpec strict 校验。

**Out of scope**

- 管理后台全部内容：用户列表、用户详情、按信用分排序/筛选、管理员角色、核实页面、人工封禁、申诉。
- 管理员核实的人工操作入口；本 change 只落领域行为与待核实状态。
- 加扣分明细、原因、时间、历史记录列表；用户端「信用记录」按信用状态理解。
- 安全学习页面、客服系统、可点击的「如何恢复」入口；入口待定，不放假链接。
- 解除限制后恢复原申请/同行关系；被取消的行程恢复。
- 通知 / 推送 / 邮件 / 站内信。
- 体验获赞加分、举报核实扣分的完整业务流程；举报核实只作为未来触发源。
- 修改 `trip-companions`「退出同行」的聊天保留语义；本 change 沿用当前代码与未归档 `refine-trip-chat` 的口径。
- 修改 `trip-cancellation` 的发布者取消规则；本 change 只新增系统取消路径与系统原因。
- 对已完成/已取消历史行程的清理或改写。

## 4. Scenarios + AC hints

### A. 退出原因、预计影响与扣分（S22）

1. **S22-1 退出原因必选** — Given 已接受同行者打开退出流程，When 未选择原因即确认，Then 前端阻止提交并提示选择原因；服务端同样以 400 `INVALID_INPUT` 拒绝；退出关系、分数与账本均不改变。
2. **S22-2 个人原因 48 小时预计 -5** — Given 用户 ACCEPTED、信用分 80、集合时间在 48 小时后、当月无已生效出发前退出，When 选择「个人原因」并确认，Then 预计影响显示「本次 -5，退出后 75 / 100」；退出成功；信用分 80→75；账本记录原因、-5、前 80、后 75、关联行程、时间；当月序号 1。
3. **S22-3 不可抗力暂不扣分** — Given 已接受同行者、信用分 80，When 选择「不可抗力」并确认，Then 退出成功、分数仍 80、写一条零值账本记录、标记待核实、不计入当月次数；页面提示「暂不扣分，待核实」。
4. **S22-4 安全原因暂不扣分并引导举报** — Given 同上，When 选择「安全原因」并确认，Then 退出成功、分数不变、写零值待核实记录、不计入次数；退出后展示既有举报入口，用户可前往举报；不强制举报。
5. **S22-5 7 天及以上只记录事实** — Given 出发基准 ≥7 天，When 选择「个人原因」并确认，Then 分数不变；写零值账本记录（原因 `EXIT_BEFORE_TRIP_NO_PENALTY`）；不计入当月次数；预计影响显示「不扣分，仅记录」。
6. **S22-6 3–7 天 -3** — Given 距出发 [3 天, 7 天)，When 个人原因退出，Then 扣 -3；当月首次；账本与展示一致。
7. **S22-7 24–72 小时 -5** — Given 距出发 [24 小时, 3 天)，When 个人原因退出，Then 扣 -5。
8. **S22-8 12–24 小时 -8** — Given 距出发 [12 小时, 24 小时)，When 个人原因退出，Then 扣 -8。
9. **S22-9 12 小时内 -10** — Given 距出发 [0, 12 小时)，When 个人原因退出，Then 扣 -10。
10. **S22-10 旅行中 -15** — Given 当前时间 ≥ 出发基准且行程未完成/未取消，When 退出确认，Then 固定 -15；不翻倍；不计入月度次数。
11. **S22-11 边界左闭右开** — Given 距出发恰好 7 天 / 3 天 / 72 小时 / 24 小时 / 12 小时，When 个人原因退出，Then 分别扣 0 / -3 / -3 / -8 / -10；少 1 秒时分别进入下一档（-3 / -5 / -8 / -10 / -10）。
12. **S22-12 月度第 2 次翻倍** — Given 当月已有 1 次已生效出发前退出扣分，When 第 2 次个人原因退出，Then 按档位翻倍（-6 / -10 / -16 / -20）；旅行中 -15 不翻倍；≥7 天免责与待核实不计入。
13. **S22-13 第 3 次及之后仍翻倍** — Given 当月已有 ≥2 次已生效出发前退出扣分，When 再次个人原因退出，Then 仍按翻倍值扣分；不继续叠加倍率。
14. **S22-14 待核实后来变为扣分** — Given 当月已有 1 次已生效扣分且存在 1 条待核实退出，When 该待核实被内部核实为不属实，Then 按实际退出时间确定档位，并按核实当时该月已有扣分次数取下一序号（本例为第 2 次，翻倍）；计入当月次数；不追溯调整其他已结算退出。
15. **S22-15 待核实核实为真** — Given 一条待核实退出，When 内部核实为真，Then 不扣分、不计入次数；记录标记核实为真；分数不变。
16. **S22-16 0 分下限裁断** — Given 用户当前 0 分，When 一次出发前退出扣分事件发生，Then 分数仍 0；账本记录实际变化 0；该事件仍计入当月次数；预计影响显示「当前分数已在下限，本次实际变化 0」。
17. **S22-17 幂等与并发** — Given 同一用户对同一行程快速确认两次或并发提交，When 两次都到达服务端，Then 只解除一次关系、只写一条退出账本、分数只变化一次；第二次返回成功或幂等结果，不重复扣分。
18. **S22-18 非同行者 / 发布者 / 终态行程不能退出** — Given 用户不是 ACCEPTED 同行者、或是发布者、或行程已完成/已取消，When 尝试退出，Then 服务端按既有规则拒绝；不写账本、不改分数；发布者提示改用结束/取消行程。
19. **S22-19 三个入口一致** — Given 用户分别从行程详情、我的旅行、聊天页点击退出，When 打开流程，Then 三处都展示原因选择与同一份服务端预计影响；确认后三处都得到一致结果；前端不自行计算扣分。
20. **S22-20 预计与实扣一致** — Given 预计影响已展示，When 用户在确认前该月新增了一次已生效退出，Then 服务端在确认时重新计算并返回实际扣分；页面以实际结果为准；不出现「预计 -5、实扣 -10」的静默差异。
21. **S22-21 集合时间优先与回退** — Given 行程 `meeting_time` 有值，When 计算距出发时间，Then 以该日期时间为基准；Given `meeting_time` 为空，Then 以 `start_date` 00:00（Asia/Shanghai）为基准；Given 发布者在退出后修改集合时间，Then 已结算扣分不回溯变化。
22. **S22-22 退出原因与明细不对外** — Given 用户完成退出，When 其他用户查看该行程或该用户信用展示面，Then 只看到既有分数/等级与「已退出」关系，不看到退出原因、预计影响或加扣分明细。

### B. 低信用自动限制（S23）

23. **S23-1 跌破 60 自动触发** — Given 用户信用分 65，When 一次 -10 的举报核实扣分使其变为 55，Then 系统自动建立限制记录（原因 `CREDIT_SCORE_BELOW_60`、触发分数 55、触发时间、状态 active）；无需管理员操作；用户看到限制状态与原因。
24. **S23-2 60 与 59 边界** — Given 分数为 60，When 读取/变更后仍为 60，Then 不触发；Given 分数变为 59，Then 触发。
25. **S23-3 限制记录幂等** — Given 用户已处于 active 限制，When 又一次扣分使其仍 <60，Then 不新增第二条 active 限制记录；历史不被覆盖；限制状态保持。
26. **S23-4 本人看到原因与自动解除说明** — Given 用户受限，When 打开自己的个人主页，Then 展示当前分数、等级、「限制中」、限制原因「信用分低于 60」与「分数回到 60 分及以上自动解除」；不展示逐条明细。
27. **S23-5 他人看到限制徽标、不看原因** — Given 受限用户出现在个人主页、资料弹窗、详情发布者行、行程卡发布者行、申请者行，When 他人查看，Then 五个展示面都显示「限制中」徽标；不显示限制原因；分数与等级仍按既有口径展示。
28. **S23-6 不能发布新行程** — Given 用户受限，When 尝试发布新行程，Then 前端禁用入口并说明原因；绕过界面调用返回 403 `CREDIT_RESTRICTED`；不创建行程。
29. **S23-7 不能申请加入新行程** — Given 用户受限，When 尝试申请加入，Then 前端禁用入口并说明原因；服务端 403 `CREDIT_RESTRICTED`；不创建申请。
30. **S23-8 不能发布新体验** — Given 用户受限，When 尝试发布体验，Then 前端禁用入口并说明原因；服务端 403 `CREDIT_RESTRICTED`；不创建体验。
31. **S23-9 不能编辑既有内容** — Given 用户受限，When 尝试编辑既有行程或既有体验，Then 服务端 403 `CREDIT_RESTRICTED`；内容不变；前端不展示可编辑入口。
32. **S23-10 不能发送聊天消息** — Given 用户受限且仍有历史会话，When 打开聊天，Then 可查看历史消息；发送被 403 `CREDIT_RESTRICTED` 拒绝；页面提示限制原因与自动解除说明。
33. **S23-11 不能编辑资料/头像** — Given 用户受限，When 尝试保存资料或上传头像，Then 服务端 403 `CREDIT_RESTRICTED`；资料/头像不变。
34. **S23-12 查看与举报保留** — Given 用户受限，When 浏览首页、详情、我的旅行、个人主页、信用状态、聊天历史，或使用举报/安全入口，Then 均可用；登录/退出不受影响。
35. **S23-13 自动撤回待处理申请** — Given 用户受限且存在待处理申请，When 限制触发，Then 全部待处理申请变为已取消/已撤回；发布者不能再处理；用户「我申请的」显示对应状态；不产生退出扣分。
36. **S23-14 自动解除未结束同行关系** — Given 用户受限且存在未结束行程的已接受同行关系，When 限制触发，Then 全部关系解除；已加入人数 -1；满员行程恢复招募中；已完成/已取消历史保留；不产生退出扣分、不计入当月次数。
37. **S23-15 自动取消未结束已发布行程** — Given 用户受限且存在招募中/已满员/旅行中的已发布行程，When 限制触发，Then 全部自动取消；待处理申请取消；已接受同行者保留但看到已取消；聊天只读；新申请被拒绝；不产生退出扣分。
38. **S23-16 系统取消原因可见性** — Given 行程因信用限制被自动取消，When 发布者或已接受同行者查看详情，Then 看到系统原因「信用分低于 60，账号受限」；其他用户只看到「已取消」，不看到原因与限制细节。
39. **S23-17 已完成/已取消不受影响** — Given 用户受限且存在已完成/已取消行程，When 限制触发，Then 这些历史行程与关系保持原样；不重复取消、不重复解除。
40. **S23-18 分数回到 ≥60 自动解除** — Given 用户受限，When 一次加分或调整使其分数回到 60 或更高，Then 限制记录置为已解除（记录解除时间与原因）；只读守卫解除；用户可再次发布/申请/发体验/聊天/编辑资料；不恢复原申请与同行关系。
41. **S23-19 再次跌破 60** — Given 用户曾受限并已解除，When 分数再次跌破 60，Then 新建一条 active 限制记录；上一段限制历史保留；再次执行自动清理。
42. **S23-20 限制与人工封禁分开** — Given 本 change 上线，When 检查限制记录与入口，Then 只存在自动限制类型与 `CREDIT_SCORE_BELOW_60` 原因；不存在人工封禁记录、管理员入口或人工解除入口；未来人工封禁必须使用独立类型与独立记录。
43. **S23-21 无管理端与无客户端写入口** — Given 任意客户端身份，When 尝试调用核实、解除、人工封禁或直接写限制状态的接口，Then 系统不存在该类端点；按既有未找到/未允许响应处理；限制状态只能由分数变化驱动。
44. **S23-22 触发事务一致性** — Given 一次扣分使分数跌破 60，When 限制触发，Then 分数变化、限制记录、撤回申请、解除关系、取消行程在同一事务内完成；任一步失败则整体回滚，不出现「已扣分但未限制」或「已限制但未清理」的半状态；重复触发幂等。
45. **S23-23 系统清退不扣分** — Given 限制触发自动撤回/解除/取消，When 检查信用账本与当月次数，Then 不新增退出扣分账本、不增加当月退出次数；只记录限制与关系/行程状态变化。
46. **S23-24 限制状态下并发写入** — Given 用户被限制的同时有并发写请求（发布/申请/发消息），When 请求到达，Then 限制守卫以服务端当前状态为准拒绝；不因前端缓存或竞态放行。

## 5. Constraints

- **口径（D2）：** 以 Story 5 为准，REQ-019 D1 的「不引入自动封禁」被取代；0–100 五档不变。
- **管理端（D3）：** 本 change 不建管理员角色、后台接口、核实页面或人工封禁；待核实可以一直 pending。
- **可见性（D4 / D10）：** 用户端不展示加扣分明细；本人可见限制原因；他人只见「限制中」徽标；五个信用展示面同口径。
- **恢复（D5 / D12）：** 限制由当前分数派生；≥60 自动解除；不人工解除；不恢复原申请/同行关系；「如何恢复」入口待定，不放占位链接。
- **退出入口（D6）：** 行程详情、我的旅行、聊天页三个入口统一；预计影响由服务端计算。
- **时间基准（D7）：** `meeting_time` 优先；否则 `start_date` 00:00（Asia/Shanghai）。
- **月度计数（D8 / D14）：** 按退出动作所在自然月；仅已生效出发前退出扣分计入；待核实不计入；核实不属实时按核实当时已有次数取下一序号；旅行中、≥7 天免责不计入；0 分裁断为实际 0 的事件仍计入。
- **只读范围（D9）：** 查看与举报/安全保留；发布新行程、申请、发布/编辑体验、编辑行程、发消息、编辑资料/头像被拒绝。
- **触发联动（D11）：** 撤回全部待处理申请、解除全部未结束已接受关系、取消全部未结束已发布行程；系统清退不扣分、不计入次数；已完成/已取消保留历史。
- **系统取消原因（D13）：** 新增「信用分低于 60，账号受限」，发布者与已接受同行者可见。
- **能力归属（D15）：** `credit-enforcement`（ADDED）；`user-credit` / `trip-companions` / `trip-cancellation` 只作依赖；不修改未归档 Delta。
- **契约与迁移（D17）：** 当前 0.14.0 + V20；暂定 0.15.0 + V21，P3 排他确认。
- **账本复用：** 退出扣分与待核实零值记录统一走 `CreditService.book`；幂等键至少包含用户 + 行程 + 退出事件；限制记录不写入账本，只引用触发账本。
- **事务：** 扣分、限制记录、自动清理同事务；跨域清理失败整体回滚；重复触发幂等。
- **不加分：** 本 change 不新增任何正向计分事件；自动解除只在未来加分/调整使分数 ≥60 时发生。
