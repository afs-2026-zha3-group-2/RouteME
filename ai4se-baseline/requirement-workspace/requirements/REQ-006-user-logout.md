## 1. Intent

一句话：让**已进入 RouteME 的用户**在顶栏身份菜单里随时**退出当前身份并回到身份门**——注册账号退出会结束服务端会话，演示身份退出只清除本地身份；退出后刷新不恢复上一身份；即使结束会话的请求失败，也必须完成本地退出。因为进入系统有「演示身份」与「注册账号」两条路径，如果只有注册账号能退出，演示路径就无法在共用设备上结束使用，「选择身份 → 使用 → 退出 → 换人」这个最基本的循环是断的。

## 2. Actors

| 角色 | 权限边界 |
|---|---|
| 注册账号用户 | 可退出自己的当前会话；退出后会话失效，需重新登录或改用演示身份。 |
| 演示身份用户 | 可退出当前演示身份并回到身份门；不涉及密码或服务端会话。 |
| 访客（停留在身份门） | 无可退出的身份，身份门不展示退出入口。 |

不新增角色或权限差异；退出只能作用于当前身份，不能影响其他身份的数据。

## 3. In / Out scope

**In scope**

- 顶栏身份菜单内新增「退出登录」入口，对注册账号与演示身份都可见、可点击。
- 注册账号退出：调用既有 `POST /api/auth/logout` 结束会话，清除本地 token 与当前身份记录，返回身份门。
- 演示身份退出：清除本地当前身份记录，返回身份门；不发起认证请求。
- 退出后停留在身份门（3 个演示身份 + 既有登录 / 注册入口），刷新不再恢复上一身份。
- 结束会话请求失败时仍完成本地退出，不阻塞用户。
- 身份门与未进入状态不展示退出入口。

**Out of scope**

- 新增后端端点、数据库迁移、token 形态或鉴权方式变更。
- 业务端点从 `X-User-Id` 迁移到 Bearer token（`add-user-auth` 已登记的后续变更）。
- 退出二次确认弹窗、会话自动过期倒计时、多设备会话列表与远程下线。
- 修改演示身份数量、切换行为、身份门视觉与登录 / 注册表单。
- 账号注销、数据导出或删除。

## 4. Scenarios + AC hints（SHALL 式，可观察）

1. **注册账号退出登录** — Given 用户以注册账号登录并停留在任意页面，When 用户在顶栏身份菜单点击「退出登录」，Then 系统 SHALL 结束该账号的当前会话、清除本地会话与当前身份，并返回身份门；已结束的 token 再用于读取当前用户 MUST 返回 401。
2. **演示身份退出当前身份** — Given 用户以某个演示身份进入系统，When 用户在顶栏身份菜单点击「退出登录」，Then 系统 SHALL 清除当前演示身份并返回身份门；该动作 MUST NOT 发起认证请求、MUST NOT 要求密码。
3. **退出入口对所有身份可见** — Given 用户已进入系统（注册账号或演示身份），When 用户展开顶栏身份菜单，Then 菜单 SHALL 展示「退出登录」入口，且该入口 MUST NOT 因身份类型被隐藏。
4. **退出后到达身份门** — Given 用户完成了退出，Then 页面 SHALL 展示身份门：恰好 3 个演示身份，以及既有登录 / 注册入口；MUST NOT 停留在空白页或上一身份的页面。
5. **刷新不恢复上一身份** — Given 用户刚退出当前身份，When 用户刷新页面，Then 系统 MUST NOT 恢复上一身份或上一会话，页面 SHALL 停留在身份门。
6. **结束会话失败仍完成本地退出** — *（异常）* Given 注册账号持有有效会话，When 用户退出且结束会话的请求失败（网络或服务端错误），Then 系统 MUST 仍清除本地会话与当前身份并返回身份门；MAY 给出「会话可能仍有效」类提示，但 MUST NOT 阻止退出。
7. **退出后可再次进入** — Given 用户已退出回到身份门，When 用户选择任一演示身份或用注册账号登录，Then 系统 SHALL 以所选身份进入首页，且不残留上一身份的浏览 / 操作归属。
8. **身份门不展示退出入口** — *（边界）* Given 用户尚未进入系统或刚退出停留在身份门，When 用户查看页面，Then 系统 MUST NOT 展示「退出登录」入口，因为没有可退出的当前身份。
9. **重复触发退出** — *（边界）* Given 用户已点击「退出登录」并回到身份门，When 用户再次触发退出（如返回或重复点击），Then 系统 MUST 保持身份门状态，不报错、不恢复上一身份。

## 5. Constraints（仅事实，不含技术方案）

- 退出入口落点为顶栏身份菜单（用户指定），不新增独立页面或路由；菜单项文案固定为「退出登录」。
- 复用 `add-user-auth` 既有契约：注册账号退出使用 `POST /api/auth/logout`；演示身份没有服务端会话，不得伪造或新签会话。
- 退出必须清除本地身份记录（`routeme.currentUserId`）与本地会话 token（`routeme.authToken`）；不得残留可被下一次进入复用的上一身份数据。
- 退出后回到身份门；身份门仍展示 3 个演示身份与既有登录 / 注册入口，演示身份数量与进入方式不变。
- 退出入口对所有身份可见；不得沿用「演示身份不显示退出」的旧表述。
- 不引入新依赖、不改设计系统；退出入口需可用键盘操作并有无障碍名称。
- 既有行程、申请、聊天、体验的业务规则与接口不受影响。

## 6. Context

RouteME 路觅当前支持 3 个演示身份与注册账号两种进入方式。`add-user-auth` 已实现注册、登录、会话恢复与注册账号退出，但顶栏菜单的退出项仅在登录态渲染，演示身份无法回到身份门；`add-user-auth` 的前端任务 T6 也把「演示身份不显示退出」写成了明确取舍。用户在评审顶栏身份菜单时提出了退出需求，并指定把按钮放在该菜单内。本需求把这个缺口收敛为一条页面级、可验收的身份生命周期增量，不重做认证体系。
