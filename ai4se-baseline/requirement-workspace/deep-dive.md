# Deep-dive（Phase 2.5）— REQ-002 / 003 / 004

四张固定表，业务粒度（grain / 业务字段 / 状态流转 / 展示面），不含技术 schema（无列类型、无 SQL、无代码符号）。未知项标 `{TBD}`，不臆造。source 指 `records/discussion/2026-11-13/RouteMe_MVP_完整闭环_中文.md`（下称「闭环文档」）。

## ① 数据契约（Data contract）

| concept | grain（粒度） | 业务字段 | state transitions（状态流转） | source |
|---|---|---|---|---|
| 演示用户 (User) | 一个预设账户 | 昵称、默认头像、简介、旅行兴趣（最多 3–5 个标签） | 无状态机（预设固定） | §5.1.1、§8 User |
| 旅行计划 (TripPlan) | 一条行程 | 标题、目的地、出发日期、结束日期、路线/行程描述、集合区域(选填)、预算范围(选填)、兴趣标签、计划人数、已加入人数、发布者、创建时间 | 招募中 → 已满员（接受申请达上限，REQ-003 触发）；招募中/已满员 → 已结束（日期/演示操作驱动）；→ 已取消（发布者取消，边界） | §5.1.3、§8 TripPlan |
| 同行申请 (TripApplication) | 一条申请（申请者 × 行程） | 行程、申请者、一句申请说明、创建时间 | 待处理 → 已接受（发布者接受）；待处理 → 已拒绝（发布者拒绝）；待处理 → 已取消（申请者处理前取消）；已接受 → （退出同行时关系解除，见 trip-companions 关系） | §5.1.6、§8 TripApplication |
| 同行关系 (Companion) | 一对已匹配同行者（源于已接受申请） | 行程、双方用户、建立时间 | 已匹配 → 已退出（任一方退出同行） | §2.4、§5.1.7、§5.1.9 |
| 聊天消息 (ChatMessage) | 一条消息 | 行程、发送者、接收者、文字内容、发送时间 | 无状态机（仅追加、可重读） | §5.1.7、§8 ChatMessage |
| 游后体验 (TripExperience) | 一条体验（作者 × 已结束行程） | 行程、作者、文字感想、路线强度（轻松/适中/较累）、一条建议、图片(增强项，可空)、创建时间 | 无状态机（发布后展示） | §5.2.1、§8 TripExperience |

## ② 边界归属（Boundary attribution）

| rule | branch | in \| out | rationale |
|---|---|---|---|
| 发布行程必填校验 | 必填齐全 → 保存 | in (REQ-002) | 发布主路径 |
| 发布行程必填校验 | 任一必填缺失 → 拒绝 + 提示 | in (REQ-002) | 输入完整性分支（DoR ⑩ 要求枚举） |
| 发布行程日期校验 | 结束日期 ≥ 出发日期 → 通过 | in (REQ-002) | 正常分支 |

| 首页筛选 | 有匹配结果 → 列表 | in (REQ-002) | 正常分支 |
| 首页筛选 | 无匹配结果 → 空状态提示 | in (REQ-002) | 边界分支 |

| 同行申请资格 | 重复申请（已有未取消申请）→ 拒绝 | in (REQ-003) | 幂等边界 |
| 同行申请资格 | 已满员/已结束 → 拒绝 + 提示 | in (REQ-003) | 状态边界 |
| 申请处理权限 | 发布者接受/拒绝 → 生效 | in (REQ-003) | 正常分支 |
| 申请处理权限 | 非发布者处理 → 拒绝 | in (REQ-003) | 越权分支 |

| 聊天进入资格 | 未匹配 → 拒绝进入 | in (REQ-003) | 越权分支 |
| 匹配打分 | 打分可用 → 展示匹配原因(+可选百分比) | in (REQ-003) | 正常分支 |

## ④ 通知 / 展示契约（Notification / display contract）

MVP **不做推送通知**（无 push/邮件/短信渠道）。以下为 UI 展示面契约。

| trigger / surface（展示面） | recipient role | content + display fields | channel | cardinality | source |
|---|---|---|---|---|---|
| 旅行灵感首页 — 行程卡片 | 浏览者 | 标题、目的地、日期、简单路线、兴趣标签、发布者昵称、已加入/计划人数、状态 | 应用内页面 | 列表（多卡片） | §5.1.2 |
| 首页「旅行体验」视图 | 浏览者 | 游后体验摘要（感想、强度、建议、封面） | 应用内页面 | 列表 | §5.1.2、§5.2.1 |
| 行程详情页 | 浏览者/申请者 | 完整路线、日期人数、发布者简介与兴趣、当前同行者、同行申请入口、游后分享区 | 应用内页面 | 单条 | §5.1.4 |
| 匹配原因提示 | 发现同行者用户 | 可解释原因文案（目的地/日期/共同兴趣），可选百分比 | 应用内页面 | 每候选行程一条 | §5.1.5 |
| 同行申请状态 | 申请者 | 待处理/已接受/已拒绝/已取消 | 应用内页面（我的旅行/申请页） | 每申请一条 | §5.1.6 |
| 申请处理列表 | 发布者 | 申请者资料 + 一句申请说明 + 接受/拒绝操作 | 应用内页面（同行申请页） | 列表 | §5.1.6 |
| 我的旅行分组 | 当前用户 | 我发布的/我申请的/已匹配的/已完成的/可分享体验的 | 应用内页面 | 分组列表 | §5.1.8 |
| 聊天消息列表 | 已匹配双方 | 文字内容、发送时间（手动刷新/短轮询更新） | 应用内页面 | 会话消息列表 | §5.1.7 |
| 安全提示 | 涉及联系/见面的用户 | 「首次见面选择公共场所」「重要行程告知亲友」；不公开电话/证件/精确住址 | 应用内页面（静态提示） | 每相关页面常驻 | §5.1.9 |
| 举报入口 | 已匹配/申请用户 | 举报提交入口（MVP 仅记录） | 应用内页面 | 单入口 | §5.1.9 |
| 游后分享表单 | 分享者 | 文字感想、路线强度（轻松/适中/较累）、一条建议、图片(增强项) | 应用内页面（游后分享页） | 单表单 | §5.2.1 |
| 参考此行程发布入口 | 浏览者 | 按钮 → 预填目的地/路线描述/兴趣标签的新建表单；日期/人数/集合地点需重填 | 应用内页面 | 单入口 | §5.2.2 |
| 校验/错误/加载/空状态提示 | 全体 | 必填缺失、日期非法、无资格、越权、加载中、空列表 | 应用内页面 | 按触发 | §12 DoD |

无展示面缺 display-fields；A0 门 ⑫ 通过。
