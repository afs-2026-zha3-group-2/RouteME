### 探针记录（REQ-019 信用分账户）

- **注册事务边界：** `AuthServiceImpl.register` 已是 `@Transactional`，用户名唯一性、密码校验与 `createAccount` 在同一事务内；信用账户初始化必须挂在该事务内，并在失败分支（`USERNAME_TAKEN` / `INVALID_INPUT`）之前不产生写入。

- **本人 / 他人差异：** 目前仅 `includeBirthday` 一处差异；信用字段在两种视角都返回，不新增分支。
- **零额外往返：** `ProfilePage.tsx` 只有一次 `loadUserProfile`；若改为独立端点会多一次请求并引入两个加载态，D7 已否定。
- **历史数据面：** `V3`（id 1–3）、`V12`（id 4 周野）为种子用户，`V14` / `V15` 给其中部分账号写了登录凭据；回填迁移必须以「全表」为准（`INSERT ... SELECT id FROM app_users WHERE ...`），不能只覆盖有凭据的账号。
- **迁移号排他：** main 的 Flyway 头是 `V17`；`refine-trip-map`（REQ-016）与 `add-ai-itinerary`（REQ-017）分别声明 V17 / V18 且均未归档。本需求的迁移号必须在 P3 按合并顺序确认，不能假定 `V18` 或 `V19`。

### 探针记录（REQ-023 体验获赞信用）

- **点赞基线为零：** openapi / backend / frontend / Living Spec / 原型交互均无点赞；本 change 需从数据、接口到 UI 全链路新建。
- **记账服务可直接复用：** `CreditServiceImpl.book` 已在同事务内完成裁断、`applied_delta`、前后快照与幂等键唯一兜底；本 change 只需在调用前做「档位判定 + 月度剩余裁断」，不得绕过 `book` 直接改账户表。
- **幂等键即档位锁：** 由于零变化也写账本行（D11），「档位已结算」可以直接由幂等键存在性判定；无需新增档位状态表，也天然满足「回落再达不重复」。
- **月度边界：** `occurred_at` 由 `Clock.instant()` 写入（UTC ISO 串）；月度统计必须按 Asia/Shanghai 换算边界（初月 UTC `16:00` 前一 UTC 日），不能直接用 UTC 自然月。
- **每作者每行程一条体验：** `V8__create_trip_experiences.sql` 有 `(trip_id, author_id)` 唯一约束；「同行程多篇体验」规则以结算服务的 max 查询实现，单测用多行数据覆盖（必要时 mock mapper 返回多行）。
- **响应一致性：** 列表 / 详情 / 我的三处都经 `ExperienceServiceImpl` 的同一映射路径；赞数需批量查询（先收集 experienceId，再一次 `group by`），点赞态按当前用户批量查询，禁止逐条查库（沿用 REQ-018 照片批量化经验）。
- **自赞与未登录：** 控制器已有 `X-User-Id` 校验与 `DemoUserService.require`；自赞需在服务层比对 `experience.authorId`，不能只靠前端隐藏。
- **错误码闭集：** `openapi.yaml` `Error.code` 为闭集枚举；「体验不存在」需新增码或在 P2 定为复用码，不得自造。
- **无删除端点：** `ExperienceController` / `TripController` 无 DELETE；无需处理级联删除与积分回滚。
- **E2E 选择器风险：** 既有 `experiences.spec.ts` / `inspiration-home` 相关用例依赖 `.exp-foot` / `.exp-item` 结构；新增点赞按钮可能影响严格定位（如 `getByRole('button')` 计数），P4 需同步检查。
- **原型先行：** 原型 `ui.js` `expCard()` 与详情 `.exp-item` 用字符串模板；点赞态需在 `store.js` 增演示数据（或使用本地状态），并在 `prototype.html` / `styles.css` 增样式类，避免与实现类名漂移。
- **归档顺序：** `user-credit` 与 `trip-experiences` 的 Living Spec 均未包含在途 change 的 delta；本 change 归档必须排在其后（P5）。
- **`{TBD}`：** 无。非阻塞项（端点形态、错误码、契约 / 迁移号、月度聚合方式、并发保障）在 REQ-023 §8 记为 Dev 后续。
- A0 门 ⑨–⑫：全部通过。

### 探针记录（REQ-028 旅行保障）

- **注册事务边界：** `AuthServiceImpl.register` 已是 `@Transactional`，并已内嵌 `CreditService.ensureAccount`；钱包初始化必须挂同一事务，失败分支不留钱包。
- **状态派生：** 行程状态由 `TripPlan.status(now)` 派生（已取消 > 已结束 > 旅行中 > 已满员 > 招募中），服务端必须用同一实现判断可交易性，不能前端自行推断日期。
- **同行判定：** 发布者不在 `trip_applications`；资格 = `publisher_id == userId` 或存在 `trip_id + applicant_id + ACCEPTED`。
- **写守卫：** 购买 / 借款走 `AccountStatusService.assertCanWrite(userId, BUSINESS)`；还款不能走同一守卫，否则封禁用户无法结清，需单独口径。
- **并发：** 借款「每人 1 笔 ACTIVE」必须由数据库部分唯一索引兜底（服务层先查后写存在竞态）；SQLite / H2 均支持 `CREATE UNIQUE INDEX ... WHERE`，沿用 `V20` 写法。
- **余额并发：** 扣款必须用「条件更新 + 受影响行数」或事务内重读，避免双花；账本前 / 后余额在同一事务内计算。
- **金额精度：** 后端用 `long` / 整数分运算，禁止 `double`；借款本金校验 `principal_cents % 100 == 0`。
- **契约与迁移排他：** P1 时点基线 0.17.0 + `V23`；rebase 后 main 已到 0.24.0 + `V29`，本 change 按「后到者顺延」落定 **0.25.0 + `V30`**。
- **原型缺口：** P1 时点 `docs/prototype` 无钱包 / 保险 / 借款页面；rebase 后 main 已归档 v1 且禁止结构性改动，原型截点撤回，界面证据以生产 UI 与 E2E 为准。
- **E2E 影响：** 详情页新增入口区块，既有 `trips.spec.ts` 断言可能受版式影响；新增 `travel-finance.spec.ts` 覆盖购买、借款、还款与余额不足。
