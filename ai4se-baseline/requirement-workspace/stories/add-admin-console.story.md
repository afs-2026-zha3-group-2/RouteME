## S19 — 用户管理页（迭代 1 / 3 点 / 用户管理页）

作为平台管理员，我希望查看平台所有注册用户，以便查询用户信息并处理异常账号。

### 验收标准

- 展示平台所有注册用户列表，包括用户个人信息、ID、头像、昵称、邮箱、注册时间、账号状态。
- 账号状态包括 `ACTIVE`（正常）、`SUSPENDED`（暂停）、`BANNED`（封禁）。
- 支持通过用户 ID、昵称或邮箱搜索用户。
- 点击用户可进入用户详情，查看个人资料、旅行计划、旅行体验。
- 管理员在后台能够对接用户：用户点击人工客服后，管理员能与用户对话。
- 管理员可以查看所有举报信息，并对举报做出处理（封禁账号、暂停发布行程）；封禁需选择解封时间和封禁理由：
  1. 骚扰或不当言论
  2. 发布虚假行程信息
  3. 存在诈骗或金钱风险
  4. 发布色情、暴力或其他违规内容
  5. 冒充他人或身份信息可疑
  6. 恶意放鸽子 / 扰乱同行活动
  7. 泄露他人隐私信息
  8. 其他原因
- 设置封禁时间后，用户个人信息页面同步展示封禁内容。
- 仅管理员能够访问用户管理页。

### 场景

- **Given** 管理员已登录管理后台
- **When** 进入用户管理并搜索指定用户
- **Then** 展示符合条件的用户，可进入用户详情查看完整信息

### 垂直切片

一条故事 = 用户管理页 + `GET /api/admin/users` + 一次分页 / 搜索查询。

## S20 — 用户详情页（迭代 1 / 3 点 / 用户详情页）

作为平台管理员，我希望暂停、封禁或恢复用户账号，以便对违规用户采取管理措施。

### 验收标准

- 管理员可将 `ACTIVE` 用户暂停为 `SUSPENDED`。
- 管理员可将 `ACTIVE` 或 `SUSPENDED` 用户封禁为 `BANNED`。
- 管理员可将 `SUSPENDED` 用户恢复为 `ACTIVE`。
- 暂停或封禁前必须二次确认并填写处理原因。
- `SUSPENDED` 用户不能发布行程、申请同行、发送聊天消息或发布旅行体验。
- `BANNED` 用户不能继续正常使用平台。
- 处罚不会直接删除用户原有行程、旅行体验、聊天及举报记录。
- MVP 不提供管理员直接永久删除用户账号的能力。

### 场景

- **Given** 用户状态为 `ACTIVE`
- **When** 管理员选择「暂停账号」、填写原因并确认
- **Then** 用户状态变为 `SUSPENDED`，相关功能立即受到限制

### 垂直切片

一条故事 = 用户详情页 + `POST /api/admin/users/{userId}/status` + 一次状态迁移。

## S21 — 举报管理页（迭代 2 / 3 点 / 举报管理页）

作为平台管理员，我希望查看平台收到的举报，以便及时发现并处理违规用户或违规内容。

### 验收标准

- 用户提交举报后生成一条举报记录，默认状态为 `PENDING`（待处理）。
- 举报列表展示举报编号、举报人、被举报用户、举报对象、举报类型、举报时间和处理状态。
- 举报对象支持用户、旅行计划、旅行体验。
- 举报状态包括 `PENDING`（待处理）、`PROCESSING`（处理中）、`RESOLVED`（已处理）、`REJECTED`（举报不成立）。
- 支持按举报状态筛选。
- 点击举报可进入举报详情页查看举报原因及相关对象。

### 场景

- **Given** 用户已提交一条举报
- **When** 管理员进入举报管理
- **Then** 可以看到该举报，初始状态为 `PENDING`，并可进入举报详情

### 垂直切片

一条故事 = 举报管理页 + `GET /api/admin/reports` + 一次状态筛选查询。

## S22 — 举报详情页（迭代 2 / 5 点 / 举报详情页）

作为平台管理员，我希望人工审核并处理用户举报，以便对违规账号或内容采取措施并向举报人提供明确的处理结果。

### 验收标准

- 管理员打开举报开始处理后，举报状态由 `PENDING` 转为 `PROCESSING`。
- 管理员可查看举报原因、举报人、被举报用户及被举报内容。
- 管理员可从举报详情进入被举报用户或相关内容详情。
- 举报成立时，可根据实际情况对用户执行暂停或封禁处理。
- 举报不成立时，可将举报标记为 `REJECTED`。
- 处理举报时必须填写处理结果或备注。
- 举报成立并完成处理后状态变为 `RESOLVED`。
- `RESOLVED` 和 `REJECTED` 举报保留处理记录，不直接删除。
- 用户可以看到举报已受理和最终处理状态。

### 场景

- **Given** 存在一条 `PENDING` 举报
- **When** 管理员进入详情、开始处理并确认举报成立
- **Then** 状态依次变为 `PROCESSING`、`RESOLVED`，并保存管理员处理结果

### 垂直切片

一条故事 = 举报详情页 + `POST /api/admin/reports/{reportId}/start` / `resolve` + 一次状态迁移（`PENDING → PROCESSING → RESOLVED / REJECTED`）。

## S23 — 帮助与反馈 / 客服会话页（迭代 3 / 3 点 / 帮助与反馈 · 客服会话页）

作为需要帮助的平台用户，我希望能够联系人工客服，以便在遇到同行、举报、账号或平台使用问题时获得人工帮助。

### 验收标准

- 用户可以从「帮助与反馈」进入人工客服。
- 用户发起人工客服后创建客服会话，初始状态为 `WAITING`（等待接入）。
- 用户可以在会话中发送文字消息。
- 客服接入后状态变为 `HANDLING`（处理中）。
- 用户可以实时查看客服发送的回复。
- 会话结束后状态变为 `CLOSED`（已结束）。
- `CLOSED` 会话保留历史消息但不能继续发送。
- 已结束会话不影响用户后续再次发起新的客服请求。

### 场景

- **Given** 用户已登录并遇到需要人工处理的问题
- **When** 进入帮助与反馈并选择「联系人工客服」
- **Then** 创建 `WAITING` 客服会话，用户可以发送问题并等待客服接入

### 垂直切片

一条故事 = 帮助与反馈 / 客服会话页 + `POST /api/service/sessions` + 一次状态创建（无会话 → `WAITING`）。

## S24 — 客户服务页（迭代 3 / 5 点 / 客户服务页）

作为平台客服，我希望接入用户的人工客服会话并与用户对话，以便了解问题并提供人工处理。

### 验收标准

- 客服可以查看 `WAITING`（等待接入）、`HANDLING`（处理中）、`CLOSED`（已结束）的客服会话。
- 客服可以接入 `WAITING` 状态的会话，接入后状态变为 `HANDLING`。
- `HANDLING` 状态下客服与用户可以双向发送文字消息。
- 客服会话中展示当前用户的基础账号信息。
- 客服可以查看与当前用户相关的举报记录。
- 客服可以查看当前会话的完整历史消息。
- 客服完成处理后可以主动结束会话。
- 结束后状态由 `HANDLING` 转为 `CLOSED`。
- `CLOSED` 状态保留历史消息，双方不能继续发送消息。

### 场景

- **Given** 存在一条 `WAITING` 客服会话
- **When** 客服点击「接入」并发送回复
- **Then** 会话变为 `HANDLING`，用户收到客服消息并可以继续对话

### 垂直切片

一条故事 = 客户服务页 + `POST /api/admin/service/sessions/{sessionId}/join` / `close` + 一次状态迁移（`WAITING → HANDLING → CLOSED`）。
