## Story statement

作为**新用户**，我希望完善个人资料，以便展示自己的基本信息、个性特征和旅行偏好，让其他用户在查看我的行程时能够更好地了解我。

## Acceptance scenario

- **Given** 用户已完成账号注册但尚未完善个人资料
- **When** 填写头像、昵称、生日、性别、所在城市、学校、专业、职业、MBTI、旅行兴趣、旅行方式和个人简介并提交
- **Then** 系统保存个人资料，根据生日自动生成年龄和星座，并进入用户个人主页。

## Size / split note

- 3 点，页面级垂直切片，不再拆分。
- 一个页面（资料完善页 / 个人主页）+ 一份资料契约（`GET /api/users/{id}/profile`、`PUT /api/users/me/profile`、`POST /api/users/me/avatar`；注册请求体收窄）+ 一次状态迁移（资料未完善 → 资料已完善）。
- 不把「资料字段」与「个人主页」拆成两个 change：没有个人主页，资料无法满足「供其他用户查看」；没有完整资料，主页只能展示空白。
- 注册收窄与资料补齐属于同一状态迁移的两端，因此本 change 同时包含 `user-auth` MODIFIED 与 `user-profile` ADDED；按 REQ-005 先例，归档前需 SA 追认双 capability 例外。

## Out of scope

- 手机号 / 邮箱验证、实名认证、第三方登录、改密码 / 找回密码、账号注销。
- 头像裁剪编辑器、相册、背景图、动态、关注、私信、资料可见性开关。
- 旅行兴趣词表与行程标签匹配算法的统一。
- 演示身份资料编辑、演示账号数量与进入 / 切换行为。
- 行程、申请、聊天、体验的业务规则变更。

## Decisions (2026-11-16)

- **D1 头像**：真实上传图片，但改为选填；无头像回退昵称首字。
- **D2 学校 / 专业**：两个独立输入框；**学校选填**、专业选填；不新增年级字段；展示为「学校 · 专业」，缺失则省略。
- **D3 注册**：瘦身为用户名 / 密码 / 昵称；注册成功进入资料完善页。
- **D4 门禁**：完善页可跳过，可从「我的」补全；未完善资料降级展示。
- **D5 偏好**：旅行方式单选；兴趣 3–5 个。
- **D6 职业**：新增「职业」选填字段（学生 / 上班族 / 自由职业 / 其他，单选）；学校选填后，非学生可不填学校。
