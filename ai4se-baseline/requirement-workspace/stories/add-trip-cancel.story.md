## Story statement

作为**行程发起人**，我希望在旅行开始前取消自己发布的行程并选择取消原因，以便在计划无法继续时及时终止招募，让已申请或已加入的用户看到「行程已取消」，同时保留历史数据。

## Acceptance scenario

- **Given** 用户是自己发布的一条「招募中」或「已满员」行程的发布者
- **When** 用户在行程详情或我的旅行点击「取消行程」，选择取消原因并确认二次确认
- **Then** 行程状态变为「已取消」，首页与匹配列表不再出现
- **And** 待处理申请自动变为「已取消」，申请入口与处理关闭
- **And** 已接受同行者保留，聊天只读并提示「该行程已取消」
- **And** 我的旅行保留该行程并显示「已取消」，取消原因仅发布者与已接受同行者可见
- **And** 行程、同行关系、申请与聊天历史全部保留，且不可恢复。

## Size / split note

- 3 点，故事本身不再拆分。
- 一条故事承载一个状态机扩展（四态 → 五态）与一次取消操作（招募中/已满员 → 已取消），并联动列表、申请、聊天、我的旅行与统计。
- 不拆成「取消操作」与「取消善后」两条故事：没有善后，取消后的页面无法验收；没有取消操作，善后没有触发源。
- 新能力 `trip-cancellation` 单 capability；不改写 `trip-plans` / `trip-companions` 既有 Requirement 块，避免与 `add-trip-completion` / `refine-trip-application` / `refine-trip-chat` 三方同时改同一块。

## Out of scope

- 信用分、信用记录、扣分规则、免扣分申请、管理员审核（用户裁决 D1）。
- 删除行程、恢复 / 重新开启、改期改线。
- 推送、短信、邮件等外部通知。
- 取消原因的公开展示、申诉与审核流程。
- 已取消行程的体验发布、评价、退款或补偿。

## Decisions (2026-11-17)

- **D1 信用分：** 不做；信用分 / 信用记录 / 免扣分审核属其他 story。
- **D2 取消入口：** 详情页 + 我的旅行「我发布的」行内；原型需先行。
- **D3 原因可见性：** 仅发布者与 ACCEPTED 同行者；PENDING 与其他用户只见「已取消」。
- **D4 其他原因：** 说明必填，1–100 字，前后端同时校验。
- **D5 我的旅行归组：** 沿用四组，取消行程留在「我发布的」/「已匹配同行」并显示「已取消」。
- **D6 编号：** REQ-019 / `add-trip-cancel`（REQ-018 已被并行 `add-experience-photos` 占用）。
