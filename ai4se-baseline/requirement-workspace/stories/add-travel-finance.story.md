## Story statement

作为**已加入某条行程的旅行者**，我希望在行程保障页看到本次行程的目的地、日期与同行人数，并通过页面进入第三方保险机构完成投保，或在旅途中用演示钱包借一笔 100–2,000 元的小额周转金，以便在出现意外或临时缺钱时不至于中断旅行；RouteMe 只提供入口与「是否已投保」的状态，保险产品、保费、承保与理赔都由第三方提供方负责；借款由平台从本金扣除 5% 服务费，并按日计息、逾期按日计罚息。

## Acceptance scenario

- **Given** 用户是自己发布或已 `ACCEPTED` 参加的某条 `recruiting` / `full` / `ongoing` 行程成员，且账号为 `ACTIVE`
- **When** 用户在行程详情或账号菜单进入「旅行保障」，余额为 10,000 元
- **Then** 保障页展示目的地、出发 / 结束日期、同行人数、实际第三方提供方名称，以及保单 / 理赔 / 紧急求助入口
- **And** 点「前往第三方购买」在新窗口打开第三方投保地址（带 `trip_id`），余额与记录均不变
- **And** 第三方确认后状态变为「保障中」，保障期为行程出发日 ~ 结束日；重复确认仍是同一条记录
- **And** 保障结束后状态展示为「已结束」，记录与保障期仍可查看；RouteMe 不保存保单号、证件、银行卡或保费
- **And** 可以借 100–2,000 元整、期限 7 / 14 / 30 天；借 1,000 元实际到账 950 元，利息 7 元，应还 1,007 元，到期 = 放款 + 期限
- **And** 同一时间只能有一笔进行中借款；还款扣本金 + 利息后变为「已还清」，逾期展示「已逾期」并按本金 × 0.1%/日 × 已开始逾期天数累计罚息，还款时一并结清
- **And** 每次余额变化都有账本流水，余额 = 初始余额 + 入账 − 出账；重复提交不会重复扣款。

## Size / split note

- 5 点，故事本身不再拆分。
- 一条故事承载「钱包 → 第三方入口 → 状态回写 → 借款 → 还款」的单一闭环；保险入口与借款共享同一钱包、资格与页面，拆成两故事会复制余额与资格逻辑。
- 新能力 `travel-finance` 单 capability；不改写 `trip-plans` / `trip-companions` / `user-auth` 既有 Requirement 块。

## Out of scope

- 真实保险机构的投保 / 核保 / 出单 API、回调验签、对账文件；RouteMe 不成为保险中介或代理。
- 保险产品设计、保费与保额计算、免责条款正文、保单批改、退保、理赔审核与给付。
- 真实银行 / 支付网关 / KYC / 征信 / 真实放款。
- 借款展期、分期、提前结清优惠、复利、罚息封顶、催收、信用分影响。
- 钱包充值 / 提现 / 转账 / 多币种；管理后台金融视图；通知 / 推送 / 邮件。
