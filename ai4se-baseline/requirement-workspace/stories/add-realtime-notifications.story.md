# Story file — REQ-032 / add-realtime-notifications

- **Parent REQ：** REQ-032（`requirements/REQ-032-realtime-notifications.md`）
- **Change：** `add-realtime-notifications`（`notifications` ADDED）
- **拆解模式：** Workflow（记录 → 推送 → 计数 → 通知中心与跳转 → 八类业务接入）
- **范围说明：** 本文只覆盖本 change；通知历史分页、偏好设置、邮件 / OS 推送，以及业务规则改动均在范围外。

## S33-1 — 建立通知记录与八类模型

- **用户声音：** 作为用户，我希望所有需要我知道的事都以同一种格式留痕，而不是散落在各个页面；同一件事不要重复提醒我。
- **AC 摘要：**
  - 记录包含类型（八类）、事件（snake_case）、标题、正文、优先级、状态、创建 / 已读时间与关联对象。
  - `read_at` 为空即 `UNREAD`，非空即 `READ`。
  - 同一 `(recipient_id, dedupe_key)` 只留一行；重复触发不增加计数。
  - 业务状态变化不删除既有通知；标读不回写业务。
- **Size：** M
- **Spec：** `specs/notifications/spec.md`「通知记录、类型与生命周期」
- **场景：** REQ-032 §4 S33-1 ~ S33-4

## S33-2 — 行程生命周期通知

- **用户声音：** 作为发布者或同行者，我希望行程满员、开始、取消或结束时马上知道，取消时还要知道原因。
- **AC 摘要：**
  - 满员 → 除接受动作本人外的参与者收到 `TRIP/trip_full`。
  - 进入 `ONGOING` → 参与者收到 `TRIP/trip_ongoing` + `SYSTEM/safety_reminder`，重复读取不重复生成。
  - 取消 → 已接受同行者收到 `TRIP/trip_cancelled`（含原因）；待处理申请者收到 `APPLICATION/application_closed`。
  - 结束 → 已接受同行者收到 `TRIP/trip_completed`。
- **Size：** M
- **Spec：** `specs/notifications/spec.md`「行程生命周期事件」
- **场景：** REQ-032 §4 S33-5 ~ S33-8

## S33-3 — 申请与裁决通知

- **用户声音：** 作为发布者，有人申请时我希望立刻处理；作为申请者，通过或被拒我都希望知道。
- **AC 摘要：**
  - 申请成功 → 发布者 1 条 `application_received`，目标为申请处理页。
  - 接受 / 拒绝 → 申请者 1 条 `application_accepted` / `application_rejected`，目标为行程详情。
  - 被既有规则拒绝的请求不产生通知。
  - 通知失败不回滚裁决。
- **Size：** M
- **Spec：** `specs/notifications/spec.md`「申请与裁决事件」
- **场景：** REQ-032 §4 S33-9 ~ S33-12

## S33-4 — 聊天与信用通知

- **用户声音：** 收到同行消息、信用分发生变化时，我希望在通知中心看到原因和数字，而不是自己猜。
- **AC 摘要：**
  - 消息落库 → 接收方 1 条 `CHAT/message`；自消息不产生。
  - 信用变动 → 1 条 `CREDIT/credit_changed`，含变化量、原因、变动后分数；< 60 标为重要。
  - 完成安全学习恢复 → 1 条 `CREDIT/credit_recovered`，说明限制解除。
  - 聊天类只在会话未打开时提示；打开会话只清该会话。
- **Size：** M
- **Spec：** `specs/notifications/spec.md`「聊天、信用、举报与账号事件」「未读计数与标读规则」
- **场景：** REQ-032 §4 S33-13 ~ S33-15、S33-31

## S33-5 — 举报、账号、客服与系统通知

- **用户声音：** 举报有没有结果、账号为什么被限制、客服是否回复、身份是否认证通过，我希望收到明确、可核对的说明，而不是模糊或泄露隐私的提示。
- **AC 摘要：**
  - 举报提交 / 处理中 / 完成 → 举报人三类 `REPORT` 通知，正文含编号与结论。
  - 账号暂停 / 封禁 / 恢复 → 本人 `ACCOUNT` 通知，说明受限内容与恢复时间，不含管理员备注。
  - 客服接入 / 回复 / 结束 → `SERVICE` 通知。
  - 安全提醒与身份认证 → `SYSTEM` 通知。
- **Size：** M
- **Spec：** `specs/notifications/spec.md`「聊天、信用、举报与账号事件」「客服与系统事件」
- **场景：** REQ-032 §4 S33-16 ~ S33-20

## S33-6 — 通知中心、筛选与跳转

- **用户声音：** 我希望有一页能看到所有通知，按类型筛选，点一下就到对应页面；相关内容没了也告诉我，而不是跳到空白页。
- **AC 摘要：**
  - `#/notifications` 展示八类筛选（带数字）、类型标签、重要标记、未读 / 已读文字。
  - 每条通知按 `target.kind` 跳到行程、申请处理、会话、信用记录、举报详情、本人主页、客服或身份资料页。
  - 关联对象不存在时保留正文、提示「相关内容当前不可查看」、不跳转、仍标读。
  - 「全部已读」清除该用户全部 UNREAD。
- **Size：** L
- **Spec：** `specs/notifications/spec.md`「通知中心与跳转」
- **场景：** REQ-032 §4 S33-21 ~ S33-24、S33-28

## S33-7 — 未读计数与标读规则

- **用户声音：** 我想要一个诚实的数字：读过就减少，刷新不回弹，别人看不到我的计数。
- **AC 摘要：**
  - `total` 与八类 `by_type` 由持久化未读行派生，零值不省略。
  - 铃铛、侧栏与账号菜单入口显示 `total`；聊天入口与会话列表显示 `CHAT`。
  - 读一条、读全部、读一个会话各自只影响约定范围；重复标读幂等。
  - 越权标读返回 404；刷新或重连后计数不反弹。
- **Size：** M
- **Spec：** `specs/notifications/spec.md`「未读计数与标读规则」
- **场景：** REQ-032 §4 S33-25 ~ S33-32

## S33-8 — 实时投递与失败隔离

- **用户声音：** 我希望不用刷新就能看到新通知，而且推送坏了不要影响我用其它功能。
- **AC 摘要：**
  - SSE 只推给收件人，3 秒内到达；重连后用 REST 对账且不重复。
  - 通道失败时其它功能可用、计数保留、无阻塞弹窗。
  - 任何通知写入失败都只记录，不回滚业务流程。
- **Size：** M
- **Spec：** `specs/notifications/spec.md`「实时投递与失败隔离」
- **场景：** REQ-032 §4 S33-33 ~ S33-36
