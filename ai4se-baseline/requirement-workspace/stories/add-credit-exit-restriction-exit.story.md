## Story statement

作为已经加入行程的同行者，我希望在无法继续参加旅行时能够退出同行，同时根据退出时间承担相应的信用影响，以便在无法同行时仍能完成退出，并清楚知道这次退出会让我的信用分发生什么变化。

## Acceptance scenario

- **Given** 用户已 ACCEPTED 加入行程，信用分为 80，集合时间在 48 小时后，且当月首次出发前退出
- **When** 用户从详情页 / 我的旅行 / 聊天页点击「退出同行」，选择「个人原因」，看到预计 -5 并确认
- **Then** 退出成功，信用分由 80 变为 75，并生成一条退出信用记录
- **And** 页面明确告知本次实际扣分与退出后分数
- **And** 如果选择不可抗力 / 安全原因，则暂不扣分、记录待核实，且不计入当月次数

## Size / split note

- 5 点，故事本身不再拆分。
- 一条故事承载「退出原因 → 预计影响 → 六档扣分 → 月度累加 → 待核实」的完整垂直切片；拆开会出现「有预览没有扣分」或「有扣分没有告知」的不可验收半成品。
- 与 S23 同属 `credit-enforcement`，共享 `CreditService.book`、同一份退出事件与限制执行；按用户裁决放在同一 change，但故事与验收分开。

## Out of scope

- 管理员核实页面 / 接口、人工封禁、申诉；本 change 只保证「待核实」与暂不扣分。
- 加扣分明细、原因、时间、历史列表；用户端只看分数、等级与本人限制原因。
- 安全学习页面、客服系统、可点击的恢复入口。
- 通知 / 推送 / 邮件 / 站内信。
- 体验获赞加分、举报核实扣分的完整业务流程。
- 修改「退出同行」的聊天保留语义；沿用当前代码与未归档 `refine-trip-chat` 口径。
- 已完成 / 已取消行程的历史改写。

## Decisions（2026-11-17）

- **D1：** 一个 change 覆盖 Story 4 + Story 5；本故事为 S22。
- **D6：** 三个退出入口统一。
- **D7：** 出发基准集合时间优先，否则开始日期 00:00（Asia/Shanghai）。
- **D8：** 月度计数按退出动作所在自然月；仅已生效出发前扣分计入；待核实不计入；核实不属实时取下一序号；不追溯其他已结算退出。
- **D14：** 0 分下限裁断为实际 0 的扣分事件仍计入次数。
