## 原始诉求

> admin account which provide basic dashboard for statistics and count of different users etc

## 角色

作为平台管理员，我希望在管理后台首页看到平台的整体规模与积压情况，以便判断先处理哪一类工作。

## 验收标准

- 管理后台有一个概览页，作为进入后台后的默认落地页。
- 概览页展示六组统计：用户、行程、同行申请、旅行体验、举报、客服会话。
- 用户组展示总数、按角色（普通用户 / 管理员）与按账号状态（正常 / 暂停 / 封禁）的数量，以及最近 7 天与 30 天新增用户数。
- 行程组展示总数、按状态（招募中 / 已满员 / 旅行中 / 已结束 / 已取消）的数量，以及最近 7 天与 30 天新增行程数。
- 同行申请组展示总数与按状态（待处理 / 已通过 / 已拒绝 / 已取消 / 已退出）的数量。
- 旅行体验组展示总数与最近 7 天、30 天新增数。
- 举报组展示按状态（待处理 / 处理中 / 已处理 / 举报不成立）的数量。
- 客服会话组展示按状态（等待接入 / 处理中 / 已结束）的数量。
- 所有状态即使为 0 也要展示为 0，不留空。
- 用户、举报、客服三组卡片可以点击进入对应的管理页面；行程、同行申请、旅行体验暂无管理页面，不提供跳转。
- 概览页提供手动刷新；不自动刷新。
- 非管理员不能看到概览页内容，也不能读取统计接口。

## 场景

- **Given** 管理员已登录并进入管理后台
- **When** 打开后台首页
- **Then** 看到六组统计数字与最近更新时间
- **And** 点击「用户」卡片进入用户管理页

- **Given** 普通用户直接访问 `#/admin`
- **When** 页面渲染
- **Then** 展示无权限提示，且不请求统计接口

## 垂直切片

一条故事 = 概览页 `#/admin` + `GET /api/admin/dashboard` + 一次只读聚合查询（不分页、不筛选、不写入）。

## 口径说明

- **用户总数含管理员**，角色分桶之和等于总数；账号状态按有效状态计，封禁已到期视为正常。
- **行程状态不落库**，统计复用用户侧同一套四态推导（取消 > 已结束 > 旅行中 > 满员 > 招募中），已取消行程计入总数。
- **新增** 以 `created_at` 为准，窗口为产品时区（Asia/Shanghai）自然日，含当天共 7 / 30 天。
- **不新增数据表、迁移或缓存**；统计随每次请求即时计算。
