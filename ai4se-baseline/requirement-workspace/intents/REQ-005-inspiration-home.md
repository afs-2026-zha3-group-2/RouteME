# 意图捕获 — REQ-005 灵感首页：招募中行程与旅行体验双视图（S03）

- **候选能力：** `trip-plans`（MODIFIED）、`trip-experiences`（MODIFIED）
- **来源：** `docs/prototype/stories.html` S03（迭代 1、P0、3 点、落点：灵感首页）；原型实现 `docs/prototype/ui.js` 的 `discover()`；现行 Living Spec `openspec/specs/trip-plans/spec.md`、`openspec/specs/trip-experiences/spec.md`
- **捕获日期：** 2026-11-16

## 原始意图（一句话）

作为还没有明确目的地的学生，我希望在灵感首页默认看到别人公开的招募中行程，并能切到「旅行体验」视图看到已结束行程的真实分享，以便获得旅行灵感。

## 为什么（价值假设）

灵感首页是 RouteME「旅行灵感 → 发布行程 → 发现同行者 → 建立连接 → 一起旅行 → 分享体验 → 产生新灵感」闭环的入口。对尚无明确目的地的学生，首页必须先给出足够完整、可信的行程与真实体验，才能触发下一步「申请同行」或「参考发布」。S03 验证的假设是：**别人公开的行程与游后体验能直接成为下一位学生的旅行灵感**。

## 意图边界（初判）

- **覆盖：**
  - 默认进入「招募中的行程」视图；卡片展示标题、目的地、起止日期、路线摘要、标签、发布者昵称、已加入 / 计划人数、状态。
  - 可切换到「旅行体验」视图，查看来自已结束行程的分享。
  - 列表为空时展示空状态与「去发布行程」引导；加载中展示骨架或加载态。
  - 已满员、已结束在视觉上可与招募中区分，且不能只靠颜色表达。
  - 数据存在 6 条行程时，打开首页卡片信息完整；切换视图后内容随之变化。
- **不覆盖：**
  - 新增行程/体验数据模型、状态机或接口端点（复用 `GET /api/trips`、`GET /api/experiences`）。
  - 发布行程表单、详情页、申请、聊天、游后分享发布（分别属既有 `trip-plans` / `trip-companions` / `trip-experiences` 能力）。
  - 推荐算法、个性化排序、图片上传、地图导航（P2 / 不做）。
- **状态迁移：** 本故事只有页面视图状态迁移（`招募中的行程` ⇄ `旅行体验`），不新增行程业务状态；行程状态仍由 `trip-plans` 定义、由 `trip-companions` / 结束操作触发。

## 与现有 Living Spec / 能力的关系

- `trip-plans` 已定义「浏览未结束的旅行计划」：默认列表、卡片字段、加载/空状态、筛选、分页、状态文字。S03 需要把默认视图名称明确为「招募中的行程」，并补强「已满员 / 已结束不只靠颜色区分」的展示契约。
- `trip-experiences` 已定义「灵感首页的旅行体验视图」：视图切换、体验卡、筛选、分页、空态。S03 需要补强体验视图的空态「去发布行程」引导，以及来源行程「已结束」状态的显式表达。
- 两能力均已在 `openspec/specs/` 存在，本变更只做 MODIFIED 增量，不新建能力名。
