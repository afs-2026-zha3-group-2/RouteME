## 1. 原始诉求（issue #45 摘要）

> 作为正在寻找旅行搭子的人，我希望看到其他用户过去发布行程的实际完成情况和对应的信誉提示，以便识别经常完成旅行计划的用户，并对长期发布但完成度较低的用户保持警惕。

验收要点（原文 12 条）：

1. 为用户预留「路线完成度」指标，完成度数据未来来源于行程过程中的人工打卡。
2. 当前版本先完成字段、接口和 UI 展示入口，人工打卡和真实完成率计算逻辑后续独立实现。
3. 路线完成度按用户已结束行程的有效完成情况统计，不使用当前进行中或尚未开始的行程。
4. 历史完成度 ≥80% 显示「信誉良好」。
5. 历史完成度 <70% 显示「请留意行程完成情况」。
6. 70%–79% 保持中性，不展示「信誉良好」或「警惕」标签。
7. 没有足够路线完成数据的用户显示「暂无足够完成记录」，不得直接标记为信誉良好或需要警惕。
8. 与 LV1–LV5 成长等级完全独立。
9. 与现有信用分保持独立，不直接修改信用分。
10. 推荐列表可以展示简化标签，用户主页或详情页可以查看具体路线完成度。
11. 「警惕」标签只说明历史路线完成情况较低，不展示「骗子」「危险用户」「不可信」等定性结论。
12. 完成度数据和信誉标签由后端返回，前端不得自行根据页面数据计算标签。

> 数据来源预留：未来依赖行程途经点的人工打卡（例如计划 10 个有效打卡点、完成 8 个 → 该行程 80%）；人工打卡、位置校验和具体聚合算法后续单独开卡，本故事暂不实现。
>
> 技术边界：LV1–LV5 = 社区成长等级；信用分 = 独立信用体系；路线完成度 = 历史履约/完成行为指标。三者分别存储和计算，不互相替代。

## 2. 一句话意图

每位用户的公开资料里预留一行「路线完成度」：后端返回完成度数值与信誉状态码，个人主页据此展示「85% · 信誉良好」「75%」「55% · 请留意行程完成情况」或「暂无足够完成记录」；本期不实现人工打卡与真实聚合，所有用户均为「数据不足」，但阈值派生逻辑、接口字段与展示入口先落地，未来打卡上线后直接接线。

## 3. 角色

| 角色 | 边界 |
|---|---|
| 浏览者（找搭子的用户） | 打开他人个人主页，查看对方路线完成度与信誉提示。 |
| 资料本人 | 打开自己的个人主页，看到与浏览者同口径的完成度（沿用信用分的本人/他人同口径实践）。 |
| 系统 | 返回只读完成度数值与状态码；本期无数据源时统一返回「数据不足」；不写信用分、不写成长等级、不写资料统计。 |
| 管理员 | 本切片不涉及管理端配置、人工修正或申诉。 |

## 4. 用户裁决（D1–D8）

| id | 问题 | 结论 | 理由 |
|---|---|---|---|
| D1 | 当前版本没有人工打卡，数值从哪里来？ | **仅预留 + 数据不足**：所有用户一律返回「暂无足够完成记录」；不做临时计算、不造假数据；后端仍实现阈值 → 标签派生逻辑 | 最贴合 issue「当前版本先完成字段、接口和 UI 展示入口，打卡后续实现」；避免用已结束行程冒充有效完成 |
| D2 | 多少条已结束行程算「足够数据」？ | **≥1 条**已结束行程，且存在有效完成度数据（本期不存在） | 满足阈值时即展示；少于 1 条直接数据不足 |
| D3 | 「推荐列表」指哪个现有界面？ | **本期不做列表类落点**；只做个人主页 | main 的同行者推荐引擎已在 `c516d76` 移除，当前没有对应的推荐列表；不重建推荐引擎 |
| D4 | 编号与命名 | **REQ-031 / S32**；change `add-route-completion`；capability `route-completion`；分支 `feature/add-route-completion` | `aa320dc` 上 REQ-028 / S29 已被 `add-travel-finance` 占用；REQ-029 / S30 由并行 `add-growth-level`（issue #44）登记，按用户裁决顺延为 REQ-031 / S32 |
| D5 | 「具体路线完成度」的展示形态？ | **标签 + 百分比**；数据不足时只显示「暂无足够完成记录」 | 让浏览者既能看到数值又能看到信誉结论；中性档只显示百分比 |
| D6 | 未来聚合的统计范围？ | **发布者 + 已接受同行者**参与的已结束行程都计入 | 作为同行者履约同样代表「经常完成旅行计划」 |
| D7 | 「预留字段」落在哪一层？ | **仅接口字段**：`GET /users/{userId}/profile` 响应增加只读完成度字段；不落库、不新增迁移 | 本期无写入方，先建表属于死重；未来打卡聚合上线后再决定存储 |
| D8 | 本人 / 他人的展示口径与状态码 | 本人与他人**同口径**返回与展示；状态用英文码 + 前端 i18n 映射 | 沿用 `credit_level` 既有实践；避免前端做阈值判断 |

## 9. 残余风险

| 风险 | 处理 |
|---|---|
| 「预留」被实现成假数据或临时计算 | D1 写死：本期只返回数据不足；Delta 增加「不得返回伪造数值」约束 |
