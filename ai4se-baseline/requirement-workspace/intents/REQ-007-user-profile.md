# 意图捕获 — REQ-007 完善个人资料并生成个人主页

- **候选能力：** `user-profile`（ADDED）、`user-auth`（MODIFIED — 注册表单瘦身与注册后落点）
- **来源：** 用户故事「作为新用户，我希望完善个人资料，以便展示自己的基本信息、个性特征和旅行偏好，让其他用户在查看我的行程时能够更好地了解我」+ 16 条验收标准；落点页面「个人资料完善页」；2026-11-16 用户对 6 项产品裁决的答复
- **捕获日期：** 2026-11-16

## 原始意图（一句话）

作为刚注册的新用户，我希望能一次性填完头像、昵称、生日、性别、城市、学校与专业、职业、MBTI、旅行兴趣、旅行方式和个人简介并保存，以便系统生成我的个人主页，其他人在查看我发布的行程时能了解我是谁、喜欢怎么旅行。

## 为什么（价值假设）

当前 `add-user-auth` 只做了「能注册、能登录、能退出」：注册表单顺手收了昵称、学校和兴趣，用户没有真实头像、生日、性别、城市、专业、MBTI、旅行方式与简介；个人资料只散落在顶栏身份菜单和行程卡上。`trip-plans` 与 `trip-experiences` 展示发布者时只有昵称、学校首字和一句简介，浏览者无法判断「这个人是否和我合得来」。验证的假设是：**一份结构化、可浏览的个人资料（含年龄 / 星座派生信息与旅行方式）能让发布者从「一个昵称」变成「一个可判断的同行候选」**。

## 意图边界（初判）

- **覆盖：**
  - 注册成功后进入个人资料完善页；注册表单只收用户名、密码、昵称（用户裁决 D3）。
  - 完善页字段：头像（选填，真实上传）、昵称、生日、性别、所在城市、学校（选填）、专业（选填）、职业（选填）、MBTI（选填）、旅行兴趣（3–5 个）、旅行方式（单选）、个人简介（选填）。
  - 生日自动派生年龄与星座并展示；生日本身不对外公开。
  - 必填项：昵称、生日、性别、所在城市、旅行兴趣（≥3）、旅行方式；学校、专业与职业均为选填。未完成时不能提交，并逐项提示缺失字段。
  - 提交成功后保存资料，进入本人个人主页；其他人从行程卡 / 详情页的发布者入口查看同一主页。
  - 「资料未完善 → 资料已完善」是一次可观察的状态迁移；未完善资料可稍后从「我的」补全（用户裁决 D4），他人查看时降级展示已有字段。
- **不覆盖：**
  - 手机号 / 邮箱验证、实名认证、第三方登录、改密码 / 找回密码、账号注销。
  - 头像裁剪编辑器、多图相册、背景图、动态 / 关注 / 私信（非行程上下文）。
  - 资料可见性开关、按字段屏蔽、访客与登录用户的可见性差异。
  - 旅行兴趣词表与行程标签的匹配算法统一（P3 设计项；本需求只要求 ≥3 且可保存）。
  - 演示身份的资料编辑（演示账户只读；不新增演示账号）。
- **状态迁移：** `资料未完善 → 资料已完善`。资料是否完善由必填字段派生，不新增独立状态机；未完善资料不阻断浏览与发布等既有行为。

## 与现有 Living Spec / 能力的关系

- `user-auth` 已归档并进入 Living Spec：注册目前校验昵称与兴趣标签数量，注册成功直接进入首页。本需求把注册收窄为用户名 / 密码 / 昵称，并让注册成功进入资料完善页，因此以 **MODIFIED** 表达「注册账号」增量，保留既有用户名 / 密码 / 唯一性校验场景。
- `trip-plans` 的「演示身份进入与切换」与 `trip-experiences` 的发布者展示只消费用户昵称 / 学校 / 简介；本需求新增个人主页与发布者入口，展示契约需要扩展，但不改行程与体验的业务规则。是否同步修改这两个 Living Spec，交由 P3 设计确认（倾向只改 P2/P3 的展示层契约，不重写行程需求）。
- 个人资料是新的业务概念（头像、生日、性别、城市、专业、MBTI、旅行方式、简介与派生年龄 / 星座），因此新开 `user-profile` capability，而不是把字段塞进 `user-auth`。
- 演示账户（1–3）的 `school` 仍保存历史合并文案「年级 · 专业」；新注册账号改为「学校 + 专业」两列，显示时拼接为「学校 · 专业」。本需求不迁移演示数据。

## 用户裁决（2026-11-16）

| id | 议题 | 裁决 | 影响 |
|---|---|---|---|
| D1 | 头像是否必须真实上传 | **真实上传图片，但头像改为选填** | 覆盖原始 AC「头像为必填」；无头像时回退昵称首字，展示不空 |
| D2 | 学校 / 专业如何录入 | **学校、专业两个独立输入框**；不新增年级字段；**学校改为选填**（2026-11-16 追加裁决） | 避免输入间隔号 `·`；演示账号保留旧文案；学校不再是必填 |
| D3 | 注册表单是否瘦身 | **瘦身**：注册只收用户名 / 密码 / 昵称，学校、兴趣、简介移到完善页 | `user-auth` 的「注册账号」为 MODIFIED |
| D4 | 完善页能否跳过 | **可跳过**；可稍后从「我的」补全，未完善时他人看到降级资料 | 「资料未完善」可长期存在；提交前仍不能提交不完整表单 |
| D5 | 旅行方式单选还是多选；兴趣上限 | **旅行方式单选**；兴趣 **3–5 个**，沿用现有选择器与自定义标签 | 不突破既有 5 个上限与匹配计算假设 |
| D6 | 是否支持非学生身份 | **新增「职业」选填字段**：学生 / 上班族 / 自由职业 / 其他（单选）；学校选填后，非学生可不填学校 | 资料不再假设所有用户都在校；职业与学校可同时填写 |
