- **捕获日期：** 2026-11-16
- **分支：** 主工作区 `main`（P1 只写工件，无代码改动）
- **编号说明：** 本文档起草时按当时序号写作 REQ-011；同日 `main` 已将 S15 结束行程登记为 REQ-011（`add-trip-completion`），按「后到者顺延」改为 **REQ-012**。意图 / Ready 条目、`deep-dive.md` / `impact-brief.md` 增补、change 工件与本轮记录已同步改号。

## 原始意图（一句话）

作为与陌生人同行的学生，我希望在行程详情页和聊天页看到可读的安全边界——公共场所见面、把行程告知亲友、不公开电话证件住址——并能就地举报行程或对方，提交后拿到明确回执，以便更安心地判断要不要同去。

## 为什么（价值假设）

`add-trip-companions` 已归档：`SafetyNote` 已在详情页与聊天页渲染，`ReportModal` 已能提交到 `POST /api/reports` 并显示回执，后端只记录不处置，电话 / 证件 / 精确住址从未采集。也就是说 S14 的**能力底座已经存在**，但展示与故事 AC 有三处错位：

1. 安全提示是一整段 `safetyBody` 文字，「公共场所集合」只是隐含在「确认路线与集合点」里，**「把行程告知亲友」整条缺失**，也不含原型里的「本行程集合区域」与「拒绝转账 / 索取证件」；
2. 回执文案是「举报已收到，我们会记录处理。」，而故事 AC 要求「已收到，我们会处理」；
3. 举报弹窗缺少「不会向对方透露你的身份」与「平台举报不能替代紧急求助」两句边界说明；本人发布的行程上也能看到举报按钮（自己举报自己）。

本需求验证的假设是：**把安全提示拆成三条可读事实、把举报流程的边界与回执说清楚之后，学生能在不离开页面的前提下完成「看清边界 → 判断风险 → 举报 → 拿到回执」**；同时不引入工单系统、不改后端规则。

## 意图边界（初判）

- **覆盖：**
  - 详情页安全提示改为三条可读事实：公共场所集合（含本行程集合区域，缺失时「待确认，出发前在聊天中确认」）、把目的地 / 日期 / 同行人昵称告知亲友、平台不公开电话 / 证件 / 精确住址并拒绝转账或索取证件。
  - 聊天页安全提示改为一行同义文本，含本行程集合区域（缺失时「待确认」）与「不要转账或提供证件信息」。
  - 两条提示都是**文本**表达，不允许只靠颜色或图标承载；列表对读屏可读。
  - 举报入口：详情页「举报这条行程」（仅他人行程）、聊天页「举报这位用户」。
  - 举报弹窗：举报对象（行程标题 / 对方昵称）、原因（沿用四类）、补充说明（选填 ≤200 字）、「我们不会向对方透露你的身份」、「如果你正处于危险中，请先联系当地警方或学校保卫处。平台举报不能替代紧急求助。」
  - 提交成功进入回执态，回执文案「已收到，我们会处理」；后端只记录，不做处置闭环。
  - 提交失败给出可读提示，保留已填内容可重试。
  - 为 `trip-companions` 写 MODIFIED delta，替换「我的旅行聚合与最低安全能力」，保留既有「我的旅行」两个场景。
- **不覆盖：**
  - 举报后台工单、处置状态、处理时限、通知 / 回执查询、封禁与申诉。
  - 举报原因词表扩容、按目标类型分表、原因必填校验之外的新规则、`openapi.yaml` 版本变更。
  - 新增求助热线、紧急联系人、位置共享、行程分享链接、实名认证、信用体系。
  - 资料弹窗的举报按钮（REQ-009 已明确不做）、体验发布页的安全提示改版（保留现状）。
  - 采集或展示电话、证件、精确住址等隐私字段。
  - 后端端点、数据库迁移、状态机变更。

## 与现有 Living Spec / 能力的关系

- `trip-companions` 的 Living Spec「我的旅行聚合与最低安全能力」已经写明：详情页与聊天页展示安全提示、提供以行程或用户为对象的举报入口、提交后返回明确回执、不公开电话 / 证件 / 精确住址。本需求**不新增业务规则**，只把提示与回执的**展示口径**补成可验收增量，因此以 **MODIFIED** 表达，并保留「我的旅行」既有场景。
- `trip-plans` 拥有 `meeting_area` 字段与行程状态；本需求只读消费集合区域，不改字段与状态。
- `openapi.yaml` 0.8.1 已定义 `POST /api/reports`、`target_type` / `reason` 枚举与 `note ≤200`；本需求**预期不改契约**。
- 原型 `docs/prototype/ui.js` 的 `safetyPanel()` / `chat-safety` / `reportModal()` 是视觉与文案基准；不复制其 mock 数据与演示控制。
