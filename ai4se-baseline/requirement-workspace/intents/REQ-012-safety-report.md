## 原始意图（一句话）

作为与陌生人同行的学生，我希望在他人行程的详情页和聊天页页头都能一眼找到一个明确可点的举报入口——详情页举报「这条行程」、聊天页举报「这位用户」——提交后拿到「已收到，我们会处理」的明确回执，遇到不适时不用在长页面里找按钮。

## 为什么（价值假设）

`add-trip-companions` 已归档：`ReportModal` 已能提交到 `POST /api/reports` 并显示回执，后端只记录不处置，电话 / 证件 / 精确住址从未采集。也就是说 S14 的**举报能力底座已经存在**，但展示与故事 AC 有四处错位：

1. 举报入口埋在整段安全提示的**底部**（详情页在安全区末尾、聊天页在输入框下方），可发现性差；
2. 回执文案是「举报已收到，我们会记录处理。」，而故事 AC 要求「已收到，我们会处理」；
3. 举报弹窗缺少「不会向对方透露你的身份」与「平台举报不能替代紧急求助」两句边界说明；
4. 本人发布的行程上也能看到举报按钮（自己举报自己）。

裁决 D5 进一步决定：详情页三条安全提示与聊天页一行提示**整块下线**，页面只保留举报入口。入口因此不能再依附提示区，必须独立占据页头。

本需求验证的假设是：**把举报入口固定在页头、把弹窗边界与回执说清楚之后，学生遇到不适时能在一两步内完成「找到入口 → 举报 → 拿到回执」**；同时不引入工单系统、不改后端规则、不在本页承载安全文案。

## 意图边界（rev2）

- **覆盖：**
  - 他人行程详情页页头（与状态标签同一行）渲染文本按钮「举报这条行程」；窄屏换行到标题下方，不得隐藏。
  - 聊天页页头（头像对侧）渲染文本按钮「举报这位用户」，常驻（含已结束只读聊天）。
  - 详情页与聊天页**不再渲染安全提示**：三条列表、聊天页一行文本与两套集合区域回退文案（「尚未填写，出发前请在聊天中确认」/「待确认」）一并下线。
  - 举报入口为**文本**表达，不允许只靠颜色或图标承载；键盘可达、读屏可读。
  - 举报弹窗：举报对象（行程标题 / 对方昵称）、原因（沿用四类）、补充说明（选填 ≤200 字）、「我们不会向对方透露你的身份」、「如果你正处于危险中，请先联系当地警方或学校保卫处。平台举报不能替代紧急求助。」
  - 提交成功进入回执态，回执文案「已收到，我们会处理」；后端只记录，不做处置闭环。
  - 提交失败给出可读提示，保留已填内容可重试。
  - 为 `trip-companions` 移除旧需求块「我的旅行聚合与最低安全能力」，新增「同行举报入口与回执」；保留「我的旅行」两个场景与举报 / 回执场景。
- **不覆盖：**
  - 举报后台工单、处置状态、处理时限、通知 / 回执查询、封禁与申诉。
  - 重新引入安全提示、边界文案或帮助中心内容（D5 明确移除；如需要另开需求）。
  - 举报原因词表扩容、按目标类型分表、原因必填校验之外的新规则、`openapi.yaml` 版本变更。
  - 新增求助热线、紧急联系人、位置共享、行程分享链接、实名认证、信用体系。
  - 资料弹窗的举报按钮（REQ-009 已明确不做）、体验发布页的「发布前提醒」改版（保留现状，且不出现举报入口）。
  - 采集或展示电话、证件、精确住址等隐私字段。
  - 后端端点、数据库迁移、状态机变更。

## 与现有 Living Spec / 能力的关系

- `trip-companions` 的 Living Spec「我的旅行聚合与最低安全能力」已写明：详情页与聊天页展示安全提示、提供以行程或用户为对象的举报入口、提交后返回明确回执、不公开电话 / 证件 / 精确住址。rev2 需要**删掉其中的提示场景**，而 `openspec` 的校验器禁止 MODIFIED 块丢弃既有场景名（`current spec contains scenario(s) not present in the modified block`），因此改为 **REMOVED** 旧需求块 + **ADDED**「同行举报入口与回执」，让删除在归档 diff 中显式可见。
- `trip-plans` 拥有 `meeting_area` 字段与行程状态；本需求只读消费「行程安排 · 集合」事实行，不新增提示落点，不改字段与状态。
- `openapi.yaml` 0.8.1 已定义 `POST /api/reports`、`target_type` / `reason` 枚举与 `note ≤200`；本需求**预期不改契约**。
- 原型 `docs/prototype/ui.js` 的 `reportModal()` 仍是弹窗文案基准；`safetyPanel()` / `chat-safety` 不再是本需求的落点，仅保留在 `openspec/changes/refine-safety-report/preview/safety-report.html` 的「对照」模式里供追溯。
