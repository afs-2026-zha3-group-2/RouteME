# 意图捕获 — REQ-027 发布行程改用地图路线编辑器

- **候选能力：** `trip-plans`（MODIFIED 1 Requirement）
- **来源：** 发起人 2026-11-18 验收反馈「旅行地图有点冗余，但它在地图上显示路线、添加目的地的能力很好，用它替掉发布行程里的简单路线」；优先级 P0 / 迭代 3 / 3 点；落点页面「发布行程 · 路线规划段」
- **捕获日期：** 2026-11-18 ｜ **记录人：** Jacky（当前开发者）
- **分支 / 基点：** 主工作区 `main`，基线 `origin/main@c058e12`（契约 0.22.0，迁移最新 `V26`）
- **编号说明：** `registry.md` 现最大为 REQ-026 / S27，本需求顺延登记为 **REQ-027 / S28**。

## 原始意图（一句话）

发布行程时，用户应该在地图上边看路线边加途经点，而不是填一个看不见路线、不能排序、也不会重算的地名多选框。

## 为什么（价值假设）

`trip-plans` 的第 2 段现名「简单路线」，实际只是 `AmapPlacePicker mode="multi" showMap` 的地名多选（`TripCreatePage` 第 2 段）。它不画路线、不给距离与时间、不能调整顺序、切换出行方式也不会重算（P0 §5 G-01…G-04）。

与此同时，`MapExplorerPage` 已经具备一整套成熟的路线面板：地图 + 搜索 + 地图点选、`已选途经点 n/8`、拖拽排序、`行程顺序` 与逐段说明、出行方式切换、直线降级、`生成旅行路线` 按钮。这套能力被放在一级导航「旅行地图」里，但它真正的使用场景是**发布行程**——用户在发布时才需要交代自己要怎么走。

价值假设：把「地图 + 路线」放到决策发生的位置（发布页），发布者提交前就能看到自己要走的路线，途经点写反可以就地拖回；浏览者拿到的 `stops` 顺序也已经是发布者确认过的顺序。

## 现状核对（2026-11-18，`origin/main@c058e12`）

| 事实 | 证据 | 结论 |
|---|---|---|
| 发布页路线段是地名多选 | `TripCreatePage` 第 2 段；`AmapPlacePicker mode="multi" showMap` | 需替换为地图路线编辑器 |

| 标签表写死「驾车」 | `MODE_LABELS.driving = '驾车'`，`ItineraryPanel` 直接复用 | 发布页需注入「自驾 / 骑行 / 公共交通」 |

## 意图边界

**覆盖：**

- 发布页第 2 段（`sectionRoute`）从「简单路线」改为「路线规划」，内容换成地图路线编辑器。
- 地图增点三入口：关键字搜索候选、地图点选、景点标记。
- 途经点面板：`已选途经点 n/8`、拖拽或上下按钮排序、单点删除、清空。
- 路线渲染：折线、起点 / 终点、编号 pin、总距离与总时长。
- 出行方式：三档就地切换；公共交通带目的地城市；首次生成后自动重算。
- 降级：路线服务不可用 → 直线虚线 + 面向用户的「示意 / 估算」提示。
- 提交：`stops: string[]`（按当前顺序、去空）+ `travel_mode`；占位名拦截。
- 导航：移除「旅行地图」入口；`#/map`、`#/map/{省码}`、`#/map/{省码}/{市码}` 保留。
- 测试：重写 `trips.spec.ts` 的失效断言，新增面板与占位名覆盖。

**不覆盖：**

- 路线持久化 / 收藏 / 分享 / 路线重合度打分。
- 详情页 `AmapTripMap` 的「按名称重算路线」口径。
- 同行者匹配面板进发布页。
- AI 规划页与 AI 快照结构。
- 探索页公共交通未传城市、`RouteLayer` 重投影等既有缺陷的修复（仅记录）。
- 新增后端接口、契约字段、数据库迁移。
