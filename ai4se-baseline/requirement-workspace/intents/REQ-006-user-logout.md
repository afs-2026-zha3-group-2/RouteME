# 意图捕获 — REQ-006 退出当前身份（含演示身份）

- **候选能力：** `user-auth`（ADDED）
- **来源：** 用户指令「用户应该可以退出登录；按钮可放在顶栏身份菜单（截图：`林见夏 / 切换身份` 下拉面板）」；截图展示的组件为 `RouteME/frontend/src/shell/AppShell.tsx` 的 `id-switch` 面板；既有认证变更 `openspec/changes/archive/2026-11-16-add-user-auth/`（Living Spec `openspec/specs/user-auth/`）
- **捕获日期：** 2026-11-16

## 原始意图（一句话）

作为已经进入 RouteME 的用户，我希望在顶栏身份菜单里随时退出当前身份并回到身份门，以便在共用设备上结束使用、换人使用或重新选择身份。

## 为什么（价值假设）

「进入系统」目前有两条路径：选择演示身份、用注册账号登录。注册账号已经有退出登录，但演示身份没有出口——一旦进入，只能切换到另一个演示身份，无法回到身份门。共用设备时这会留下一个始终活跃的身份，也让「结束使用」在演示路径上不成立。验证的假设是：**无论用哪种身份进入，用户都能以同样的方式结束当前会话并回到身份选择**。

## 意图边界（初判）

- **覆盖：**
  - 顶栏身份菜单提供「退出登录」入口，且对注册账号与演示身份都可见。
  - 注册账号退出：结束服务端会话、清除本地会话，回到身份门。
  - 演示身份退出：清除本地当前身份，回到身份门；不调用认证接口、不需要密码。
  - 退出后刷新页面不再恢复上一身份。
  - 退出动作失败（网络 / 服务端错误）时仍完成本地退出。
  - 身份门本身不显示退出入口（没有可退出的身份）。
- **不覆盖：**
  - 新增认证端点、改密码 / 找回密码、账号注销、token 存储形态变更（沿用 `add-user-auth` 契约）。
  - 业务端点从 `X-User-Id` 切换到 token 鉴权（`add-user-auth` 已记录的后续 change）。
  - 退出前的二次确认弹窗、自动会话过期倒计时、多设备会话管理（可作为后续增强）。
  - 演示身份的数量、切换行为与身份门视觉。
- **状态迁移：** 当前身份只有「已进入 → 已退出」一次迁移；注册账号同时伴随服务端会话「有效 → 已结束」。不新增行程 / 申请 / 聊天业务状态。

## 与现有 Living Spec / 能力的关系

- `add-user-auth`（进行中）已定义 `user-auth` 的会话校验与注册账号退出：`POST /api/auth/logout` 删除会话，同一 token 再访问 `/auth/me` 返回 401；其前端任务 T6 明确「演示身份不显示退出」。
- 本需求把退出扩展到演示身份，并把入口统一到顶栏身份菜单；因此**以本需求为准覆盖 T6 的「演示身份不显示退出」表述**，其余会话与密码契约不变。
- `trip-plans` 已定义「演示身份进入与切换」；本需求只新增退出路径，不改进入、切换或身份门展示。
- `user-auth` 尚未进入 `openspec/specs/`（`add-user-auth` 未归档），因此本 change 的 delta 以 ADDED 需求表达，避免 MODIFIED 一个尚未存在的 living requirement。
