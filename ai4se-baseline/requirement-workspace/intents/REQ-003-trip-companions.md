# 意图捕获 — REQ-003 同行匹配、申请与旅行前沟通

- **候选能力：** `trip-companions`（发现同行者 → 建立连接 → 一起旅行的基础沟通与安全）
- **来源：** `records/discussion/2026-11-13/RouteMe_MVP_完整闭环_中文.md`（§2.3–2.5、§5.1.5–5.1.9、§6、§7 US-03/US-04/US-05、§10 迭代 2–3）
- **捕获日期：** 2026-11-15

## 原始意图（一句话）

大学生希望在 REQ-002 已有的行程池上，按目的地/日期/兴趣找到相近的同行计划并看到可解释的匹配原因，提交一句说明的同行申请，由发布者接受或拒绝，双方建立连接后进行基础文字沟通，并具备取消/退出/举报等最低安全能力。

## 为什么（价值假设）

产品核心假设之二：**用户愿意基于具体路线申请同行**。REQ-003 把「灵感/发布」转化为真实的同行连接，是闭环中「发现同行者 → 建立连接 → 一起旅行」三环，也是产品区别于普通陌生人私聊工具的关键（先有共同行程、再沟通）。

## 意图边界（初判）

- 覆盖：基础路线匹配（打分 + 匹配原因，可降级为筛选 + 共同兴趣提示）、同行申请（提交/待处理/接受/拒绝/取消）、人数上限联动与状态流转、我的旅行聚合视图、匹配后一对一文字聊天、最低安全能力（取消申请/退出同行/举报入口/隐私不公开/见面与告知亲友提示）。
- 不覆盖：行程发布与详情（REQ-002）、游后分享与参考发布（REQ-004）、AI 推荐/附近的人/实时位置/导航/紧急救援/WebSocket 实时/语音视频图片聊天/已读回执/推送（P2 或明确不做）。
- 对应迭代：第 4–5 天「发现与连接」+ 第 6–7 天「沟通」，验收场景为「用户 B 找到用户 A 的计划，申请同行，用户 A 接受，双方建立连接并进行沟通」。

## 与现有 Living Spec / 能力的关系

- 依赖 REQ-002 `trip-plans` 的行程、状态与筛选作为输入；REQ-003 **新增** `trip-companions` 能力（ADDED），并**触发** `trip-plans` 行程状态的人数联动流转（招募中 → 已满员），此为跨能力的 MODIFIED 触点，锚点见 deep-dive ③。
