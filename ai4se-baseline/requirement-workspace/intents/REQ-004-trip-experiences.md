# 意图捕获 — REQ-004 游后体验分享与参考此行程发布

- **候选能力：** `trip-experiences`（游后分享 → 产生新灵感的闭环收口）
- **来源：** `records/discussion/2026-11-13/RouteMe_MVP_完整闭环_中文.md`（§2.6–2.7、§5.2.1–5.2.2、§6、§7 US-06、§10 迭代 3、§11 演示脚本）
- **捕获日期：** 2026-11-15

## 原始意图（一句话）

完成旅行的大学生希望对已结束且自己参加过的行程发布简短的真实体验（文字感想、路线强度评价、一条给后来者的建议），并让其他用户能「参考此行程发布」快速创建自己的计划，从而把体验转化为下一位用户的新旅行灵感，收口整个价值闭环。

## 为什么（价值假设）

产品核心假设之三：**游后分享能够成为下一位用户的旅行灵感**。REQ-004 让闭环从「分享体验」回到「产生新灵感 → 发布新行程」，是 RouteME 区别于「发布行程 → 找搭子 → 聊天」的完整闭环收口。

## 意图边界（初判）

- 覆盖：游后分享（仅对已结束且参加过的行程、文字感想、强度评价轻松/适中/较累、一条建议、图片为增强项）；分享展示在原计划详情页与灵感首页；「参考此行程发布」预填目的地/路线描述/兴趣标签，日期/人数/集合地点必须重填。
- 不覆盖：行程浏览/发布/详情（REQ-002）、匹配/申请/沟通/安全（REQ-003）、短视频/直播/复杂内容社区（P2）、个性化推荐算法（P2）。
- 对应迭代：第 6–7 天「P0 稳定后完成」项，演示脚本第 1、9、10 步（看到分享 → 参考发布 → 体验回到首页成为新灵感）。

## 与现有 Living Spec / 能力的关系

- 依赖 REQ-002 `trip-plans`（行程详情、灵感首页展示位、发布表单预填）与 REQ-003 `trip-companions`（「已结束/已完成」状态与「参加过」判定、我的旅行「可分享体验」入口）。
- REQ-004 **新增** `trip-experiences` 能力（ADDED），并对 `trip-plans` 详情页/首页**新增展示位**（MODIFIED 触点：详情页游后分享区、首页旅行体验切换、发布页预填入口），锚点见 deep-dive ③。

## Discovery Decision

`Go` — 能一句话说清候选能力（新增 `trip-experiences`：分享 + 参考发布），与既有能力关系明确（消费 trip-plans 展示位与 trip-companions 的结束/参加判定），业务素材充分且含明确降级路径（图片上传可裁剪、参考发布后端可降级为前端预填），无需升级完整 Discovery。日期：2026-11-15。
