# 意图捕获 — REQ-002 旅行灵感浏览与行程发布

- **候选能力：** `trip-plans`（旅行计划的浏览、筛选、发布与详情查看）
- **来源：** `records/discussion/2026-11-13/RouteMe_MVP_完整闭环_中文.md`（§2.1–2.2、§5.1.1–5.1.4、§6、§7 US-01/US-02/US-03、§10 迭代 1）；`records/discussion/2026-11-13/RouteMe_路觅_产品意图_中文.md`
- **捕获日期：** 2026-11-15

## 原始意图（一句话）

大学生希望在 RouteME 上浏览其他学生公开的真实旅行计划、按目的地和日期筛选获得灵感，并能把自己的旅行想法发布成一条可被他人理解的行程，作为整个「灵感 → 发布 → 找同行」价值闭环的起点。

## 为什么（价值假设）

产品核心假设之一：**用户愿意发布可被他人理解的旅行计划**。没有可浏览的计划池和发布入口，后续的同行匹配（REQ-003）与游后分享（REQ-004）都无从发生。REQ-002 是 MVP 闭环的第一块地基。

## 意图边界（初判）

- 覆盖闭环阶段：旅行灵感（浏览 + 筛选）、发布行程、行程详情、演示用户进入系统。
- 不覆盖：同行匹配打分与申请（REQ-003）、聊天与安全能力（REQ-003）、游后分享与参考发布（REQ-004）。
- 对应迭代：第 2–3 天「灵感与发布」，验收场景为「用户浏览到珠海情侣路行程，并参考灵感发布自己的旅行计划」。

## 与现有 Living Spec / 能力的关系

- REQ-001（`hello-world`，已归档）只验证了脚手架链路，尚无业务页面；REQ-002 在其之上**新增** `trip-plans` 能力，属 ADDED，不与既有能力冲突。
- 首页从「展示一句问候语」演进为「旅行灵感首页」，是业务语义上的替换，但 `hello-world` 作为脚手架验收能力保留不动。
