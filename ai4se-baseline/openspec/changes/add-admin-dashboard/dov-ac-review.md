## 规格解释裁决

1. **「近 7 天」= 当天 + 前 6 个自然日**，不是滚动 168 小时；30 天同理。裁决理由：同一天内多次刷新结果稳定，且与行程状态的 Asia/Shanghai 日边界一致。
2. **用户总数含 `ADMIN`**；角色分桶与有效状态分桶都必须等于总数。避免「管理员是否算人」的二次解释。
3. **封禁到期是读取口径，不是写回。** 统计按 `ACTIVE` 计，库内仍可能是 `BANNED`；概览只读，不触发懒恢复写入。
4. **行程状态不落库。** 必须复用「取消 > 已结束 > 旅行中 > 满员 > 招募中」的既有推导，禁止在统计侧另写判定或新增 `status` 列。
5. **`total` 与分桶必须同源。** 若用两次查询，极端并发下可能总数 ≠ 分桶之和；P3 需明确同一时刻 / 同一结果集。
6. **不可跳转是产品边界，不是遗漏。** 行程 / 申请 / 体验没有后台列表页，卡片只展示数字。
7. **状态键大小写沿用既有 wire 值**（账号 / 举报 / 会话大写枚举名，行程 / 申请小写），P3 在契约 schema 中锁定键名。
