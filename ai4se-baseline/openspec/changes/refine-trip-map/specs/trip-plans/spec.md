# trip-plans 增量规格（refine-trip-map）

## MODIFIED Requirements

### Requirement: 发布表单的默认值与地图上下文

系统 SHALL 在打开发布表单时把出发日期与结束日期预填为当天（本地日期），用户可修改且既有校验不变；途经点地图 SHALL 采用三级离线 SVG 架构：未选目的地时渲染中国地图（省级区域、hover/selected、点击省进入省级地图并写入目的地省），选定省后渲染省级地图（城市节点、MUST NOT 出现城市间连线，点击城市写入 `destination_code` 并进入城市旅行地图），选定目的地后 MUST 只展示该市 CityTravelMap；城市地图 MUST 含六个独立 SVG Layer（RoadLayer / WaterLayer / ParkLayer / PoiLayer / RouteLayer / TravelerLayer），底图包含简化道路、河流水域、公园绿地与城市分区；已选途经点 MUST 以顺序编号水滴 pin 与蓝→紫渐变路线（白色 casing）表达；地图 MUST 提供图例、比例尺、竖排控制条（放大 / 缩小 / Reset View / 全屏，Esc 退出）与面包屑（中国 > 省 > 市，可点击回层），支持拖拽平移与滚轮缩放，Zoom MUST NOT 代替层级切换；任何点击 MUST 有可见反馈：点击 POI 弹地点卡（按上下文提供加入 / 移除路线动作），点击空白弹最近候选浮层（≤3 个候选，可一键加入）；表单控件 MUST 撑满字段宽度，字段 MUST 按「基本信息 / 路线 / 补充信息」分组且相邻字段间距一致。

旧行为与新行为的差异：R1 的全省概览（城市散点＋连线）被 R2 三级级联（中国→省→城市）取代；路线由纯蓝升级蓝→紫渐变；底图升级六 Layer；「未选目的地时展示全省概览」场景被「未选目的地时展示中国地图并级联选目的地」取代，「目的地暂无离线点位」改为统一 fallback 文案；其余既有场景保留。

#### Scenario: 日期默认今天
- **Given** 用户打开发布行程表单
- **When** 表单渲染完成
- **Then** 出发日期与结束日期都显示当天日期
- **And** 用户改动日期后按改动后的值校验

#### Scenario: 目的地可点选
- **Given** 用户打开发布行程表单
- **When** 用户点击目的地字段
- **Then** 省 / 市候选面板出现在可视区域内
- **And** 用户可依次选到「广东省 / 珠海」并在字段中看到已选值

#### Scenario: 未选目的地时展示中国地图并级联选目的地
- **Given** 用户尚未选择目的地
- **When** 用户查看途经点区域
- **Then** 渲染中国地图：省级区域可 hover / selected，不显示景点 / 路线 / 同行者
- **When** 用户点击「广东」
- **Then** 切换为广东省级地图（城市节点、无城市间连线），目的地省写入广东
- **When** 用户点击「广州」
- **Then** `destination_code` 写入广州代码并切换为广州城市旅行地图

#### Scenario: 面包屑回层与 Zoom 不换层
- **Given** 用户处于城市级地图
- **When** 用户点击面包屑的省或中国
- **Then** 切换回对应层级地图
- **When** 用户滚轮或按钮缩放
- **Then** 仅当前层视口变化，MUST NOT 触发层级切换

#### Scenario: 选定目的地后地图聚焦该市
- **Given** 用户已选择「广东省 / 珠海」
- **When** 用户查看途经点区域
- **Then** 地图出现并只显示该市范围
- **And** 候选点只包含该市的地点
- **And** 地图保持地理比例，不被横向拉伸

#### Scenario: 目的地无城市数据时统一 fallback
- **Given** 用户选择了城市数据未覆盖的城市（例如「拉萨」）
- **When** 用户查看途经点区域
- **Then** 显示统一 fallback「该城市详细旅行地图正在完善」，不白屏不报错
- **And** 提示 MUST NOT 表达为「先选目的地」

#### Scenario: 六 Layer 底图与渐变路线表达
- **Given** 用户已选择有城市数据的目的地并加入 ≥2 个途经点
- **When** 用户查看地图
- **Then** 六个独立 SVG Layer 渲染：简化道路、河流水域、公园绿地、城市分区、POI、路线
- **And** 已选途经点按顺序以编号水滴 pin 标记，pin 间以蓝→紫渐变路线连接且带白色 casing
- **And** 地图展示图例（路线 / 景点 / 公园绿地 / 河流 / 道路）与比例尺

#### Scenario: 地图点击总有可见反馈
- **Given** 用户处于城市级地图
- **When** 用户点击一个地点 pin
- **Then** 弹出地点卡：内置封面、名称、类型与城市，以及「加入路线」动作
- **When** 用户点击空白处
- **Then** 弹出最近候选浮层，最多 3 个候选，每个可一键加入路线
- **And** 浮层与地点卡 MUST 定位在地图可视范围内

#### Scenario: 缩放平移与全屏
- **Given** 用户查看发布页地图
- **When** 用户拖拽、滚轮或点击放大 / 缩小按钮
- **Then** 视口相应平移或缩放，且不出全省 / 全市边界
- **When** 用户点击全屏按钮
- **Then** 地图铺满视口，Esc 或再次点击退出

#### Scenario: 途经点连加与上限反馈
- **Given** 用户处于城市级地图
- **When** 用户连续点击不同地点并加入路线
- **Then** 途经点 chips 按加入顺序编号递增，至少支持 2 个、至多 8 个
- **When** 已选 8 个后再次加入
- **Then** 系统给出「最多选择 8 个地点」提示且不改变已选列表

#### Scenario: 表单分组与间距一致
- **Given** 用户查看发布行程表单
- **When** 页面渲染完成
- **Then** 字段按「基本信息 / 路线 / 补充信息」分组
- **And** 同组控件宽度一致，相邻字段间距一致

### Requirement: 发布可被他人理解的旅行计划

系统 SHALL 允许已进入的演示用户发布一条旅行计划，发布者 MUST 取当前身份；系统 MUST 按下列约束校验：标题必填且 ≤ 40 字、目的地 MUST 是行政区划字典中的二级节点代码 `destination_code`（必须选到市）、出发与结束日期必填且结束不早于出发、有效途经点至少两个（至多 8 个）、计划人数为整数且 2–12（含发布者本人）、预算下限不高于上限、兴趣标签最多 5 个、集合区域为选填数组 `meeting_areas`（≤3 个、每个 trim 后 ≤100 字、去重）、集合时间选填且格式合法、日期部分不晚于结束日期；预算范围、兴趣标签与补充说明为选填。目的地名称 MUST 由系统按代码生成，MUST NOT 接受调用方传入的名称。校验失败 MUST NOT 产生新行程。

旧行为与新行为的差异：`meeting_area` 单字符串（≤100 字）替换为 `meeting_areas` 数组（≤3 个、每个 ≤100 字、trim 去重）；其余约束与既有场景全部保留。

#### Scenario: 填写完整必填项后成功发布
- **Given** 用户处于发布行程表单
- **When** 用户填写全部必填项并提交
- **Then** 系统保存该行程，状态为「招募中」
- **And** 已加入人数计入发布者本人
- **And** 该行程出现在旅行灵感首页

#### Scenario: 选填项可留空
- **Given** 用户处于发布行程表单
- **When** 用户仅填写必填项、留空全部选填项（含集合区域与集合时间）并提交
- **Then** 系统正常保存该行程，不因选填项缺失而拒绝
- **And** 集合区域、预算范围、兴趣标签与补充说明在详情页按未填写处理

#### Scenario: 填写集合信息后成功发布
- **Given** 用户处于发布行程表单
- **When** 用户填写 1–3 个集合区域与集合时间并提交
- **Then** 系统保存两者，详情页可看到相同的全部集合区域与集合时间

#### Scenario: 多个集合区域去重与 trim
- **Given** 用户在集合区域依次加入「陈家祠」「 陈家祠 」「永庆坊」
- **When** 表单提交
- **Then** 保存的 `meeting_areas` 为「陈家祠」「永庆坊」两项，顺序保持首次加入顺序

#### Scenario: 集合时间晚于结束日期时拒绝发布
- **Given** 用户填写了集合时间
- **When** 集合时间的日期部分晚于结束日期并提交
- **Then** 系统拒绝发布并给出可读提示
- **And** 不产生新的行程

#### Scenario: 集合时间格式非法时拒绝发布
- **Given** 用户填写了集合时间
- **When** 该值无法解析为日期时间并提交
- **Then** 系统以 400 拒绝并提示集合时间格式非法

#### Scenario: 集合区域超长时拒绝发布
- **Given** 用户填写了集合区域
- **When** 任一集合区域 trim 后超过 100 字并提交
- **Then** 系统拒绝发布并提示集合区域长度上限

#### Scenario: 集合区域超量时拒绝发布
- **Given** 用户已加入 3 个集合区域
- **When** 用户尝试加入第 4 个或直接请求携带 4 个元素提交
- **Then** 前端给出「最多选择 3 个集合区域」提示；后端以 400 `INVALID_INPUT` 拒绝
- **And** 不产生新的行程

#### Scenario: 必填项缺失时拒绝发布
- **Given** 用户处于发布行程表单
- **When** 任一必填项为空时提交
- **Then** 系统拒绝发布并给出可读的校验提示
- **And** 不产生新的行程

#### Scenario: 必填项缺失时逐项给出字段级错误
- **Given** 用户处于发布行程表单
- **When** 用户清空标题、目的地、出发日期、结束日期与途经点后提交
- **Then** 系统拒绝提交且不发出创建请求
- **And** 每个缺失字段各自显示一条字段级错误提示，而不是只显示一条汇总错误

#### Scenario: 日期不合法时拒绝发布
- **Given** 用户处于发布行程表单
- **When** 结束日期早于出发日期并提交
- **Then** 系统拒绝发布并在结束日期字段提示日期不合法

#### Scenario: 途经点不足两个时拒绝发布
- **Given** 用户处于发布行程表单
- **When** 有效途经点少于两个并提交
- **Then** 系统拒绝发布并提示至少写出两个途经点

#### Scenario: 计划人数越界时拒绝发布
- **Given** 用户处于发布行程表单
- **When** 计划人数小于 2、大于 12 或不是整数并提交
- **Then** 系统拒绝发布并提示人数范围

#### Scenario: 预算区间倒置时拒绝发布
- **Given** 用户填写了预算下限与上限
- **When** 下限高于上限并提交
- **Then** 系统拒绝发布并提示预算区间不合法

#### Scenario: 后端独立校验发布约束
- **Given** 调用方绕过前端直接请求 `POST /api/trips`
- **When** 请求缺少必填字段、结束日期早于出发、有效途经点少于两个、人数为 1 或 13、预算下限高于上限、`meeting_areas` 超量或单项超长
- **Then** 系统返回 400 `INVALID_INPUT`
- **And** 数据中不产生新的行程

#### Scenario: 目的地代码非法时拒绝发布
- **Given** 调用方绕过前端直接请求 `POST /api/trips`
- **When** 请求携带不存在、非二级或格式错误的 `destination_code`
- **Then** 系统返回 400 `INVALID_INPUT`
- **And** 数据中不产生新的行程

#### Scenario: 发布成功后跳转详情页
- **Given** 用户提交了一条合法的旅行计划
- **When** 系统保存成功
- **Then** 页面跳转到该行程的详情地址 `#/trips/{id}`
- **And** 详情页标题与该次填写的一致

#### Scenario: 首页立即可见新发布的行程
- **Given** 用户刚发布了一条行程
- **When** 用户回到旅行灵感首页
- **Then** 该行程出现在默认的「招募中的行程」列表或按目的地筛选后的结果中
- **And** 状态为「招募中」

#### Scenario: 发布者身份取自当前身份
- **Given** 用户以某个演示身份进入系统
- **When** 用户发布一条行程并查看详情
- **Then** 该行程的发布者是当前身份
- **And** 当前同行者列表包含发布者本人
- **And** 详情页对发布者本人展示「这是你发布的行程」

#### Scenario: 发布的数据在重启后仍在
- **Given** 用户成功发布了一条行程
- **When** 后端进程重启后再次查询该行程
- **Then** 系统仍返回该行程的完整字段

### Requirement: 查看行程详情与清晰的状态

系统 SHALL 提供行程详情视图，展示完整途经点、起止日期、计划与当前人数、发布者资料与旅行兴趣、当前同行者、集合区域（多值列表）与集合时间、状态徽标；集合区域为空数组 / null 或集合时间为空时 MUST 显示「待确认」，并提示出发前在聊天中确认。同行申请入口 MUST 仅在「招募中且未满员且非本人发布」时可用，提交行为属 REQ-003；已结束行程的游后分享区内容属 REQ-004。

旧行为与新行为的差异：集合区域由单值文本改为多值列表展示（顺序与发布 / 编辑一致）；空值口径不变；原有六条场景全部保留。

#### Scenario: 查看行程详情
- **Given** 用户在首页看到某条行程
- **When** 用户进入该行程详情页
- **Then** 详情页展示完整途经点、起止日期、计划人数与当前人数、发布者简介与旅行兴趣、当前同行者与状态徽标
- **And** 当前同行者至少包含发布者本人

#### Scenario: 展示集合区域与集合时间
- **Given** 一条行程填写了多个集合区域与集合时间
- **When** 用户查看详情
- **Then** 详情页按顺序展示全部集合区域与集合时间，且与发布/编辑时填写的内容一致

#### Scenario: 集合信息为空时显示待确认
- **Given** 一条行程没有填写集合区域或集合时间
- **When** 用户查看详情
- **Then** 对应位置显示「待确认」
- **And** 提示出发前在聊天中确认

#### Scenario: 状态标识清晰
- **Given** 一条行程处于招募中、已满员或已结束中的任一状态
- **When** 用户在卡片或详情页查看该行程
- **Then** 系统以文字明确展示其当前状态
- **And** 用户据此可判断该行程是否仍可加入

#### Scenario: 同行申请入口按资格显示
- **Given** 一条招募中且未满员的他人行程
- **When** 用户查看详情页
- **Then** 系统展示可用的同行申请入口
- **Given** 行程已满员、已结束，或由当前用户发布
- **When** 用户查看详情页
- **Then** 同行申请入口被隐藏或置灰

#### Scenario: 已结束行程展示游后分享区占位
- **Given** 一条已结束的行程
- **When** 用户查看详情页
- **Then** 页面展示游后分享区
- **And** 分享内容按 REQ-004 呈现，本能力只保留展示位

#### Scenario: 旧数据集合区域升级不丢值
- **Given** 数据库存在 V16 时代填写了 `meeting_area` 的行程
- **When** V17 迁移执行后用户查看该行程
- **Then** `meeting_areas` 为包含原值的单元素数组
- **And** 详情页集合区域展示原值

### Requirement: 发布者维护集合信息

系统 SHALL 允许行程发布者修改自己行程的集合区域（`meeting_areas` 数组）与集合时间，且 MUST NOT 在同一操作中修改其他字段。可编辑状态为「招募中」与「已满员」；「已结束」行程 MUST 拒绝编辑。非发布者 MUST 被拒绝，且不改变任何字段。集合区域 ≤3 个、每个 trim 后 ≤100 字、去重；字段类错误（超量、单项超长、集合时间格式非法、日期部分晚于结束日期）MUST 以 400 `INVALID_INPUT` 拒绝，非发布者 MUST 以 403 `FORBIDDEN` 拒绝，已结束行程 MUST 以 409 拒绝；不引入 422。保存后行程详情、聊天页集合信息与「我的旅行」MUST 立即反映新值。

旧行为与新行为的差异：编辑对象由 `meeting_area` 单字符串改为 `meeting_areas` 数组，校验增加 ≤3 与去重；错误码口径与既有五条场景全部保留。

#### Scenario: 发布者编辑集合信息
- **Given** 用户是自己发布的、状态为「招募中」的行程发布者
- **When** 用户修改集合区域（1–3 个）与集合时间并保存
- **Then** 系统更新该行程的这两个字段
- **And** 详情页、聊天页集合信息与「我的旅行」显示新值

#### Scenario: 已满员行程仍可编辑集合信息
- **Given** 一条已满员的行程
- **When** 发布者修改集合区域或集合时间并保存
- **Then** 系统更新成功，行程状态保持不变

#### Scenario: 已结束行程不能编辑集合信息
- **Given** 一条已结束的行程
- **When** 发布者尝试修改集合信息
- **Then** 详情页不展示编辑入口
- **And** 直接调用接口被拒绝（409），且不改变任何字段

#### Scenario: 非发布者不能编辑集合信息
- **Given** 当前用户不是该行程发布者
- **When** 用户尝试修改集合信息
- **Then** 系统拒绝（403）且不改变任何字段

#### Scenario: 集合信息校验失败时不保存
- **Given** 发布者编辑集合信息
- **When** 集合区域超过 3 个、任一超过 100 字、集合时间格式非法，或日期部分晚于结束日期
- **Then** 系统以 400 `INVALID_INPUT` 拒绝并提示对应字段
- **And** 行程保持修改前的值

## ADDED Requirements

### Requirement: 行程详情路线地图

系统 SHALL 在行程详情页为目的地有城市数据的行程渲染只读 CityTravelMap：六 Layer 底图、按 stops 顺序的编号水滴 pin、蓝→紫渐变路线白 casing、图例与竖排控制条（放大 / 缩小 / Reset View / 全屏）；地图旁 SHALL 以 TravelerLayer 展示该路线的同行者聚合气泡（重合度％＋人数，数据模型计算）；地图下方 SHALL 展示行程安排条（序号徽标 + 地点名 + 相邻点「约 x km」直线距离估算）；点击途经点列表项、行程条卡片或地图 pin MUST 聚焦该点并弹出地点卡；地图 MUST NOT 提供修改路线的动作。目的地无城市数据或途经点不在索引时 SHALL 降级为文本列表并给出说明。

旧行为与新行为的差异：R1 只读 PlaceMap 升级为只读 CityTravelMap（六 Layer＋渐变路线＋TravelerLayer 同行者气泡）；聚焦 / 行程条 / 降级语义保留。

#### Scenario: 详情渲染路线地图与行程安排条
- **Given** 一条目的地有城市数据、途经点均在索引的行程
- **When** 用户进入详情页
- **Then** 页面渲染只读 CityTravelMap：编号 pin 按 stops 顺序、蓝→紫渐变路线白 casing、六 Layer、图例与控制条
- **And** 地图下方行程安排条列出全部途经点与相邻「约 x km」估算

#### Scenario: 详情地图展示路线同行者
- **Given** 一条行程的路线与城市数据中的旅行者路线存在共同景点
- **When** 用户进入详情页
- **Then** 地图旁显示同行者聚合气泡（重合度％＋人数，由数据计算）
- **When** 用户点击查看同行者
- **Then** 面板列出共同景点、旅行日期与偏好标签

#### Scenario: 点击途经点聚焦并弹出地点卡
- **Given** 详情页已渲染路线地图
- **When** 用户点击途经点列表项、行程条卡片或地图 pin
- **Then** 地图视口聚焦该点
- **And** 弹出地点卡（内置封面 + 名称 + 类型），不含修改路线动作

#### Scenario: 详情地图缩放与全屏
- **Given** 详情页已渲染路线地图
- **When** 用户拖拽、滚轮、按钮缩放或切换全屏
- **Then** 视口相应变化，Esc 退出全屏
- **And** 1440 / 768 / 390 宽度与浅 / 深主题下不横向溢出

#### Scenario: 无离线点位时降级文本列表
- **Given** 一条目的地无城市数据、或含不在索引途经点的行程
- **When** 用户进入详情页
- **Then** 不渲染路线地图，保留文本途经点列表
- **And** 给出「该目的地暂无离线地图」或「部分途经点不在地图地名库」的说明

### Requirement: 三级旅行地图探索

系统 SHALL 提供独立探索路由 `#/map`（中国）→ `#/map/{provinceCode}`（省）→ `#/map/{provinceCode}/{cityCode}`（城市），并在主导航提供「旅行地图」入口；三级 MUST 为独立组件（ChinaMap / ProvinceMap / CityTravelMap）切换，Zoom MUST NOT 代替换层。ChinaMap 渲染离线简化省级区域（hover / selected / 搜索）；ProvinceMap 渲染省轮廓与城市节点且无城市间连线；CityTravelMap 以六个独立 SVG Layer 渲染轻导航底图与 POI。面包屑 MUST 可回层；无数据城市 MUST 显示统一 fallback，不白屏不报错。

#### Scenario: 中国地图选省
- **Given** 用户进入 `#/map`
- **When** 页面渲染完成
- **Then** 显示中国省级区域地图（34 省级单元的离线简化省形），省份可 hover 高亮与 selected 标记
- **And** 不显示景点 / 路线 / 同行者
- **When** 用户点击「广东省」
- **Then** 路由变为 `#/map/440000` 并渲染广东省级地图

#### Scenario: 搜索省或市直达
- **Given** 用户处于中国地图
- **When** 用户搜索「广州」并选择结果
- **Then** 直达 `#/map/440000/440100` 城市旅行地图
- **When** 用户搜索「广东」并选择结果
- **Then** 直达省级地图

#### Scenario: 省级地图选城市且无连线
- **Given** 用户处于广东省级地图
- **When** 页面渲染完成
- **Then** 显示广州 / 深圳 / 佛山 / 东莞 / 珠海等城市节点与省轮廓（广东手工布局，其余省由区划字典＋确定性布局生成）
- **And** MUST NOT 出现城市间连线
- **When** 用户点击「广州」
- **Then** 路由变为 `#/map/440000/440100` 并渲染广州城市旅行地图

#### Scenario: 城市旅行地图六 Layer
- **Given** 用户进入广州城市旅行地图
- **When** 页面渲染完成
- **Then** RoadLayer / WaterLayer / ParkLayer / PoiLayer 独立渲染（珠江、越秀公园、广州塔 / 海心沙 / 花城广场 / 北京路等 POI 可见）
- **And** 面包屑显示「中国 > 广东省 > 广州市」

#### Scenario: 面包屑逐级返回
- **Given** 用户处于广州城市旅行地图
- **When** 用户点击面包屑「广东省」
- **Then** 回到广东省级地图
- **When** 用户点击面包屑「中国」
- **Then** 回到中国地图

#### Scenario: 无数据城市 fallback
- **Given** 用户进入一个城市数据未覆盖的城市层（例如拉萨）
- **When** 页面渲染完成
- **Then** 显示「该城市详细旅行地图正在完善」
- **And** 不白屏、不抛错，面包屑（中国 > 省 > 市）仍可返回

#### Scenario: MVP 十城可进入
- **Given** 北京 / 上海 / 广州 / 深圳 / 成都 / 重庆 / 杭州 / 西安 / 南京 / 苏州 任一城市
- **When** 用户经省层或搜索进入该城市层
- **Then** 渲染该城 CityTravelMap（POI 与底图 Layer 来自该城数据模块）

### Requirement: 路线生成与行程同步

系统 SHALL 在城市旅行地图提供「生成路线」动作：仅当已选景点 ≥2 时可用；生成后 RouteLayer MUST 以蓝→紫渐变高亮路线并按顺序渲染编号 pin；地图旁行程列表 MUST 与地图编号双向同步（点击列表项聚焦地图 pin，点击 pin 高亮列表项）；统计卡 MUST 展示景点数量、预计距离、预计时间与行程顺序，距离与时间 MUST 标「预计」（离线直线距离×步行速度估算，MUST NOT 伪装真实导航结果）；加入 / 移除景点 MUST 即时更新编号与统计。

#### Scenario: 少于两个景点不能生成路线
- **Given** 用户只选了 1 个景点
- **When** 用户查看生成路线动作
- **Then** 动作不可用或提示至少选择两个景点

#### Scenario: 生成路线后编号与列表同步
- **Given** 用户依次选择广州塔 / 海心沙 / 花城广场 / 北京路
- **When** 用户点击生成路线
- **Then** 地图渲染 ①②③④ 编号 pin 与蓝→紫渐变路线
- **And** 行程列表按同顺序列出四个景点
- **When** 用户点击列表第 3 项
- **Then** 地图聚焦花城广场 pin

#### Scenario: 统计卡标预计
- **Given** 路线已生成（4 个景点）
- **When** 用户查看统计卡
- **Then** 展示景点数量 4、预计距离（km）、预计时间（小时/分钟）与顺序
- **And** 距离与时间文案含「预计」

#### Scenario: 移除景点即时同步
- **Given** 路线已生成 4 个景点
- **When** 用户移除第 2 个景点
- **Then** 编号重排为 ①②③，统计卡数量与距离即时更新

### Requirement: 地图同行者发现

系统 SHALL 在路线生成后于地图旁显示同行者聚合气泡（最高重合度％＋同行者人数＋「查看同行者」入口）；点击后 SHALL 打开同行者面板，每位展示：路线重合度、共同景点、旅行日期、旅行偏好标签、「查看资料」与「发起同行邀请」。重合度 MUST 由数据模型（城市 travelers 的路线景点集合与当前路线的共同景点比例）经纯函数计算，MUST NOT 在 UI 组件硬编码百分比；面板 MUST 按重合度降序。旅行者数据 MAY 为 Mock，但 MUST 存于城市数据模块；「查看资料」MUST 链接真实用户资料页（traveler 引用真实 userId 时）；「发起同行邀请」MUST 跳转该旅行者真实行程的详情申请入口（traveler.tripId 存在时），无真实行程时 MUST 给出演示提示而非伪造发送成功。

#### Scenario: 聚合气泡由数据计算
- **Given** 当前路线为广州塔 / 海心沙 / 花城广场 / 北京路
- **And** 城市数据中某旅行者路线含其中 3 个景点
- **When** 路线生成完成
- **Then** 聚合气泡显示 75% 同路与对应人数（3/4 计算所得）
- **And** 百分比来自纯函数而非组件常量

#### Scenario: 面板展示共同景点与偏好
- **Given** 用户点击「查看同行者」
- **When** 面板打开
- **Then** 每位旅行者展示重合度、共同景点名称、旅行日期区间与偏好标签
- **And** 按重合度降序排列

#### Scenario: 查看资料与发起邀请
- **Given** 面板中某旅行者引用真实 userId 与 tripId
- **When** 用户点击「查看资料」
- **Then** 跳转该用户资料页
- **When** 用户点击「发起同行邀请」
- **Then** 跳转该真实行程详情页的申请入口

#### Scenario: 无真实行程的邀请给演示提示
- **Given** 面板中某旅行者无 tripId
- **When** 用户点击「发起同行邀请」
- **Then** 给出演示提示（Mock 数据说明），MUST NOT 显示伪造的发送成功

### Requirement: 按级加载的城市数据

系统 SHALL 以数据驱动结构组织地图：ChinaMap / ProvinceMap / CityTravelMap 三组件＋Province Data / City Data / POI Data / Route Data 四层数据；新增城市 MUST 主要通过新增 City Data＋POI Data＋Map Layer Data 完成，MUST NOT 新增页面组件。城市重数据（Layer / POI 详情 / travelers）MUST 按城懒加载（动态 import），MUST NOT 一次性静态加载全国道路与图层数据；搜索 / 校验索引 MAY 静态轻量存在（名称 / 别名 / 城市 / 坐标）。MVP MUST 完整支持北京 / 上海 / 广州 / 深圳 / 成都 / 重庆 / 杭州 / 西安 / 南京 / 苏州，其中广州完成度最高；legacy 广东城市 MUST 保留为同构数据模块以兼容发布与详情。

#### Scenario: 城市数据懒加载
- **Given** 用户处于中国或省级地图
- **When** 城市层尚未进入
- **Then** 该城 Layer / travelers 数据模块未被加载
- **When** 用户进入该城市层
- **Then** 对应数据模块按需加载并渲染

#### Scenario: 新增城市只加数据
- **Given** 开发者为一个新城市新增 City Data＋POI Data＋Layer Data 并登记 registry
- **When** 用户进入该城市层
- **Then** 复用同一 CityTravelMap 渲染，无需新增页面组件

#### Scenario: 搜索索引轻量静态
- **Given** 应用首屏加载
- **When** 检查静态 bundle
- **Then** 仅含名称 / 别名 / 城市 / 坐标的轻量索引，不含全国道路 / 水域 / 公园 / travelers 重数据
