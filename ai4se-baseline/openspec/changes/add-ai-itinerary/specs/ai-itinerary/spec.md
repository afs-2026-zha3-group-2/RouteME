# ai-itinerary 增量规格（add-ai-itinerary）

## ADDED Requirements

### Requirement: 旅行条件输入与地点选择

系统 SHALL 提供 AI 规划页（`#/ai-planner`）左栏条件表单：出发地与目的地 MUST 各支持「搜索地点」「使用当前定位」（仅出发地）「地图点击选点」三种设置方式，选定后字段展示地点名称且地图定位到该点；旅行日期、游玩时长（半天 / 1 天 / 2 天）、预算（选填，正数）、出行方式（公共交通 + 步行 / 步行 / 驾车）、兴趣偏好（多选）、行程节奏（宽松 / 适中 / 紧凑）MUST 可设置；「✨ AI 推荐路线」按钮 MUST 仅在出发地、目的地、旅行日期三者齐备时可用。

#### Scenario: 搜索设置出发地
- **Given** 用户处于 AI 规划页
- **When** 用户在出发地搜索框输入「广州南站」并选中候选
- **Then** 出发地字段显示「广州南站」
- **And** 地图定位到该地点并展示标记

#### Scenario: 当前定位设置出发地
- **Given** 用户处于 AI 规划页且浏览器定位可用
- **When** 用户点击「使用当前定位」
- **Then** 出发地设置为定位反解出的地点名称
- **Given** 浏览器定位不可用或被拒绝
- **When** 用户点击「使用当前定位」
- **Then** 显示可读的定位失败提示，出发地保持原值，不伪造位置

#### Scenario: 地图点击设置地点
- **Given** 用户处于 AI 规划页
- **When** 用户点击地图任意位置并确认选点
- **Then** 当前正在设置的地点字段（出发地或目的地）写入该点反解名称
- **And** 地图在该点展示标记

#### Scenario: 搜索或地图点击设置目的地
- **Given** 用户处于 AI 规划页
- **When** 用户搜索「广州市」并选中候选，或点击地图选点
- **Then** 目的地字段显示所选地点名称
- **And** 地图聚焦到目的地范围

#### Scenario: 可选条件可设置
- **Given** 用户处于 AI 规划页
- **When** 用户设置日期 2026-11-21、游玩时长 1 天、预算 500 元、出行方式公共交通 + 步行、兴趣美食 / 摄影 / City Walk、节奏适中
- **Then** 各字段展示所设值
- **And** 预算、时长、出行方式、兴趣、节奏留空时不阻止生成

#### Scenario: 生成按钮按必填项门控
- **Given** 用户尚未填齐出发地、目的地、旅行日期
- **When** 用户查看「✨ AI 推荐路线」按钮
- **Then** 按钮不可用
- **When** 三者齐备
- **Then** 按钮可用

### Requirement: AI 行程生成与重新生成

系统 SHALL 通过后端 OpenAI 兼容代理（`POST /api/ai/itineraries/generate`）调用 AI 服务；后端 MUST 在生成请求内按目的地经纬度与旅行日期自取真实天气，与用户条件、预算约束一起组装为提示词，并随方案返回本次使用的天气摘要；AI 输出 MUST 为严格 JSON 且包含至少 2 个 POI，每个 POI 含名称、推荐理由、游玩顺序、建议到达时间、建议停留时长、室内 / 户外标记，整体含天气注意事项、建议携带物品与预算四项估算（交通 / 门票 / 餐饮 / 其他）；后端 MUST 校验输出结构，非法输出按失败处理；AI MUST NOT 产出经纬度、路线、距离、交通时间或实时价格；「重新生成」MUST 基于当前条件重跑并整体替换方案。

#### Scenario: 生成完整推荐行程
- **Given** 用户已填出发地「广州南站」、目的地「广州市」、日期 2026-11-21、1 天、预算 500 元、兴趣美食 / 摄影 / City Walk
- **When** 用户点击「✨ AI 推荐路线」且 AI 与天气服务正常
- **Then** 右栏展示至少 2 个 POI 的行程时间轴
- **And** 每个 POI 展示推荐理由、建议到达时间、建议停留时长
- **And** 展示天气注意事项、建议携带物品与预算估算

#### Scenario: 重新生成基于当前条件
- **Given** 用户已生成一份方案并把节奏改为「紧凑」
- **When** 用户点击「重新生成」
- **Then** 系统以修改后的条件重新请求 AI
- **And** 新方案整体替换旧方案，地图与统计同步更新

#### Scenario: 生成响应携带真实天气
- **Given** 目的地经纬度与旅行日期合法且 Open-Meteo 可用
- **When** 后端处理生成请求
- **Then** 后端先调用 Open-Meteo 获取真实天气并注入提示词
- **And** 响应同时返回行程方案与本次使用的天气摘要

#### Scenario: AI 输出非法时按失败处理
- **Given** AI 上游返回无法解析为约定 JSON 的内容或少于 2 个 POI
- **When** 后端校验输出
- **Then** 返回 `AI_INVALID_OUTPUT` 错误
- **And** 前端展示 Error 与 Retry，不展示伪造行程

#### Scenario: AI 不产出地图数据
- **Given** 调用方请求 `POST /api/ai/itineraries/generate`
- **When** 后端组装提示词并解析 AI 输出
- **Then** 提示词明确禁止 AI 给出经纬度 / 路线 / 距离 / 交通时间 / 实时价格
- **And** 响应契约不含经纬度、路线、距离、交通时间字段（这些由前端经高德获取）

### Requirement: 真实天气参与推荐

系统 SHALL 通过后端代理（`GET /api/weather/forecast`）按目的地经纬度与旅行日期调用 Open-Meteo，返回最高温度、最低温度、降雨概率、降水量、天气状态、风速与 UV（接口可用时）；天气摘要 MUST 注入 AI 提示词实际影响推荐：降雨时优先室内景点并减少长时间户外，高温 / 高 UV 时减少中午长时间户外，低温时提醒早晚温差；右栏 MUST 展示天气卡、AI Tips 与建议携带物品，且建议与当天真实天气对应。

#### Scenario: 按目的地与日期获取天气
- **Given** 用户已选择目的地「广州市」与日期 2026-11-21
- **When** 系统请求天气
- **Then** 后端以目的地经纬度与该日期调用 Open-Meteo
- **And** 右栏天气卡展示最高 / 最低温度、降雨概率、天气状态、风速与 UV（可用时）

#### Scenario: 雨天推荐室内优先
- **Given** 目的地当天降雨概率高（例如 ≥60%）
- **When** AI 生成方案
- **Then** 方案中室内景点占比高于无雨口径，长时间户外活动减少
- **And** AI Tips 与装备建议包含雨伞 / 防水鞋类物品

#### Scenario: 高温高 UV 推荐防晒补水
- **Given** 目的地当天最高温度高或 UV 强
- **When** AI 生成方案
- **Then** 中午时段避免长时间户外安排
- **And** 装备建议包含防晒霜 / 帽子 / 饮用水类物品

#### Scenario: 低温推荐外套与温差提醒
- **Given** 目的地当天最低温度低
- **When** AI 生成方案
- **Then** AI Tips 包含携带外套与早晚温差提醒

#### Scenario: 超出预报窗口的日期被拒绝
- **Given** 用户选择的旅行日期超出 Open-Meteo 预报窗口（约 16 天）
- **When** 系统请求天气
- **Then** 后端返回 400 与可读提示
- **And** 不伪造天气数据

### Requirement: 地图验证与路线同步

系统 SHALL 把 AI 返回的每个 POI 名称经高德地图 JavaScript API 2.0 地点搜索 / 地理编码解析为真实经纬度后才渲染 Marker；解析失败的 POI MUST 提示更换，MUST NOT 伪造坐标；地图 Marker MUST 使用 1、2、3… 编号且与行程列表顺序一致；路线、总距离与预计交通时间 MUST 取自高德路线规划（按用户出行方式），AI 不产出路线数据；景点集合或顺序变化后 MUST 重新计算路线、距离与时间。

#### Scenario: POI 经高德解析后上图
- **Given** AI 返回「广州塔」「海心沙」「花城广场」「北京路步行街」
- **When** 前端逐个经高德地点搜索解析坐标
- **Then** 每个成功解析的 POI 在地图展示编号 Marker
- **And** 编号 1–4 与行程列表顺序一致

#### Scenario: 路线数据来自高德
- **Given** 行程含 ≥2 个已解析 POI 且出行方式为公共交通 + 步行
- **When** 系统计算路线
- **Then** 地图展示高德返回的实际路线
- **And** 总距离与预计交通时间取自高德路线结果并标注「预计」

#### Scenario: POI 解析失败提示更换
- **Given** AI 返回的某个 POI 名称在高德搜索无结果
- **When** 前端解析该 POI
- **Then** 该 POI 在列表中标记「未定位」并提供更换入口
- **And** 地图不渲染伪造 Marker，路线按已解析 POI 计算

#### Scenario: 景点变化后重算
- **Given** 行程已生成且地图已展示路线
- **When** 用户删除 / 更换 / 调序任一景点
- **Then** 地图 Marker 编号、路线、总距离与预计交通时间重新计算
- **And** 统计卡与行程列表同步更新

### Requirement: 行程编辑

系统 SHALL 允许用户在右栏行程列表删除景点、更换景点（搜索替换）与上下移动调整顺序；每次编辑后地图与统计 MUST 同步重算；有效景点少于 2 个时 MUST 提示补齐，且「保存行程」不可用。

#### Scenario: 删除景点
- **Given** 行程含 4 个景点
- **When** 用户删除第 2 个景点
- **Then** 列表剩余 3 个景点并重新编号
- **And** 地图与路线统计重算

#### Scenario: 更换景点
- **Given** 行程含「北京路步行街」
- **When** 用户点击更换并搜索选中「永庆坊」
- **Then** 该位置替换为「永庆坊」，顺序不变
- **And** 新景点经高德解析后更新 Marker 与路线

#### Scenario: 调整顺序
- **Given** 行程顺序为 A → B → C
- **When** 用户把 C 上移到 B 之前
- **Then** 列表与地图编号变为 A → C → B
- **And** 路线按新顺序重算

#### Scenario: 景点不足两个时提示补齐
- **Given** 行程只剩 1 个有效景点
- **When** 用户查看右栏
- **Then** 展示「至少保留 2 个景点」提示
- **And** 「保存行程」不可用

### Requirement: 预算估算与超预算反馈

系统 SHALL 在右栏预算卡展示交通、门票、餐饮、其他四项估算与合计，全部 MUST 标记「AI 估算」（无真实价格来源）；用户填写预算且合计超过预算时 MUST 显示「预计超过预算 X 元」并提供「AI 帮我降低预算」动作，点击后携带预算约束重新生成；未填写预算时不展示超预算提示。

#### Scenario: 预算四项与 AI 估算标注
- **Given** AI 方案已生成
- **When** 用户查看预算卡
- **Then** 展示交通 / 门票 / 餐饮 / 其他四项与合计
- **And** 每项与合计均带「AI 估算」标注，不表述为真实价格

#### Scenario: 超预算提示与降预算动作
- **Given** 用户预算 500 元且方案合计 580 元
- **When** 用户查看预算卡
- **Then** 显示「预计超过预算 80 元」
- **And** 提供「AI 帮我降低预算」按钮
- **When** 用户点击该按钮
- **Then** 系统携带预算约束重新生成方案

#### Scenario: 未填预算不提示超支
- **Given** 用户未填写预算
- **When** 方案生成完成
- **Then** 预算卡仍展示四项估算与「AI 估算」标注
- **And** 不展示超预算提示与降预算按钮

### Requirement: 外部服务失败状态

系统 SHALL 在高德地图、Open-Meteo 或 AI 服务请求失败时，于对应区域展示明确的 Error 文案与 Retry 按钮，请求进行中展示 Loading；失败 MUST NOT 产出伪造的行程、天气、路线或价格；AI 服务未配置 key 时后端 MUST 返回 503 `AI_NOT_CONFIGURED` 与可读提示。

#### Scenario: 生成中展示 Loading
- **Given** 用户点击「✨ AI 推荐路线」
- **When** 天气与 AI 请求进行中
- **Then** 右栏展示 Loading 状态，生成按钮不可重复点击

#### Scenario: AI 失败可重试
- **Given** AI 上游返回错误或超时
- **When** 后端归一错误返回前端
- **Then** 右栏展示 AI 失败文案与 Retry 按钮
- **And** 不展示任何伪造行程
- **When** 用户点击 Retry 且服务恢复
- **Then** 重新生成成功

#### Scenario: 天气失败可重试
- **Given** Open-Meteo 请求失败
- **When** 前端收到天气错误
- **Then** 天气卡展示 Error 与 Retry，不展示伪造天气
- **And** 用户可选择重试天气后再生成

#### Scenario: 高德失败可重试
- **Given** 高德路线或 POI 解析请求失败
- **When** 前端收到高德错误
- **Then** 地图区域展示 Error 与 Retry
- **And** 距离 / 时间统计不展示伪造数值

#### Scenario: AI 未配置 key
- **Given** 后端未配置 AI key
- **When** 调用方请求 `POST /api/ai/itineraries/generate`
- **Then** 返回 503 `AI_NOT_CONFIGURED` 与可读提示
- **And** 前端展示配置缺失说明与 Retry

### Requirement: AI 行程快照保存

系统 SHALL 通过 `POST /api/ai/itineraries` 把用户确认的 AI 方案落库为快照，内容 MUST 至少包含出发地、目的地、日期、POI（名称 + 经纬度 + 顺序）、出行方式、路线信息、距离、时间、天气摘要、AI 推荐理由与 AI 预算估算；快照 MUST 归属当前用户；非法或缺失关键字段的快照 MUST 以 400 拒绝。

#### Scenario: 保存完整快照
- **Given** 用户已生成并确认一份 ≥2 个已定位 POI 的方案
- **When** 用户触发保存快照
- **Then** 后端持久化完整快照并返回快照 id
- **And** 快照包含出发地 / 目的地 / 日期 / POI 经纬度与顺序 / 出行方式 / 路线信息 / 距离 / 时间 / 天气摘要 / 推荐理由 / 预算估算

#### Scenario: 快照归属当前用户
- **Given** 用户以某个演示身份保存快照
- **When** 后端记录快照
- **Then** 快照归属该身份
- **And** 其他身份不能把该快照链接到自己的行程

#### Scenario: 快照重启后仍在
- **Given** 用户成功保存一份快照
- **When** 后端进程重启后按 id 查询
- **Then** 系统仍返回该快照的完整字段

#### Scenario: 非法快照被拒绝
- **Given** 调用方绕过前端直接请求 `POST /api/ai/itineraries`
- **When** 请求缺少目的地 / 日期 / POI 少于 2 个或 POI 缺经纬度
- **Then** 返回 400 `INVALID_INPUT`
- **And** 不产生新快照
