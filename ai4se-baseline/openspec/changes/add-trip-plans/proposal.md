# 变更提案：add-trip-plans

- **需求：** REQ-002（`requirement-workspace/requirements/REQ-002-trip-plans.md`）
- **能力：** `trip-plans`（ADDED）｜ **迭代：** 1「灵感与发布」｜ **规模：** M（闭环地基，页面 4 个）

## 问题

REQ-001 只验证了脚手架链路，RouteME 还没有任何业务能力。产品价值闭环「旅行灵感 → 发布行程 → 发现同行者 → …」缺少起点：用户既看不到别人的真实旅行计划，也无法发布自己的行程。本提案新增 `trip-plans` 能力，让大学生能选择演示身份进入系统、在灵感首页浏览并按目的地/日期筛选公开行程、发布自己的旅行计划并查看行程详情，从而验证「用户愿意发布可被他人理解的旅行计划」这一核心假设，并为 REQ-003（同行匹配）与 REQ-004（游后分享）提供可筛选的行程池。

## 范围

**In scope（业务能力与页面）**

- 演示用户选择：从 2–3 个预设账户中选择身份进入系统（不做完整注册/验证码/找回密码）。
- 旅行灵感首页：以卡片展示公开行程（标题、目的地、日期、简单路线、兴趣标签、发布者昵称、已加入/计划人数、状态），支持按目的地与日期筛选，含空状态。
- 发布行程：必填（标题、目的地、出发日期、结束日期、路线/行程描述、计划人数）+ 选填（集合区域、预算范围、兴趣标签、补充说明），含必填缺失与日期非法校验。
- 行程详情：完整路线、日期人数、发布者简介与兴趣、当前同行者、同行申请入口（占位）、游后分享区（占位）。
- 行程状态定义与展示：招募中 / 已满员 / 已结束（作为 REQ-003/004 的共享状态锚点）。

**Out of scope**

- 路线匹配打分与匹配原因、同行申请/接受/拒绝/取消、人数上限联动、聊天、退出/举报/安全提示（→ REQ-003）。
- 游后分享发布、参考此行程发布（→ REQ-004）。
- AI 推荐、无限信息流、热门榜单、地图导航、实时定位、订票/酒店/支付、实名认证、积分勋章、头像上传（→ P2 / 明确不做 / 可降级为默认头像）。

## 影响面（业务）

| 位置（能力 / 页面） | 改动 |
|---|---|
| `trip-plans` 能力 | 新增：浏览、筛选、发布、详情、状态展示 |
| 旅行灵感首页 | 首页语义由「问候语展示」演进为「灵感首页」；`hello-world` 脚手架验收能力保留不动 |
| 演示用户选择页 / 发布行程页 / 行程详情页 | 新增业务页面 |
| 下游 `trip-companions` / `trip-experiences` | 消费本能力的行程、状态与兴趣标签（不在本 change 实现） |
