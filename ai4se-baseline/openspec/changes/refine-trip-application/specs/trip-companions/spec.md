# trip-companions 增量规格（refine-trip-application）

## MODIFIED Requirements

### Requirement: 提交与取消同行申请

系统 SHALL 允许用户对招募中且未满员的他人行程提交同行申请，申请说明为选填且不超过 120 字；MUST 阻止申请自己的行程、重复申请（已有待处理或已接受申请）、对已满员或已结束行程的申请。行程详情页 SHALL 在可申请时展示内联申请区（说明输入、提交按钮与聊天权限说明），提交成功后 SHALL 展示待处理状态与撤回入口，不依赖弹窗承载申请；重复申请 MUST 提示「已申请，请等待回应」，已满员或已结束 MUST 展示可读原因。上述拒绝 MUST 由服务端执行，不只依赖前端隐藏。

#### Scenario: 可申请行程展示内联申请区
- **Given** 一条他人发布的行程处于「招募中」且未满员，当前用户没有待处理或已接受的申请
- **When** 用户打开行程详情
- **Then** 页面在操作区展示内联申请表单：一句申请说明（选填、120 字以内）、「提交同行申请」按钮
- **And** 展示「提交后对方接受才会开放聊天，不会变成无条件私聊」的说明
- **And** 不使用弹窗承载申请表单

#### Scenario: 提交申请并进入待处理
- **Given** 一条招募中且未满员的他人行程，当前用户没有待处理或已接受的申请
- **When** 用户填写（或留空）申请说明并提交
- **Then** 系统生成一条「待处理」申请
- **And** 申请区展示「申请已提交，等待 {发布者昵称} 回应。处理前你可以随时撤回。」与「撤回申请」
- **And** 刷新页面后仍展示待处理状态，不重新出现申请表单
- **And** 发布者能看到申请者资料与申请说明

#### Scenario: 说明选填且不超过 120 字
- **Given** 用户在申请表单留空或只输入空白
- **When** 用户提交
- **Then** 系统接受并生成一条「待处理」申请，申请说明为空
- **And** 用户输入超过 120 字时，前端阻止提交或提示最多 120 字，且不生成申请

#### Scenario: 不能申请自己发布的行程
- **Given** 用户查看自己发布的行程
- **When** 用户尝试申请同行
- **Then** 系统不展示申请入口
- **And** 服务端拒绝该申请且不生成申请
- **And** 发布者的申请处理与结束行程入口保持可用

#### Scenario: 不能重复申请
- **Given** 用户对某行程已有待处理或已接受的申请
- **When** 用户再次提交申请（包括页面停留期间在其他标签页已提交）
- **Then** 服务端拒绝并返回重复申请错误，不新增申请
- **And** 前端提示「已申请，请等待回应」
- **And** 申请区刷新为待处理或已匹配状态

#### Scenario: 已满员或已结束的行程不能申请
- **Given** 一条「已满员」或「已结束」的行程
- **When** 用户打开行程详情或提交同行申请
- **Then** 申请入口不可用，并展示「人数已满」或「行程已结束」的原因
- **And** 服务端同样拒绝，不生成新申请
- **And** 拒绝错误码为 `TRIP_NOT_OPEN`；若当前用户已有有效申请，则按 `DUPLICATE_APPLICATION` 拒绝
- **And** 拒绝由服务端执行，不只依赖前端隐藏

#### Scenario: 处理前取消申请
- **Given** 用户有一条「待处理」申请
- **When** 用户在发布者处理前取消
- **Then** 申请状态变为「已取消」
- **And** 发布者侧的待处理数量同步减少
- **And** 行程仍可申请时，申请区恢复为内联申请表单

#### Scenario: 页面停留期间行程状态变化
- **Given** 用户打开一条可申请行程后停留在详情页
- **When** 该行程在此后变为已满员或已结束，用户仍提交申请
- **Then** 服务端拒绝该申请
- **And** 前端展示可读的不可申请原因，并刷新行程与申请状态
- **And** 刷新后不再展示申请表单
