# user-auth 增量规格（add-user-logout）

## MODIFIED Requirements

### Requirement: 会话校验与退出

系统 SHALL 用不透明随机 token 表示注册账号的登录会话，并在读取当前用户与退出时校验其有效性与过期时间；退出后该 token MUST NOT 再被接受。系统 SHALL 允许已进入系统的用户从顶栏身份菜单退出当前身份并返回身份门；退出入口 MUST 对注册账号与演示身份同样可见，且 MUST 可用键盘操作并有无障碍名称。注册账号退出 MUST 结束其服务端会话并清除本地会话与当前身份，演示身份退出 MUST 只清除本地身份且 MUST NOT 要求密码或发起认证请求。

#### Scenario: 用有效 token 读取当前用户
- **Given** 用户已登录并持有有效 token
- **When** 携带 `Authorization: Bearer <token>` 请求当前用户
- **Then** 返回该用户的昵称、学校、简介与兴趣

#### Scenario: 无效或过期 token
- **When** 请求未携带 token，或 token 不存在/已过期
- **Then** 系统返回 401 与 `SESSION_INVALID`

#### Scenario: 退出登录
- **Given** 用户以注册账号登录并持有有效 token
- **When** 用户从顶栏身份菜单点击「退出登录」
- **Then** 系统删除该会话并返回 204
- **And** 清除本地会话与当前身份并返回身份门，不保留上一账号的顶栏身份
- **And** 同一 token 再次请求当前用户返回 401

#### Scenario: 演示身份退出当前身份
- **Given** 用户以某个预设演示身份进入系统
- **When** 用户在顶栏身份菜单点击「退出登录」
- **Then** 系统清除当前演示身份并返回身份门
- **And** 不发起认证请求，也不要求密码
- **And** 身份门仍展示 3 个预设演示账户与既有登录 / 注册入口

#### Scenario: 退出入口对所有身份可见
- **Given** 用户已进入系统，且当前身份是注册账号或演示身份之一
- **When** 用户展开顶栏身份菜单
- **Then** 菜单展示「退出登录」入口
- **And** 该入口不因身份类型被隐藏
- **And** 该入口可键盘聚焦并触发

#### Scenario: 结束会话失败仍完成本地退出
- **Given** 注册账号持有有效会话
- **When** 用户退出登录且结束会话的请求失败
- **Then** 系统仍清除本地会话与当前身份并返回身份门
- **And** 系统可以提示会话可能仍有效，但不阻止退出

#### Scenario: 退出后刷新不恢复身份
- **Given** 用户刚退出当前身份并停留在身份门
- **When** 用户刷新页面
- **Then** 系统不恢复上一身份或上一会话
- **And** 页面停留在身份门，可重新选择演示身份或登录

#### Scenario: 退出后可重新进入
- **Given** 用户已退出当前身份并停留在身份门
- **When** 用户选择任一演示身份，或用注册账号登录
- **Then** 系统以所选身份进入首页
- **And** 首页与「我的」内容按新身份加载，不残留上一身份的浏览或操作归属

#### Scenario: 重复触发退出
- **Given** 用户已退出并停留在身份门
- **When** 用户重复触发退出动作
- **Then** 系统保持身份门状态且不报错
- **And** 不恢复上一身份

#### Scenario: 身份门不展示退出入口
- **Given** 用户尚未进入系统或刚退出并停留在身份门
- **When** 用户查看页面
- **Then** 系统不展示「退出登录」入口
