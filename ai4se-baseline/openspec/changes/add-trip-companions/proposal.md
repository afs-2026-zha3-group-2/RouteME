# 变更提案：add-trip-companions

- **需求：** REQ-003（`requirement-workspace/requirements/REQ-003-trip-companions.md`）
- **能力：** `trip-companions`（ADDED）｜ **迭代：** 2–3「发现与连接 + 沟通」｜ **规模：** L（场景最多，建议内部两阶段交付）

## 问题

REQ-002 建立了行程池，但用户之间还无法产生真实的同行连接。产品要验证第二个核心假设——**用户愿意基于具体路线申请同行**，并坚持「先有共同行程、再沟通」，避免沦为无条件陌生人私聊工具。本提案新增 `trip-companions` 能力：让用户按目的地/日期/兴趣发现相近行程并看到可解释的匹配原因，用一句说明申请同行、由发布者接受或拒绝，双方建立连接后进行基础文字沟通，并具备取消/退出/举报/隐私保护/安全提示等最低安全能力。

## 范围

**In scope（业务能力与页面）**

- 基础路线匹配（可解释规则）：目的地相同、日期相同/相差一天、共同兴趣累计加分；结果展示匹配原因文案（可选百分比）；时间不足时降级为「筛选 + 共同兴趣提示」，不展示误导性百分比。
- 同行申请：填写一句说明、提交、查看待处理/已接受/已拒绝/已取消、处理前取消。
- 申请规则：不能申请自己的行程、不能重复申请、已满员/已结束不能申请、只有发布者能处理申请。
- 接受后人数联动：接受申请后已加入人数增加，达计划人数上限时行程置为「已满员」并停止接受新申请。
- 我的旅行：分组展示我发布的、我申请的、已匹配的、已完成的、可分享体验的行程。
- 匹配后一对一文字沟通：文字消息 + 发送时间 + 消息列表，手动刷新或短轮询；仅已匹配者可进入；若阻断可降级为「已匹配用户的同行留言区」。
- 最低安全能力：取消申请、退出同行、举报入口、不公开电话/证件/精确住址、首次见面选择公共场所提示、重要行程告知亲友提示。

**Out of scope**

- 行程浏览/筛选/发布/详情（→ REQ-002）；游后分享与参考发布（→ REQ-004）。
- 复杂推荐算法、附近的人、滑卡匹配、无限私聊、实时位置、导航、紧急救援（→ P2/不做）。
- WebSocket 实时、语音/视频/图片聊天、已读回执、推送通知、实名认证、复杂信用体系（→ 明确不做）。

## 影响面（业务）

| 位置（能力 / 页面） | 改动 |
|---|---|
| `trip-companions` 能力 | 新增：匹配、申请、人数联动、我的旅行、聊天、安全 |
| `trip-plans` 行程状态（跨能力触点） | 接受申请达上限时触发行程状态由「招募中」流转为「已满员」；状态定义锚点仍为 REQ-002，本 change 仅触发流转，不重复定义状态机 |
| 同行申请页 / 我的旅行页 / 聊天页 | 新增业务页面 |
| 行程详情页 | 复用 REQ-002 的同行申请入口，承接申请与处理行为 |
