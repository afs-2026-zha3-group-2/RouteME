# 变更提案：add-growth-level

- **需求来源：** GitHub Issue [#44](https://github.com/afs-2026-zha3-group-2/RouteME/issues/44)「用户成长等级 LV1–LV5」（P1 / 迭代 3 / 3 点）｜ **需求条目：** `requirement-workspace/requirements/REQ-033-growth-level.md`（41 场景，blocking OQ 0，DoR BLOCKER 0）｜ **故事：** S34（编号四次顺延：REQ-029 / S30 → REQ-030 / S31 → REQ-033 / S34）
- **能力：** `user-growth`（ADDED）；只读消费 `trip-experiences`（体验首次创建 / 点赞）与 `admin-console`（举报成立）；`user-credit` 完全分离
- **规模：** M（2 张表 + 1 次迁移 + 3 处事件挂接 + 2 处读取扩字段 + 6 处展示面；无管理端）
- **规则：** `@rule:api-contract`、`@rule:java-patterns`、`@rule:web-coding-style`、`@rule:security-baseline`、`@rule:tdd-cycle`、`@rule:sdd-artifacts`；原型先行：`docs/prototype/prototype.html` + `styles.css`

## Why

RouteME 已有信用分这一独立体系（`user_credit_account` + `credit_ledger` + 五档 + 五个展示面），但它表达的是「可信 / 风险」：初始 80，只有扣分事件才变化，获赞只在信用侧按档位 +1。它无法表达「这个人是否持续发布真实体验、是否被社区认可」的正向成长。Issue #44 明确要求新增一套与信用分完全分离的成长等级：LV1–LV5、每 100 EXP 升一级、发布已完成行程的体验与获得点赞会增加经验、举报成立会扣经验，并且经验变化必须留流水、由后端统一计算。

当前缺少四块基础：

- 没有成长账户与经验流水，无法证明「经验加了多少、为什么加、能否回算」；
- 没有等级派生与展示，用户看不到自己的成长进度，其他用户也看不到等级；
- 没有防刷与每日上限，点赞 / 取消点赞 / 重复发布可以被用来无限刷经验；
- 没有与举报成立的联动，社区负向行为不会影响成长等级。

价值假设：给社区参与一条可见、可累计、与信用风险解耦的正向反馈链；同时保留可审计的流水与明确的防刷边界。

## What Changes

- **新增能力 `user-growth`（ADDED）**：成长账户、append-only 经验流水、LV1–LV5 等级派生、发布 / 点赞 / 举报三类事件结算、只读展示契约。
- **数据**：新增 `user_growth_account`（每用户 1 条总经验）与 `growth_exp_ledger`（append-only，含来源 / 实发值 / 前后快照 / 时间 / 关联对象 / 幂等键）；新增 1 次迁移，为存量用户建 0 EXP 账户；**不回填**历史发布 / 点赞 / 已处理举报；**不改** `user_credit_account` / `credit_ledger` / `app_users`。
- **等级规则**：LV1 0–99、LV2 100–199、LV3 200–299、LV4 300–399、LV5 400+；每 100 EXP 升一级；LV5 后继续累计经验、等级封顶；等级由当前总经验派生、不落库；扣经验后等级随经验回退。
- **发布经验**：首次创建「已完成行程」的体验 +10 EXP（配置项 `routeme.growth.publish-exp`，默认 10，可改，无管理端）；同一（行程, 作者）只发一次；编辑、重复提交、删除后重建不再发；未完成行程沿用既有发布资格拒绝。
- **点赞经验**：单篇体验每累计 10 个有效点赞 +5 EXP（10/20/30… 各一次），档位锁定；取消点赞不回滚，重新点赞不重复结算；作者自赞沿用既有拒绝；多篇体验各自分档。
- **每日上限**：正向经验（发布 + 点赞）每自然日（Asia/Shanghai）最多 +20；跨档按剩余额度截断（如 18/20 时 +5 只发 +2）；档位照常锁定、不次日补发；零实发也留流水；负向扣减不受上限限制。
- **举报扣经验**：所有 RESOLVED（成立）举报对被举报用户 −50 EXP，每份举报只扣一次，不受每日上限限制；经验最低 0（不足 50 时按实际扣，如 30 → 0）；等级随经验回退；上线前已成立举报不回填。
- **展示与可见性**：6 处展示面（个人主页、资料弹窗、详情发布者区、首页行程卡、申请处理页申请者行、详情同行者卡片）显示 `LVn`；本人额外可见当前经验与距下一级所需经验，LV5 显示已满级；他人只可见等级，不返回、不展示具体经验值；成长等级与信用分并列但文案可区分，不得称为信用等级或官方安全认证。
- **读取接口**：在既有个人主页响应与批量信用读取响应上追加只读成长字段（具体形状 P3 定）；不新增客户端修改经验 / 等级的写端点。
- **故事与登记**：`stories.md` / `stories/REQ-033-growth-level.story.md` / `registry.md` / `handoff.md` 登记 REQ-033 / S34 → `add-growth-level`。
- **契约与迁移**：`openapi.yaml` 升次版本（预计 0.30.0）；迁移 `V34`；基线 0.26.0 + V31（#29 已并入 main），P3 排他确认。

## Out of Scope

- 经验明细页、流水列表、排行榜、等级权益、徽章、证书。
- 通知 / 推送 / 邮件。
- 管理端调整经验、管理端成长视图、配置维护界面。
- 中文等级头衔命名（只用 `LVn`）。
- 存量回填（历史发布 / 历史点赞 / 已处理举报）。
- 等级影响信用分、限制账号、解锁功能。
- 「路线完成度」「信誉良好 / 警惕」等 #45 的履约指标（独立故事）。
- 改变点赞资格（受限 / 封禁用户点赞是否有效）——沿用现状，如需变更另开需求。
- 改变体验发布、点赞、取消点赞、举报处置的既有语义与状态机。

## 决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 与信用分的关系（D1） | 新增 `user-growth`，独立账户与账本；不读写信用表 | 信用分表达风险，成长等级表达参与；混表会破坏信用分的只读约束 |
| 等级规则（D2 / D15） | LV1–LV5，每 100 EXP 一级；扣经验后随总经验回退 | 等级 = f(总经验) 单一口径；不引入「历史最高等级」第二真相 |
| LV5 之后（D3） | 继续累计经验，等级封顶 | 不丢流水；展示 `400+` / 已满级 |
| 初始与回填（D4） | 所有人 LV1 / 0；不回填历史事件；迁移只建 0 账户 | 符合「初始经验值 0」；避免上线即升级 |
| 发布经验（D5） | 首次创建已完成行程体验 +10，配置化，按（行程, 作者）幂等 | 现有体验按（行程, 作者）唯一；编辑 / 删除重建不应重复发 |
| 点赞经验（D6） | 单篇体验分档锁定，10/20/30… 各 +5；取消不回滚 | 与既有信用获赞的「档位锁定」同构；防反复点赞刷经验 |
| 举报扣经验（D7） | 所有 RESOLVED 举报 −50，每份一次，最低 0，不受上限 | issue 原文「经核实的举报成立后扣除 50 点经验」；固定值不随违规类型变化 |
| 每日上限（D8） | 正向每自然日 +20（Asia/Shanghai）；按剩余额度截断；档位仍锁定 | 与信用 / 出行业务日一致；截断比丢弃更符合「最多 20」 |
| 流水（D9） | append-only，含来源 / 实发 / 前后快照 / 时间 / 关联 / 幂等 | 可审计、可回算；零实发也留痕用于锁定 |
| 计算与可见性（D10） | 后端统一计算；本人可见经验，他人只见等级 | issue 的技术边界；避免客户端改值；减少隐私暴露 |
| 展示面（D11） | 6 处：主页 / 弹窗 / 详情发布者 / 行程卡 / 申请者行 / 同行者卡片；只用 `LVn` | issue 的 3 个落点 + 信用分既有 5 面 + 同行者卡片 |
| 明确不做（D12） | 明细页 / 排行榜 / 通知 / 权益 / 管理端 / 中文头衔 | 保持切片最小，避免范围膨胀 |
| #29 关系（D13） | #29 已并入 main；在其「扣信用分」之后并列追加「扣成长经验」 | 不覆盖既有副作用，冲突点已消除 |
| 契约 / 迁移（D14） | P3 排他；落定 0.30.0 + V34 | 基线 0.26.0 + V31（#29 已并入 main） |

## 验收信号

1. 新用户与存量用户打开个人主页，成长信息均为 `LV1` / `0 EXP`，不出现空值或错误页；存量历史发布 / 点赞 / 举报不补发。
2. 99 → 100 EXP 时从 `LV1` 升到 `LV2`；399 → 400 时从 `LV4` 升到 `LV5`；400 之后继续累计经验但等级保持 `LV5`，展示 `400+` / 已满级。
3. 首次发布已完成行程的体验 +10 EXP；编辑、重复提交、删除后重建不再增加；未完成行程无法发布（沿用既有拒绝）。
4. 某篇体验第 10 个有效赞 +5 EXP，第 20 个再 +5；第 11–19 个不再增加；取消点赞不回滚，重新点赞不重复结算；自赞被拒绝。
5. 当日正向经验达到 20 后不再增加；18/20 时一笔 +5 只实发 +2；被截断的档位次日不补发；负向扣减不受上限限制。
6. 一份举报被判为 RESOLVED 后，被举报用户 −50 EXP；同一举报重复处理不重复扣；REJECTED 不扣；不足 50 时扣到 0，不出现负数；等级随经验回退。
7. 任意一次经验变化都有流水，满足 `exp_before + applied_delta = exp_after` 且 `exp_after ≥ 0`；账户总经验可由流水回算。
8. 客户端不存在直接设置经验或等级的写端点；经验只能由发布 / 点赞 / 举报事件触发。
9. 本人个人主页与资料弹窗可见 `LVn`、当前经验与距下一级所需经验；他人只能看到 `LVn`，不返回、不展示具体经验值。
10. 行程详情发布者区、首页行程卡、申请处理页申请者行、详情同行者卡片均显示 `LVn`；批量读取只返回等级。
11. 成长等级与信用分在同一展示面并列时文案可区分；成长等级不被称为信用分、信用等级或官方安全认证。
12. 双击 / 重试 / 并发点赞、举报处理或体验发布，至多结算一次；不出现双发、双扣或第二条同档流水。
13. `openspec validate add-growth-level --strict` 通过；既有信用分、体验发布 / 点赞、举报处置、行程与申请不回归。

## 残余风险

| 风险 | 处理 |
|---|---|
| 与 #29 同改 `AdminReportServiceImpl.resolve` | 两边各自追加副作用；合并时并列保留「扣信用分 + 扣成长经验」；P4 在合并后复验两个副作用 |
| 契约 / 迁移号撞号 | P3 按 main 当前头与 #29 合并顺序排他确认；若被抢占整体顺延并在 PR 记录 |
| 每日上限按 UTC 计算导致跨日错误 | 统一 `Asia/Shanghai`；用 UTC 16:00 边界场景断言 |
| 被截断的档位被误认为次日可补发 | 档位幂等记录先于上限判断；零实发也留流水；E2E / 单测覆盖 |
| 扣经验导致等级回退引发误解 | 用户已裁决「随经验回退」；展示层不承诺不掉级；验收信号 6 覆盖 |
| 6 个展示面视觉拥挤 / 与信用分混淆 | 原型先行；成长与信用文案、色阶区分；浏览器走查 1440 / 1024 / 768 / 390 × 浅 / 深色 |
| 「有效赞」是否包含受限 / 封禁用户 | 沿用既有 `experience_likes` 行口径；不改点赞资格；如需变更另开需求 |
| 体验发布事务失败导致经验回滚 | P3 明确事务边界：优先同事务（发布成功才发经验）；如需失败不阻断，必须写明理由与补偿 |
| 全量 E2E 既有债务 | P4 只跑本 change 与受影响回归，报告标注既有债务 |

## 规模与工作量

- **故事点：** 3（来自 issue #44）。
- **估算：** 约 2.5–3 人日（后端 1.5 / 前端 1 / 测试与文档 0.5）；不含 P3 原型与评审等待。
- **切片：** 单 change `add-growth-level`，单能力 `user-growth`（ADDED）；不拆。账户、流水、等级、三类事件与展示共用同一经验口径，拆开会产生不完整验收。
- **阶段：** P1 提案 + Delta 草稿 → P2 G1 → P3 原型 + ATDD / design / tasks → P4 实现与验证 → P5 归档（按发起人指示再定是否执行）。
