# user-profiles 增量规格

## ADDED Requirements

### Requirement: 从行程卡片与详情页查看发布者公开资料

系统 SHALL 在行程卡片的发布者区域与行程详情页的发布者卡片提供资料入口。点击发布者后，系统 MUST 在当前页面打开该发布者的公开资料弹窗；从卡片入口点击发布者时 MUST NOT 触发进入行程详情页。该入口 MUST 对任意已进入的用户可用（演示账户或注册账户），包括发布者本人。

#### Scenario: 从行程卡片打开资料

- **Given** 浏览者在旅行灵感首页看到一条由他人发布的行程
- **When** 浏览者点击卡片上的发布者区域
- **Then** 系统打开该发布者的公开资料弹窗
- **And** 页面不进入该行程详情页

#### Scenario: 从行程详情页打开资料

- **Given** 浏览者在某条行程的详情页
- **When** 浏览者点击发布者卡片
- **Then** 系统打开该发布者的公开资料弹窗

#### Scenario: 查看自己的资料

- **Given** 行程的发布者就是当前用户
- **When** 当前用户点击自己的发布者区域或发布者卡片
- **Then** 系统打开公开资料弹窗
- **And** 弹窗展示「这是你」标识

#### Scenario: 关闭资料弹窗

- **Given** 公开资料弹窗已打开
- **When** 用户关闭弹窗
- **Then** 系统回到原页面
- **And** 不改变行程列表或详情页的现有状态

### Requirement: 资料弹窗展示公开资料与共同兴趣

系统 SHALL 在公开资料弹窗展示头像、昵称、身份/年级与专业或行业（MBTI 选填）、加入时间、简介与兴趣标签。身份/专业字段 MUST 同时支持学生与非学生形态，例如「大三 · 软件工程专业 · ENTJ」与「上班族 · 互联网行业 · INFP」；MBTI 缺省时 MUST NOT 出现空占位或多余分隔符。加入时间 MUST 与用户实际加入时间一致。当发布者与当前浏览者存在共同兴趣时，系统 MUST 展示共同兴趣提示；没有共同兴趣时 MUST NOT 展示该提示；当发布者为当前用户本人时 MUST NOT 展示共同兴趣提示。系统 MUST 同时展示隐私说明，说明平台仅展示昵称、头像、身份/专业、加入时间、简介与旅行兴趣，且电话、证件、精确住址与实时位置不会公开。

#### Scenario: 展示学生形态的身份与专业

- **Given** 发布者的身份/专业字段为「大三 · 软件工程专业 · ENTJ」
- **When** 资料弹窗展示
- **Then** 系统完整展示该字段
- **And** 同时展示头像、昵称、加入时间、简介、兴趣标签与隐私说明

#### Scenario: 展示非学生形态的身份与专业

- **Given** 发布者的身份/专业字段为「上班族 · 互联网行业 · INFP」
- **When** 资料弹窗展示
- **Then** 系统完整展示该字段
- **And** 不把该字段表述为学校名称

#### Scenario: 字段缺省时不显示空占位

- **Given** 发布者的身份/专业字段不含 MBTI，或只有身份与专业两段
- **When** 资料弹窗展示
- **Then** 系统展示已有的两段内容
- **And** 不出现空的 MBTI 占位或多余分隔符

#### Scenario: 存在共同兴趣

- **Given** 发布者与当前浏览者有至少一个相同的兴趣标签
- **When** 资料弹窗展示兴趣标签
- **Then** 系统展示共同兴趣提示
- **And** 提示列出双方共同的兴趣

#### Scenario: 没有共同兴趣

- **Given** 发布者与当前浏览者没有相同的兴趣标签
- **When** 资料弹窗展示兴趣标签
- **Then** 系统不展示共同兴趣提示

#### Scenario: 自我查看不展示共同兴趣

- **Given** 发布者就是当前用户
- **When** 资料弹窗展示兴趣标签
- **Then** 系统不展示共同兴趣提示

#### Scenario: 加入时间与隐私说明

- **Given** 任意发布者的公开资料弹窗
- **When** 用户查看加入时间与隐私说明
- **Then** 加入时间与用户实际加入时间一致
- **And** 隐私说明包含平台展示字段与不公开字段的说明

### Requirement: 公开资料的四项旅行统计口径

系统 SHALL 在公开资料弹窗展示四项统计：发布行程、已完成、参与同行、游后分享。发布行程 MUST 统计该用户发布的行程数；当前 `trip-plans` 能力没有「已取消」状态，若未来引入取消状态，已取消行程 MUST NOT 计入发布行程。已完成 MUST 统计该用户发布的已结束行程数；参与同行 MUST 统计该用户被接受的同行申请数；游后分享 MUST 统计该用户发布的游后体验数。统计结果 MUST 与对应行程、申请与体验的当前状态一致。

#### Scenario: 展示可核对的四项统计

- **Given** 发布者已有发布行程、已结束行程、被接受的申请与已发布体验
- **When** 资料弹窗展示
- **Then** 四项统计分别展示对应数量
- **And** 数量与行程、申请与体验的当前状态一致

#### Scenario: 不计入不符合口径的数据

- **Given** 发布者有未被接受的申请或未发布的体验
- **When** 资料弹窗展示统计
- **Then** 未被接受的申请不计入参与同行
- **And** 未发布的体验不计入游后分享

#### Scenario: 新用户统计为零

- **Given** 发布者还没有任何行程、被接受的申请与体验
- **When** 资料弹窗展示
- **Then** 四项统计均展示为 0

### Requirement: 资料读取失败与用户不存在

系统 SHALL 在发布者用户不存在或公开资料读取失败时给出可理解的失败提示。此时系统 MUST NOT 展示不完整、过期或其他用户的资料。

#### Scenario: 发布者用户不存在

- **Given** 资料入口指向的用户已不存在
- **When** 用户尝试打开资料弹窗
- **Then** 系统展示用户不存在的提示
- **And** 不展示任何用户资料

#### Scenario: 资料读取失败

- **Given** 公开资料读取发生失败
- **When** 用户尝试打开资料弹窗
- **Then** 系统展示读取失败提示
- **And** 不展示不完整或过期的资料

### Requirement: 公开资料的隐私边界

系统 MUST NOT 在公开资料弹窗展示电话、证件、精确住址、学校门牌或实时位置。系统 MUST NOT 展示用户名、密码散列、会话令牌或其他账户凭据。资料弹窗 MUST NOT 提供举报用户按钮或举报提交入口；本能力 MUST NOT 移除或改变既有聊天与行程场景中的举报能力。

#### Scenario: 隐私字段不出现在资料弹窗

- **Given** 任意发布者的公开资料弹窗
- **When** 用户查看弹窗全部内容
- **Then** 弹窗不包含电话、证件、精确住址、学校门牌或实时位置

#### Scenario: 账户凭据不出现在资料弹窗

- **Given** 发布者是演示账户或注册账户
- **When** 用户查看公开资料弹窗
- **Then** 弹窗不包含用户名、密码散列、会话令牌或其他账户凭据

#### Scenario: 资料弹窗不提供举报入口

- **Given** 任意发布者的公开资料弹窗
- **When** 用户查看弹窗底部操作
- **Then** 弹窗不包含举报用户按钮或举报提交入口
- **And** 底部仅提供关闭操作

#### Scenario: 既有举报能力不受影响

- **Given** 聊天或行程场景已有举报入口
- **When** 本能力上线后用户进入这些场景
- **Then** 既有举报入口仍可正常使用
