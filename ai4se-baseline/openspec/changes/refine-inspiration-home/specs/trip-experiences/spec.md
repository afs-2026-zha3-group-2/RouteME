# trip-experiences 增量规格

## MODIFIED Requirements

### Requirement: 灵感首页的旅行体验视图

系统 SHALL 在灵感首页提供「招募中的行程」与「旅行体验」两个视图切换，并 MUST 默认进入「招募中的行程」；「旅行体验」视图 MUST 按页展示已发布体验所属的行程标题、目的地、作者、强度、感受摘要与来源行程「已结束」标识，支持关键词、目的地与兴趣筛选，并按发布时间倒序排列；来源行程「已结束」MUST 以文字或图形表达，不得仅以颜色表达；没有结果时 MUST 给出空态提示与「去发布行程」引导；数据未返回时 MUST 展示骨架或加载态，且不得残留上一视图的卡片。

#### Scenario: 切换到旅行体验视图
- **Given** 首页已有已发布体验
- **When** 用户从默认的「招募中的行程」切换到「旅行体验」
- **Then** 列表展示体验卡而不是行程卡
- **And** 展示体验数量
- **And** 当前视图具有可访问的选中标识

#### Scenario: 体验卡标识来源行程已结束
- **Given** 一条体验来自已结束的行程
- **When** 用户查看「旅行体验」视图的体验卡
- **Then** 卡片展示来源行程标题、目的地与「已结束」标识
- **And** 该标识不只依赖颜色表达

#### Scenario: 体验筛选与倒序
- **Given** 存在多条不同目的地 / 标签的体验
- **When** 用户按关键词、目的地或兴趣筛选
- **Then** 只展示命中的体验
- **And** 结果按发布时间从新到旧排列

#### Scenario: 体验分页与筛选并用
- **Given** 用户已设置关键词、目的地或兴趣条件
- **When** 用户翻页
- **Then** `total` 反映筛选后的命中数
- **And** 每页条目仍是筛选后的子集

#### Scenario: 筛选变化重置体验分页
- **Given** 用户停在体验视图的第 2 页
- **When** 用户修改任一筛选条件
- **Then** 体验列表从第 1 页重新查询

#### Scenario: 体验空态
- **Given** 当前筛选条件下没有体验
- **When** 用户查看「旅行体验」视图
- **Then** 系统展示空态提示与「去发布行程」引导
- **And** 提示可通过完成旅行并分享来产生内容

#### Scenario: 体验视图加载态
- **Given** 体验数据尚未返回
- **When** 用户查看「旅行体验」视图
- **Then** 系统展示骨架或加载态
- **And** 不展示上一视图的行程卡
