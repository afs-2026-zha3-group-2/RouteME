# trip-plans 增量规格

## MODIFIED Requirements

### Requirement: 浏览未结束的旅行计划

系统 SHALL 在旅行灵感首页以「招募中的行程」为默认视图，按页列出未结束（招募中或已满员）的公开行程，并以卡片展示理解一条行程所需的信息；已结束与已取消行程 MUST NOT 出现在该视图。卡片状态 MUST 以文字展示，且 MUST 提供至少一种非颜色信号，使用户可区分招募中与已满员，不得仅以颜色表达状态。

#### Scenario: 默认视图为招募中的行程
- **Given** 用户已进入旅行灵感首页
- **When** 页面加载完成
- **Then** 默认视图为「招募中的行程」
- **And** 视图切换器提供「招募中的行程」与「旅行体验」两个选项
- **And** 当前视图具有可访问的选中标识

#### Scenario: 默认列表与卡片信息
- **Given** 数据中存在多条未结束的公开行程
- **When** 用户进入旅行灵感首页
- **Then** 系统以卡片列出当前页的行程
- **And** 每张卡片展示标题、目的地、起止日期、途经点摘要、兴趣标签、发布者昵称、已加入人数 / 计划人数与状态文字
- **And** 状态不以颜色作为唯一表达方式

#### Scenario: 已满员与招募中可区分
- **Given** 同一列表中同时存在已满员与招募中的行程
- **When** 用户浏览卡片
- **Then** 两者都以文字展示当前状态
- **And** 至少有一种非颜色信号可区分两者（例如状态徽标形状、图标或人数进度满格）
- **And** 用户据此可判断该行程是否仍可加入

#### Scenario: 已结束与已取消行程不出现在默认视图
- **Given** 数据中存在已结束或已取消的行程
- **When** 用户查看旅行灵感首页的默认「招募中的行程」视图
- **Then** 这些行程不出现在该视图中
- **And** 已结束行程的游后分享按 `trip-experiences` 的「旅行体验」视图展示

#### Scenario: 加载中展示骨架
- **Given** 首页数据尚未返回
- **When** 页面正在加载
- **Then** 当前视图展示骨架或加载态，而不是空白页或上一视图的旧卡片

#### Scenario: 无结果时展示空状态并保留条件
- **Given** 用户已设置筛选条件
- **When** 没有任何行程满足条件
- **Then** 系统展示可读的空状态与「去发布行程」引导
- **And** 已设置的筛选条件仍然可见、可清除

#### Scenario: 分页浏览
- **Given** 未结束行程总数大于一页容量
- **When** 用户查看首页列表
- **Then** 只渲染当前页的卡片，并展示总条数与总页数
- **And** 用户可切换到上一页、下一页或指定页码
- **And** 翻页后列表回到页面顶部

#### Scenario: 筛选变化重置分页
- **Given** 用户停在第 3 页
- **When** 用户修改关键词、目的地、日期区间、兴趣或排序
- **Then** 列表从第 1 页重新查询
- **And** 已应用条件的摘要仍然可见
