# 变更提案：refine-inspiration-home

- **需求来源：** `docs/prototype/stories.html` S03 ｜ **需求条目：** `requirement-workspace/requirements/REQ-005-inspiration-home.md`
- **能力：** `trip-plans`（MODIFIED）、`trip-experiences`（MODIFIED）
- **规模：** S（前端页面 / 文案 / 状态展示为主；无后端、接口契约、数据库或迁移变更）
- **规则：** `@rule:web-coding-style`、`@rule:sdd-artifacts`

## 问题

灵感首页已经是 RouteME 双视图浏览入口，但和 S03 的验收口径仍有四个可见缺口：

1. 默认行程视图的标签是「旅行计划」，而故事要求默认进入「招募中的行程」。
2. 「旅行体验」视图的空态只有说明文字，没有故事要求的「去发布行程」引导。
3. 体验卡只显示来源行程标题与目的地，没有显式表达来源行程「已结束」。
4. 已满员虽已有状态文字，但「已满员 / 已结束与招募中可区分，且不能只靠颜色」还没有被写成可检查的展示契约。

S03 是迭代 1 的首页浏览故事，价值在于让还没有明确目的地的学生先看到足够完整的公开行程与真实体验，再决定申请同行或参考发布。本变更只收敛这些页面级缺口，不重做首页，也不改变行程 / 体验的业务规则。

## 范围

**In scope**

- 首页默认视图命名为「招募中的行程」；保留「旅行体验」切换。
- 行程卡展示标题、目的地、起止日期、路线摘要、标签、发布者昵称、已加入 / 计划人数、状态文字；状态不以颜色作为唯一表达。
- 已满员与招募中在列表中以「状态文字 + 至少一种非颜色信号」区分。
- 体验卡显式标识来源行程「已结束」（文字或图形，不只颜色）。
- 两个视图的空状态都提供「去发布行程」引导；加载中展示骨架或加载态。
- 保留既有搜索、目的地 / 日期 / 兴趣筛选、排序与分页。
- 为 `trip-plans` 与 `trip-experiences` 各写一份 MODIFIED delta spec。

**Out of scope**

- 新增首页聚合接口、数据库表 / 字段 / 迁移、状态机或业务规则变更。
- 发布行程、行程详情、同行申请、聊天、游后分享发布的功能改动。
- 体验视图补齐日期 / 排序筛选；个性化推荐、热门榜单、AI 灵感、图片上传、地图导航。
- 可深链的单视图 URL（本故事只要求同页视图切换）。

## 决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 数据来源 | 复用 `GET /api/trips` 与 `GET /api/experiences` | 两个契约已存在且分页形状一致；新增聚合端点会引入重复数据源，超出 S03 需要 |
| 视图形态 | 同一首页内的客户端视图状态 | 故事只说「切换视图」；无深链要求，保持现有 Segmented 交互 |
| 默认列表口径 | 只含招募中 / 已满员 | 与 `trip-plans` Living Spec 一致；已结束不混回默认列表 |
| 「已结束」表达 | 体验卡来源标识 + 详情页状态文字 | 已结束行程不在默认列表；体验卡是首页内可比较「已结束 vs 招募中」的展示位 |
| 状态可辨识 | 状态文字必选 + 至少一种非颜色信号 | 满足「不能只靠颜色表达」，不把可访问性退化成配色问题 |
| 变更粒度 | 一个 change，两个 MODIFIED capability | 同一页面的垂直切片；拆成两个 change 任一半都无法单独通过「切换后内容随之变化」验收 |

## 验收信号

1. 打开首页默认显示「招募中的行程」，列表只出现未结束行程；已结束 / 已取消不出现。
2. 6 条演示数据下，每张未结束行程卡展示标题、目的地、起止日期、路线摘要、标签、发布者昵称、已加入 / 计划人数、状态文字。
3. 已满员与招募中同时存在时，两者均有状态文字，并至少有一种非颜色信号可区分。
4. 切到「旅行体验」后列表由体验卡组成，展示来源行程标题、目的地、作者、强度、感受摘要与「已结束」标识。
5. 两个视图在无结果时都展示空状态与「去发布行程」引导；招募视图保留筛选条件可清除。
6. 两个视图在加载时展示骨架或加载态，不显示上一视图的旧卡片。
7. 既有搜索、筛选、排序、分页行为不回归；`npm run build`、`npm test` 全绿，相关 E2E 通过。
8. `openspec/changes/refine-inspiration-home/specs/` 下两份 MODIFIED delta 与提案一致。

## 残余风险

| 风险 | 处理 |
|---|---|
| 默认标签文案变更影响既有 E2E / 文案断言 | 实现时同步更新 `trips.spec.ts` 与相关组件测试；「旅行体验」保持不变 |
| 非颜色信号若实现为颜色深浅，仍可能被判「只靠颜色」 | delta spec 明确「状态文字 + 至少一种非颜色信号」双条件；评审按此检查 |
| 体验视图现有日期 / 排序筛选未生效 | 本变更明确 out of scope；不顺手扩大筛选语义 |
| 体验卡补「已结束」可能与强度徽标视觉冲突 | 设计阶段选择独立位置（来源行）与语义样式，不挤占强度标签 |
