# trip-companions 增量规格（refine-safety-report）

## REMOVED Requirements

### Requirement: 我的旅行聚合与最低安全能力

**Reason**: 用户裁决 D5 移除详情页三条安全提示与聊天页一行提示，旧需求块以提示为核心；且 `openspec` 不允许 MODIFIED 块删除既有场景名，故整块移除，由「同行举报入口与回执」重建。

**Migration**: 「我的旅行」两个场景与举报、回执、失败重试、隐私红线原样迁入新需求块；基线场景「安全提示常驻」不再保留（D5 有意删除，非漏迁移）。

## ADDED Requirements

### Requirement: 同行举报入口与回执

系统 SHALL 提供「我的旅行」分区视图（我发布的、我申请的、已匹配的、已完成的），并在有待处理申请时给出可点击提醒。系统 MUST 在他人行程详情页与聊天页的页头提供举报入口（分别以行程、用户为对象），提交后 MUST 返回「已收到，我们会处理」的明确回执。本人发布的行程 MUST NOT 出现以该行程为对象的举报入口。详情页与聊天页 MUST NOT 展示安全提示文案。举报入口 MUST NOT 仅靠颜色或图标表达；系统 MUST NOT 采集或展示电话、证件与精确住址；MVP 不要求举报处置闭环，且不向被举报方透露举报人身份。

#### Scenario: 分区展示我的旅行
- **Given** 用户既发布过行程也提交过申请
- **When** 用户进入我的旅行
- **Then** 系统按我发布的、我申请的、已匹配的、已完成的四个分区展示
- **And** 每个条目可跳转到对应行程或申请

#### Scenario: 待处理申请提醒
- **Given** 用户发布的行程存在待处理申请
- **When** 用户进入我的旅行
- **Then** 系统显示待处理数量与可点击入口

#### Scenario: 详情页页头举报入口
- **Given** 用户正在查看他人发布的行程详情
- **When** 页面加载完成
- **Then** 页头在状态标签同一行右侧展示文本按钮「举报这条行程」
- **And** 页面不展示安全提示区
- **And** 入口不只靠颜色或图标表达，键盘与读屏可达

#### Scenario: 聊天页页头举报入口
- **Given** 已匹配用户进入与该行程的聊天页（包含行程已结束的只读聊天）
- **When** 页面加载完成
- **Then** 页头在头像对侧展示文本按钮「举报这位用户」
- **And** 页面不展示安全提示条
- **And** 入口不只靠颜色或图标表达，键盘与读屏可达

#### Scenario: 举报弹窗内容
- **Given** 用户点击任一举报入口
- **When** 弹窗打开
- **Then** 弹窗标明举报对象（行程标题或对方昵称）、四类原因（骚扰或不当言行 / 虚假信息 / 安全风险 / 其他）与选填说明（200 字以内）
- **And** 弹窗展示「我们不会向对方透露你的身份」与「如果你正处于危险中，请先联系当地警方或学校保卫处。平台举报不能替代紧急求助。」

#### Scenario: 本人行程不出现举报入口
- **Given** 用户打开自己发布的行程详情
- **When** 用户查看页头
- **Then** 不出现「举报这条行程」入口
- **And** 页面不展示安全提示区

#### Scenario: 提交举报并收到回执
- **Given** 用户在举报弹窗中已选定原因（可填写不超过 200 字的说明）
- **When** 用户提交举报
- **Then** 系统记录该举报并返回已接收
- **And** 弹窗进入回执态并展示「已收到，我们会处理」
- **And** 关闭弹窗只结束回执展示，不改变行程、申请或聊天状态，MVP 不要求处置闭环，也不向被举报方透露举报人身份

#### Scenario: 提交失败可读且可重试
- **Given** 网络或服务端错误
- **When** 用户提交举报
- **Then** 弹窗展示可读的失败提示，并保留已选原因与已填说明
- **And** 重试成功后仍进入回执态，且不出现重复回执或多条可见记录

#### Scenario: 举报弹窗不展示隐私字段
- **Given** 用户打开举报弹窗
- **When** 阅读全部文案
- **Then** 不出现电话、证件、精确住址等隐私字段的采集或展示
