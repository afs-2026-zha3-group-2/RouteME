# 变更提案：refine-safety-report

- **需求来源：** 用户指令「作为与陌生人同行的学生，我希望在详情页和聊天页都能立刻找到举报入口，以便遇到不适时马上求助」+ 原型故事 S14 rev2「举报入口与回执」+ 用户裁决 D5 ｜ **需求条目：** `requirement-workspace/requirements/REQ-012-safety-report.md`（rev2）
- **能力：** `trip-companions`（REMOVED + ADDED）
- **规模：** S（两个既有页面的入口增量 + 弹窗文案修正；无后端、契约、迁移变更）
- **规则：** `@rule:spec-first`、`@rule:sdd-artifacts`、`@rule:web-coding-style`、`@rule:pii-scrubbing`；视觉基准：`openspec/changes/refine-safety-report/preview/safety-report.html`（B · 页头右上）+ `docs/prototype/ui.js` `reportModal()`
- **修订记录：** rev1（2026-11-16）保留三条提示并把入口留在安全区底部；rev2（2026-11-16）依裁决 D5 移除全部提示、入口提到页头右上，Delta 改 REMOVED + ADDED。
- **编号说明（2026-11-16）：** 起草时按当时序号定为 REQ-011；同日 `main` 已将 S15 结束行程登记为 REQ-011（`add-trip-completion`），按「后到者顺延」改为 **REQ-012**。意图 / Ready 条目、`stories.md`、`registry.md`、`handoff.md`、`deep-dive.md` / `impact-brief.md` 增补已同步改号。

## Why

`add-trip-companions` 已把举报接到详情页与聊天页，但入口埋在整段安全提示的底部：学生要读完一段说明才看到一个按钮；本人发布的行程上也能举报自己；回执仍是「举报已收到，我们会记录处理。」，与故事 AC 的「已收到，我们会处理」不一致；弹窗缺少「不会向对方透露你的身份」与「平台举报不能替代紧急求助」两句边界说明。遇到不适时，用户需要的是一个**位置稳定、一眼可见的求助入口**和一句**确定被收到的回执**。裁决 D5 进一步决定两条安全提示下线，因此入口不能再依附于提示区，必须独立占据页头。

## What Changes

- `trip-companions`：他人行程详情页页头与聊天页页头各提供举报入口（分别以行程、用户为对象）；详情页 / 聊天页不再渲染安全提示；弹窗补身份保密与紧急求助说明；回执改为「已收到，我们会处理」；提交失败可读且可重试；弹窗不展示隐私字段。
- `trip-plans`：只读消费既有「集合」事实行的 `meeting_area` 与行程状态，不改字段与状态推导。
- 契约 / 后端 / 迁移：不变（复用 `POST /api/reports`、四值 `reason`、`note ≤200`；保留 `ReportControllerTest` 回归）。
- 前端 / 测试：`ReportModal`、`TripDetailPage`、`ChatPage`、`tripMessages`、`styles.css`；`SafetyNote` 从详情页 / 聊天页下线，仅评估体验发布页形态；同步相关单测 / E2E。

## 问题

`add-trip-companions` 已归档并进入 Living Spec：`ReportModal` 已能提交 `POST /api/reports` 并显示回执，后端只记录不处置，电话 / 证件 / 精确住址从未采集。但 S14 rev2 的验收口径与现状有四处错位：

- 举报入口位于安全区底部、提示文案之后，**可发现性差**；聊天页同样在输入框下方；
- 本人发布的行程详情**也能看到「举报这条行程」**；
- 回执文案是「举报已收到，我们会记录处理。」，而故事 AC 要求「已收到，我们会处理」；
- 举报弹窗只有举报对象 + 原因 + 说明，缺少「我们不会向对方透露你的身份」与「平台举报不能替代紧急求助」两句边界说明。

另据裁决 D5：详情页三条安全提示与聊天页一行提示**整块移除**，因此本 change 的展示面收敛为「两个页头入口 + 一个弹窗」。

## 范围

**In scope**

1. 他人行程详情页页头右上（与状态标签同一行）渲染「举报这条行程」；窄屏换行到标题下方，不得隐藏。
2. 聊天页页头右上（头像对侧）渲染「举报这位用户」，常驻（含已结束只读聊天）。
3. 详情页与聊天页**不再渲染安全提示**：三条列表、聊天页一行文本及两套集合区域回退文案（「尚未填写，出发前请在聊天中确认」/「待确认」）一并下线。
4. 举报入口为文本按钮，不只靠颜色或图标表达；键盘可达、读屏可读。
5. 举报弹窗补充「我们不会向对方透露你的身份」与「如果你正处于危险中，请先联系当地警方或学校保卫处。平台举报不能替代紧急求助。」；标题随对象变化为「举报这条行程 / 举报这位用户」。
6. 提交成功进入回执态，文案固定为「已收到，我们会处理」；提交失败给出可读提示并保留已选原因与已填说明以便重试。
7. 体验发布页保留现有「发布前提醒」，不出现举报入口（回归守卫）。
8. 为 `trip-companions` 移除旧需求块「我的旅行聚合与最低安全能力」（含提示场景，MODIFIED 无法删场景名），新增「同行举报入口与回执」：保留 3 个基线场景（分区展示我的旅行、待处理申请提醒、提交举报并收到回执），移除「安全提示常驻」，新增 6 个。

**Out of scope**

- 举报后台工单、处置状态与时限、处理结果通知 / 回执查询、封禁、申诉。
- 重新引入安全提示、边界文案或帮助中心内容（D5 明确移除；如需要另开需求）。
- 举报原因词表扩容或按目标类型分表；`openapi.yaml` 版本变更；后端校验规则变更。
- 求助热线、紧急联系人、位置共享、行程分享链接、实名认证、信用体系。
- 资料弹窗（REQ-009）的举报按钮；体验发布页提示改版。
- 采集或展示电话、证件、精确住址等隐私字段。
- 后端端点、数据库迁移、状态机变更；行程 / 申请 / 聊天 / 体验业务规则。

## 决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 安全提示形态 | 详情页 / 聊天页全部移除 | 用户裁决 D5（取代 D1）；页面只保留求助入口，边界文案不在本页承载 |
| 举报入口位置 | 页头右上（详情页与状态标签同行、聊天页与头像对侧） | 用户裁决 D5；位置稳定、不随内容长度下沉，窄屏可换行 |
| 举报原因词表 | 沿用现有四类 | 用户裁决 D2；分目标词表需扩枚举、升契约与后端校验 |
| 本人行程的举报入口 | 隐藏 | 用户裁决 D3；自己举报自己没有业务意义 |
| 回执文案 | 「已收到，我们会处理」 | 故事 AC 原文；由前端文案决定，不动后端 |
| 身份保密与紧急求助说明 | 写入举报弹窗 | 学生需要知道举报不会被对方知道，以及平台举报不是紧急求助 |
| 后端 / 契约 | 不改 | 举报记录、四值原因与回执契约已存在，本需求只改展示 |
| capability 粒度 | 单一 `trip-companions`，REMOVED + ADDED | 旧需求块含提示场景，校验器禁止 MODIFIED 丢弃场景名；整块重建让删除在归档 diff 中可见 |

## 验收信号

1. 打开他人行程详情，页头（状态标签同行右侧）出现可点的「举报这条行程」；同一页面找不到安全提示区。
2. 进入与该行程的聊天（含已结束只读聊天），页头（头像对侧）出现「举报这位用户」；页面没有提示条。
3. 打开弹窗可见举报对象、四类原因、选填说明、身份保密说明与紧急求助说明；标题随对象变化。
4. 选定原因并提交后，弹窗进入回执态并显示「已收到，我们会处理」；关闭弹窗只结束回执展示，不改变行程、申请或聊天状态。
5. 自己发布的行程详情不显示「举报这条行程」，也不显示安全提示区；其余功能照常。
6. 提交失败时展示可读失败提示且保留已选原因与已填说明；重试成功后同样进入回执态。
7. 举报弹窗不出现电话、证件、精确住址等隐私字段的采集或展示。
8. `openspec validate refine-safety-report --strict` 通过；前端构建与单测、后端 `ReportControllerTest` 回归、相关 E2E 全绿。

## 残余风险

| 风险 | 处理 |
|---|---|
| 回执文案变更影响既有 E2E | `companions.spec.ts` L136 断言旧文案「举报已收到，我们会记录处理。」，需同步改为「已收到，我们会处理」；L137 依赖 `.ant-modal-footer .ant-btn-primary`，回执态唯一按钮需确认为 primary |
| 体验发布页仍需要「发布前提醒」 | `SafetyNote` 不能当死代码删除；P3 明确保留形态或改为该页局部提示，P4 diff 核对 |
| 页头入口在窄屏与长标题下被挤压 | 入口保持文本按钮并允许换行；390 / 768 / 1440 三档验证不溢出、不退回纯图标 |
| 本人行程既无提示也无入口 | D5 的已知结果：发布者页面不再出现安全相关内容；如需补回，另开需求（已在 REQ-012 §8 记为 non-blocking） |
| 提示移除后学生缺少边界提醒 | 产品风险由 D5 接受；故事 / 需求已同步，避免出现「实现违反 AC」 |
| 举报原因词表与原型不一致 | 用户裁决 D2 以现有四类为准；分目标词表记为后续候选（non-blocking） |
| E2E 未纳入 CI | 与既有 change 相同：本地执行相关 spec，CI 以构建与单测为准；债务归测试 owner |
| 阶段提交与发布时机 | P1 / P2 按用户指示只本地提交、不 push；提交时机遵循 `@rule:git-commit-conventions`，发布偏离在交付说明记录 |
