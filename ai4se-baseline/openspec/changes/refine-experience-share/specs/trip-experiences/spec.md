# trip-experiences 增量规格（refine-experience-share）

## MODIFIED Requirements

### Requirement: 对已结束且参加过的行程发布游后体验

系统 SHALL 仅允许「发布者或已接受同行者」对已结束的行程发布游后体验；行程未结束（招募中、已满员或旅行中）、用户未参加或行程不存在时 MUST 拒绝，且拒绝 MUST 由服务端执行，不只依赖前端隐藏入口。前端 MUST 区分两种不可用原因：行程未结束时提示「行程结束后才能发表体验」并给出当前状态；已结束但用户既非发布者也非已接受同行者时提示「只有参加过的同行者才能发表体验」。两种情况下 MUST NOT 渲染发布表单或提交按钮。同一用户对同一行程只有一条体验，再次提交 MUST 视为修改而非新增。

#### Scenario: 具备资格时发布体验
- **Given** 一条已结束且当前用户是发布者或已接受同行者的行程
- **When** 用户填写真实感受、选择路线强度、填写一条建议并发布
- **Then** 系统保存该体验
- **And** 其他用户可在原计划详情页与灵感首页看到它

#### Scenario: 行程未结束时拒绝分享
- **Given** 一条仍在招募中、已满员或旅行中的行程
- **When** 用户尝试发布游后体验
- **Then** 系统拒绝并提示「行程结束后才能发表体验」，同时给出当前行程状态
- **And** 不生成体验记录，分享页不渲染发布表单

#### Scenario: 未参加行程时拒绝分享
- **Given** 一条已结束但当前用户既不是发布者也不是已接受同行者的行程
- **When** 用户尝试发布游后体验
- **Then** 系统拒绝并提示「只有参加过的同行者才能发表体验」
- **And** 不生成体验记录，分享页不渲染发布表单

#### Scenario: 发布者也可以分享
- **Given** 一条已结束且当前用户是发布者的行程
- **When** 用户发布游后体验
- **Then** 系统允许发布
- **And** 该体验与其他参加者的体验并列展示

#### Scenario: 再次提交即修改
- **Given** 用户已对该行程发布过体验
- **When** 用户修改内容后再次提交
- **Then** 系统更新原体验而不是新增一条
- **And** 原行程的体验条数不变，首页与详情页展示最新内容

### Requirement: 游后体验的内容口径与纯文字降级

系统 SHALL 要求体验包含真实感受（去除首尾空白后 10–400 字）、路线强度（轻松/适中/较累 三选一）与一条给后来者的建议（必填，≤120 字）。图片上传 MUST NOT 作为发布前提；体验 MUST 以纯文字展示，并由系统自带的目的地色调封面承载视觉，不因缺少图片而出现空白占位或阻断分享。

#### Scenario: 内容不满足口径时拒绝
- **Given** 用户正在填写游后体验
- **When** 感受少于 10 字或超过 400 字、未选择强度、或建议为空/超过 120 字
- **Then** 系统拒绝发布并指出需要修正的字段
- **And** 已填写内容不丢失

#### Scenario: 以三档强度表达体感
- **Given** 用户填写完感受与建议
- **When** 用户选择「轻松」「适中」或「较累」之一并发布
- **Then** 体验按所选强度展示强度标签
- **And** 展示文案与所选档位一致

#### Scenario: 无图片也能发布并展示内置封面
- **Given** 图片上传不在本迭代范围内
- **When** 用户只填写文字内容并发布
- **Then** 系统保存纯文字体验
- **And** 灵感首页的体验卡展示按目的地生成的固定色调封面条与目的地名，而不是空白占位

### Requirement: 我的旅行分享入口与分享边界

系统 SHALL 在「我的旅行」的已完成分组标识每条行程是否已分享，并提供发表或修改体验的入口。游后分享页 MUST 展示本次行程概览（内置封面、标题、目的地、日期与星期、同行人数与行程状态），MUST 以文本列表说明体验去向（原行程详情页、灵感首页「旅行体验」、可被「参考此行程发布」），并 MUST 常驻提示不写入同行者的电话、学校班级与住宿地址，且只写真实走过的部分、未走到的注明。去向与边界提示 MUST NOT 仅靠颜色或图标表达，也不阻塞发布；页面 MUST NOT 采集或展示电话、证件与精确住址。

游后分享页 MUST 采用原型的信息架构：返回入口、页头标题与副标题、行程概览、主列三个输入分组（真实感受 / 路线强度 / 给后来者的一条建议）与侧栏两个说明分组（体验去向 / 分享边界）；路线强度 MUST 以三张可选卡片呈现，且保留单选控件的键盘与读屏语义；主按钮与取消入口 MUST 位于「给后来者的一条建议」分组内。视口宽度不大于 900px 时，双栏 MUST 收为单列且页面不出现横向滚动。

#### Scenario: 已完成分组区分已分享与未分享
- **Given** 用户有已结束的行程
- **When** 用户查看「我的旅行」的已完成分组
- **Then** 已分享的行程显示「修改我的体验」
- **And** 未分享的行程显示「发表游后体验」

#### Scenario: 分享页面提示隐私边界
- **Given** 用户进入游后分享页面
- **When** 页面展示
- **Then** 可见不写入电话、学校班级与住宿地址的提示
- **And** 同时可见「只写真实走过的部分，未走到的注明」的提示
- **And** 提示不阻塞发布

#### Scenario: 分享页展示行程概览
- **Given** 用户对一条已结束且自己参加过的行程具备分享资格
- **When** 用户打开游后分享页
- **Then** 页面顶部展示内置封面、行程标题、目的地、日期与星期、同行人数与行程状态
- **And** 封面在 390 / 768 / 1440 宽度下都不横向溢出

#### Scenario: 分享页布局与原型一致
- **Given** 用户对一条已结束且自己参加过的行程具备分享资格
- **When** 用户在 1440 宽打开游后分享页
- **Then** 页面为双栏：主列三个输入分组（真实感受 / 路线强度 / 给后来者的一条建议），侧栏两个说明分组（体验去向 / 分享边界）
- **And** 路线强度以三张卡片呈现，选中卡片有底色，且可被读屏识别为单选
- **When** 视口收窄到 900px 以下
- **Then** 双栏收为单列，页面无横向滚动

#### Scenario: 分享页说明体验去向
- **Given** 用户正在填写游后体验
- **When** 用户查看页面说明
- **Then** 系统以三条文本说明：体验出现在原行程详情页、进入灵感首页「旅行体验」列表、别人可以「参考此行程发布」
- **And** 说明不只靠颜色或图标表达
