# user-credit 增量规格（add-credit-account）

## ADDED Requirements

### Requirement: 信用账户与初始分值

系统 SHALL 为每个账号维护唯一一份信用账户，记录当前信用分；信用分 MUST 为 0 到 100 之间的整数（含 0 与 100）。新账号注册成功后 MUST 立即拥有信用分为 80 的信用账户，且该初始化 MUST 与账号创建在同一事务内完成；注册失败时 MUST NOT 留下信用账户。系统 MUST 保证不存在没有信用账户的账号：无法通过注册路径建立的存量账号 MUST 由数据迁移补齐为 80 分。同一用户 MUST NOT 出现一条以上信用账户。

#### Scenario: 注册成功后初始化信用账户

- **Given** 访客使用尚未被占用的用户名与合法密码、昵称注册
- **When** 注册成功并返回会话
- **Then** 系统为该账号建立信用账户，信用分为 80
- **And** 打开其个人主页时展示「信用分：80 / 100 · 信用良好」

#### Scenario: 注册失败不留信用账户

- **Given** 用户名已被占用，或密码长度非法，或用户名格式非法
- **When** 访客提交注册
- **Then** 系统按既有规则拒绝注册
- **And** 不创建账号，也不创建任何信用账户

#### Scenario: 存量账号补齐初始分

- **Given** 账号不是通过当前注册路径建立的（含演示账号与更早注册的账号）
- **When** 读取该账号的个人主页
- **Then** 系统展示 80 分与「信用良好」
- **And** 不出现空值、0 分或错误页

#### Scenario: 同一用户只有一个信用账户

- **Given** 用户已拥有信用账户
- **When** 用户重复登录、刷新主页或多次读取资料
- **Then** 该用户仍只有一条信用账户记录
- **And** 读取本身不改变信用分

### Requirement: 分数区间与越界裁断

任何一次信用分变化 MUST 先经过 0–100 闭区间裁断：变化后高于 100 时取 100，低于 0 时取 0。系统 MUST 以「实际生效的变化量」记录本次变化，即变更后分数减变更前分数，MUST NOT 记录未生效的理论变化量。

#### Scenario: 上界裁断记录实际生效量

- **Given** 用户当前信用分为 98
- **When** 一次理论变化量为 +5 的变化被提交
- **Then** 信用分停在 100
- **And** 本次记录中的变更前为 98、变更后为 100、实际变化量为 +2

#### Scenario: 下界裁断记录实际生效量

- **Given** 用户当前信用分为 3
- **When** 一次理论变化量为 -10 的变化被提交
- **Then** 信用分停在 0
- **And** 本次记录中的变更前为 3、变更后为 0、实际变化量为 -3

#### Scenario: 分数始终落在闭区间内

- **Given** 任意账号与任意次数的变化
- **When** 读取该账号信用分
- **Then** 返回值始终为 0 到 100 之间的整数
- **And** 不存在大于 100 或小于 0 的信用分

### Requirement: 信用等级派生

系统 SHALL 由当前信用分实时派生信用等级，MUST NOT 把等级作为独立存储状态。等级区间 MUST 为：90–100 信用优秀、80–89 信用良好、60–79 信用一般、30–59 信用较低、0–29 信用风险；区间首尾相接、无空档、无重叠。信用分发生变化后，等级 MUST 在同一次读取中按新分数计算。

#### Scenario: 五档边界与区间闭合

- **Given** 信用分依次为 100、90、89、80、79、60、59、30、29、0
- **When** 读取该账号的信用等级
- **Then** 等级依次为「信用优秀、信用优秀、信用良好、信用良好、信用一般、信用一般、信用较低、信用较低、信用风险、信用风险」

#### Scenario: 等级随分数实时重算

- **Given** 用户当前信用分为 89，展示为「信用良好」
- **When** 一次 +1 的变化生效后再次读取个人主页
- **Then** 展示 90 分与「信用优秀」
- **And** 等级不出现滞后，也不需要额外刷新动作

### Requirement: 个人主页展示信用状态

个人主页 MUST 展示信用分与信用等级，且 MUST 同时给出具体分数（含 `/ 100` 上限）与等级文字，MUST NOT 仅用颜色、图标或纯数值表达等级。本人访问自己的个人主页与其他用户访问该主页 MUST 使用同一展示口径与同一数据源。资料尚未完善的用户 MUST 同样展示信用状态。

#### Scenario: 本人查看自己的信用状态

- **Given** 用户已登录并打开自己的个人主页
- **When** 页面加载完成
- **Then** 页面展示自己的信用分与等级文字

#### Scenario: 其他用户查看同一信用状态

- **Given** 任意已登录用户打开某用户的个人主页
- **When** 页面加载完成
- **Then** 展示的信用分与等级和该用户本人看到的完全一致

#### Scenario: 资料未完善仍展示信用状态

- **Given** 用户资料尚未完善
- **When** 打开该用户的个人主页
- **Then** 信用分与等级照常展示
- **And** 不因资料不完整而隐藏信用状态或报错

#### Scenario: 分数与等级文字同时展示

- **Given** 用户信用分为 80
- **When** 打开个人主页
- **Then** 页面同时输出「80 / 100」与「信用良好」
- **And** 不出现只靠颜色区分等级的展示

#### Scenario: 重复进入展示一致

- **Given** 用户已在个人主页看到自己的信用状态
- **When** 用户离开后重新进入同一主页
- **Then** 展示的分数与等级与上次完全一致
- **And** 不出现缓存分叉或短暂的空值

### Requirement: 信用分只读

信用分 MUST 只能由系统内部事件驱动变化。系统 MUST NOT 提供任何面向客户端（用户端或未登录访客）的写分端点。用户通过既有可写接口（如保存个人资料）提交信用分字段时，系统 MUST 忽略该字段，信用分 MUST NOT 改变。

#### Scenario: 用户提交信用分字段被忽略

- **Given** 用户已登录，当前信用分为 80
- **When** 用户在保存个人资料的请求中附带信用分字段（如 100）
- **Then** 资料按既有规则保存或按既有规则报错
- **And** 信用分保持 80 不变

#### Scenario: 不存在客户端写分端点

- **Given** 任何客户端身份
- **When** 尝试调用可修改信用分的接口
- **Then** 系统不存在该类端点，返回既有的未找到或未允许响应

### Requirement: 信用记录与记账服务

每一次信用分变化 MUST 在同一次写入中生成一条不可修改、不可删除的信用记录，包含变更原因、实际变化量、变更前分数、变更后分数、操作时间与关联业务标识。同一次变化对账户分数与信用记录的写入 MUST 处于同一事务：要么两者都生效，要么都不生效。信用记录 MUST 满足「变更前分数 + 实际变化量 = 变更后分数」，且前后分数均在 0–100 之间。携带相同业务标识的重复提交 MUST 只产生一条记录与一次分数变化。当一次变化被边界完全裁断（实际变化量为 0）时，系统 MUST 仍写入一条记录：变更前与变更后分数相同、实际变化量为 0，用于保留事件痕迹。

#### Scenario: 每次变化写入一条信用记录

- **Given** 用户当前信用分为 80
- **When** 一次变化将分数改为 75
- **Then** 系统写入一条信用记录，原因为该次变化的原因、实际变化量为 -5、变更前为 80、变更后为 75，并包含操作时间与关联业务标识
- **And** 账户分数与信用记录同时生效

#### Scenario: 记录满足前后分数等式

- **Given** 任意一条信用记录
- **When** 校验该记录
- **Then** 变更前分数加实际变化量等于变更后分数
- **And** 变更前与变更后均在 0–100 之间

#### Scenario: 重复业务标识只记一次

- **Given** 同一业务事件被重复提交两次
- **When** 两次提交使用同一业务标识
- **Then** 系统只写入一条信用记录，分数只变化一次

#### Scenario: 实际生效量为零仍留记录

- **Given** 用户当前信用分为 100
- **When** 一次理论变化量为 +5 的变化被提交
- **Then** 信用分仍为 100
- **And** 系统仍写入一条信用记录：变更前 100、实际变化量 0、变更后 100

### Requirement: 管理后台信用分视图与计分明细的边界

系统 MUST NOT 向任何用户展示加分 / 扣分明细、变更原因、变更时间或历史记录入口。个人主页以外的客户端界面 MUST NOT 展示信用分与等级。管理后台的信用分列表、用户详情、按信用分排序与按信用等级筛选由独立需求交付，本规格不定义其行为。

#### Scenario: 不存在管理后台信用分视图

- **Given** 任意用户
- **When** 访问应用现有路由
- **Then** 不存在管理后台用户列表或用户详情页面
- **And** 不存在按信用分排序或按信用等级筛选的入口

#### Scenario: 不展示加扣分明细

- **Given** 用户信用分已发生过变化
- **When** 本人或他人打开个人主页
- **Then** 页面不展示任何加分 / 扣分明细、变更原因、变更时间或历史记录
- **And** 页面不提供查看明细的入口
