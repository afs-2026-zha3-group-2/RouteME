# credit-enforcement 增量规格（add-credit-exit-restriction）

## ADDED Requirements

### Requirement: 退出原因与预计信用影响

系统 SHALL 允许已接受同行者在确认退出前从「个人原因 / 不可抗力 / 安全原因」中选择一项；原因缺失或非法时 MUST 拒绝退出且不改变任何数据。系统 MUST 在确认前向用户展示服务端计算的本次预计信用影响（含实际变化量与退出后分数），并在确认时重新校验；实际结果与预计不一致时 MUST 以实际结果为准并明确展示。三个退出入口（行程详情、我的旅行、聊天）MUST 使用同一原因集合与同一份服务端预计影响。退出原因、预计影响与信用明细 MUST NOT 展示给其他用户。

#### Scenario: 退出原因必选

- **Given** 用户是某行程的已接受同行者
- **When** 用户打开退出流程但未选择原因即确认
- **Then** 前端阻止提交并提示需要选择原因
- **And** 服务端同样以 400 `INVALID_INPUT` 拒绝
- **And** 同行关系、信用分与账本均不改变

#### Scenario: 个人原因 48 小时预计 -5

- **Given** 用户已 ACCEPTED、信用分 80、集合时间在 48 小时后、当月无已生效出发前退出
- **When** 用户选择「个人原因」并确认
- **Then** 预计影响显示「本次 -5，退出后 75 / 100」
- **And** 退出成功，信用分由 80 变为 75
- **And** 账本记录本次退出原因、实际变化 -5、变更前 80、变更后 75、关联行程与时间

#### Scenario: 三个退出入口一致

- **Given** 用户分别从行程详情、我的旅行、聊天页点击「退出同行」
- **When** 打开退出流程
- **Then** 三处都展示同一原因集合与同一份服务端预计影响
- **And** 确认后三处得到一致的实际结果
- **And** 前端不自行计算扣分

#### Scenario: 预计与实扣一致

- **Given** 用户已看到预计影响
- **When** 确认前该月新增了一次已生效退出
- **Then** 服务端在确认时重新计算并返回实际扣分
- **And** 页面以实际结果为准
- **And** 不出现「预计 -5、实扣 -10」的静默差异

#### Scenario: 集合时间优先与回退

- **Given** 行程 `meeting_time` 有值
- **When** 计算距出发时间
- **Then** 以该日期时间为基准
- **Given** `meeting_time` 为空
- **Then** 以 `start_date` 00:00（Asia/Shanghai）为基准
- **And** 发布者在退出后修改集合时间，已结算扣分不回溯变化

#### Scenario: 退出原因与明细不对外

- **Given** 用户完成退出
- **When** 其他用户查看该行程或该用户信用展示面
- **Then** 只看到既有分数、等级与「已退出」关系
- **And** 不看到退出原因、预计影响或加扣分明细

### Requirement: 出发前退出扣分阶梯与时间边界

系统 SHALL 按距出发时间对出发前退出应用固定扣分阶梯：距出发 ≥7 天扣 0；[3 天, 7 天) 扣 -3；[24 小时, 3 天) 扣 -5；[12 小时, 24 小时) 扣 -8；[0, 12 小时) 扣 -10。区间 MUST 左闭右开；恰好落在边界时 MUST 归入时间范围更大的档位（即左闭端所属档位）。出发前 ≥7 天退出 MUST 只记录事实、不扣分，且不计入当月退出次数。实际变化量 MUST 经过 0–100 裁断并写入信用账本；分数已为 0 时 MUST 记录实际变化 0，但该扣分事件仍计入当月次数。

#### Scenario: 出发前 7 天及以上只记录事实

- **Given** 距出发 ≥7 天
- **When** 用户选择「个人原因」并确认退出
- **Then** 信用分不变
- **And** 写一条零值信用记录，原因标识为「出发前退出无扣分」
- **And** 不计入当月退出次数

#### Scenario: 出发前 3–7 天扣 -3

- **Given** 距出发 [3 天, 7 天)
- **When** 用户以个人原因退出
- **Then** 本次扣 -3

#### Scenario: 出发前 24–72 小时扣 -5

- **Given** 距出发 [24 小时, 3 天)
- **When** 用户以个人原因退出
- **Then** 本次扣 -5

#### Scenario: 出发前 12–24 小时扣 -8

- **Given** 距出发 [12 小时, 24 小时)
- **When** 用户以个人原因退出
- **Then** 本次扣 -8

#### Scenario: 出发前 12 小时内扣 -10

- **Given** 距出发 [0, 12 小时)
- **When** 用户以个人原因退出
- **Then** 本次扣 -10

#### Scenario: 时间边界左闭右开

- **Given** 距出发恰好 7 天 / 3 天 / 72 小时 / 24 小时 / 12 小时
- **When** 用户以个人原因退出
- **Then** 分别扣 0 / -3 / -3 / -5 / -8
- **And** 少 1 秒时分别进入下一档（-3 / -5 / -5 / -8 / -10）

#### Scenario: 0 分下限裁断

- **Given** 用户当前信用分为 0
- **When** 一次出发前退出扣分事件发生
- **Then** 信用分仍为 0
- **And** 账本记录实际变化 0
- **And** 该事件仍计入当月退出次数

### Requirement: 旅行中退出与月度累进

系统 SHALL 对旅行中退出固定扣 -15，MUST NOT 对其翻倍，MUST NOT 计入当月出发前退出次数。同一自然月内第 2 次及之后的已生效「出发前退出」MUST 将本次扣分翻倍（-6 / -10 / -16 / -20）；第 3 次及之后 MUST 保持同样的翻倍值，不继续叠加倍率。重复或并发提交同一退出事件 MUST 只解除一次同行关系、只写一条账本、只改变一次分数。

#### Scenario: 旅行中退出固定 -15

- **Given** 当前时间已达到或超过出发基准，且行程未完成、未取消
- **When** 用户确认退出
- **Then** 本次扣 -15
- **And** 不翻倍、不计入当月出发前退出次数

#### Scenario: 同月第 2 次出发前退出翻倍

- **Given** 当月已有 1 次已生效的出发前退出扣分
- **When** 用户第 2 次以个人原因在出发前退出
- **Then** 按本次档位翻倍扣分（-6 / -10 / -16 / -20）
- **And** ≥7 天免责、旅行中、待核实退出不计入次数

#### Scenario: 第 3 次及之后仍翻倍

- **Given** 当月已有 2 次或以上已生效的出发前退出扣分
- **When** 用户再次以个人原因在出发前退出
- **Then** 仍按翻倍值扣分
- **And** 不再继续叠加倍率

#### Scenario: 退出幂等与并发

- **Given** 同一用户对同一行程快速确认两次或并发提交
- **When** 两次请求都到达服务端
- **Then** 只解除一次同行关系
- **And** 只写一条退出账本、分数只变化一次
- **And** 第二次返回成功或幂等结果，不重复扣分

### Requirement: 免责退出与待核实

系统 SHALL 在用户选择「不可抗力」或「安全原因」时暂不扣分，仍完成退出，并写入零值信用记录、标记为待核实；该退出 MUST NOT 计入当月退出次数。安全原因退出后 MUST 引导用户前往既有举报入口，但 MUST NOT 强制举报。当未来系统内部核实结果写入时：核实为真 MUST 不扣分、不计数；核实不属实 MUST 按实际退出时间确定档位，并按核实当时该月已有扣分次数取下一序号（不是第一次则翻倍），计入当月次数；MUST NOT 追溯调整其他已结算退出。本变更 MUST NOT 向客户端或管理员暴露核实入口。

#### Scenario: 不可抗力退出暂不扣分

- **Given** 用户是已接受同行者、信用分 80
- **When** 用户选择「不可抗力」并确认退出
- **Then** 退出成功，信用分仍为 80
- **And** 写一条零值信用记录并标记待核实
- **And** 不计入当月退出次数
- **And** 页面提示「暂不扣分，待核实」

#### Scenario: 安全原因退出暂不扣分并引导举报

- **Given** 用户是已接受同行者
- **When** 用户选择「安全原因」并确认退出
- **Then** 退出成功，信用分不变
- **And** 写一条零值信用记录并标记待核实
- **And** 不计入当月退出次数
- **And** 退出后展示既有举报入口，但不强制举报

#### Scenario: 待核实核实为真

- **Given** 存在一条待核实的免责退出
- **When** 系统内部核实结果为真
- **Then** 不扣分、不计入当月次数
- **And** 记录标记为核实为真
- **And** 信用分不变

#### Scenario: 待核实核实不属实

- **Given** 当月已有 1 次已生效出发前退出扣分，且存在 1 条待核实退出
- **When** 系统内部核实结果为不属实
- **Then** 按实际退出时间确定档位
- **And** 按核实当时该月已有扣分次数取下一序号（本例为第 2 次，翻倍）
- **And** 计入当月次数
- **And** 不追溯调整其他已结算退出

### Requirement: 信用限制触发与记录

系统 SHALL 在用户信用分低于 60 时自动建立信用限制，MUST NOT 需要管理员操作；分数等于 60 时 MUST NOT 触发。限制记录 MUST 记录触发原因 `CREDIT_SCORE_BELOW_60`、触发分数、触发时间与状态；同一用户在同一段限制期内 MUST 只有一条 active 记录。用户曾受限并解除后再次跌破 60 时 MUST 新建一段记录，历史 MUST 保留。信用限制与管理员因严重违规执行的人工封禁 MUST 分别记录；本变更 MUST 只产生自动限制记录。

#### Scenario: 跌破 60 自动触发

- **Given** 用户信用分为 65
- **When** 一次 -10 的举报核实扣分使分数变为 55
- **Then** 系统自动建立限制记录，原因为 `CREDIT_SCORE_BELOW_60`
- **And** 记录触发分数 55、触发时间与 active 状态
- **And** 无需管理员操作

#### Scenario: 60 与 59 边界

- **Given** 用户信用分为 60
- **When** 分数未低于 60
- **Then** 不触发限制
- **Given** 分数变为 59
- **Then** 触发限制

#### Scenario: 限制记录幂等

- **Given** 用户已处于 active 限制
- **When** 又一次扣分使其分数仍低于 60
- **Then** 不新增第二条 active 限制记录
- **And** 原记录不被覆盖
- **And** 限制状态保持

#### Scenario: 再次跌破 60 新建一段

- **Given** 用户曾受限并已解除
- **When** 分数再次低于 60
- **Then** 新建一条 active 限制记录
- **And** 上一段限制历史保留
- **And** 再次执行限制触发联动

#### Scenario: 限制与人工封禁分开

- **Given** 本变更上线
- **When** 检查限制记录与入口
- **Then** 只存在自动限制类型与 `CREDIT_SCORE_BELOW_60` 原因
- **And** 不存在人工封禁记录、管理员入口或人工解除入口
- **And** 未来人工封禁必须使用独立类型与独立记录

### Requirement: 受限账号只读与保留能力

受限账号 MUST 只能查看，MUST NOT 执行以下写操作：发布新行程、申请加入新行程、发布或编辑体验、编辑行程、发送聊天消息、编辑资料或头像，以及撤回申请、退出同行、取消或结束行程等其它写操作。上述写操作 MUST 由服务端以 403 `CREDIT_RESTRICTED` 拒绝，前端 MUST 不展示可用入口并给出限制原因。受限账号 MUST 保留查看首页、详情、我的旅行、个人主页、信用状态与聊天历史的能力，MUST 保留举报 / 安全入口，登录与退出 MUST NOT 受影响。限制触发时的并发写请求 MUST 以服务端当前限制状态为准拒绝。

#### Scenario: 不能发布新行程

- **Given** 用户处于信用限制
- **When** 尝试发布新行程
- **Then** 前端禁用入口并说明原因
- **And** 绕过界面调用返回 403 `CREDIT_RESTRICTED`
- **And** 不创建行程

#### Scenario: 不能申请加入新行程

- **Given** 用户处于信用限制
- **When** 尝试申请加入行程
- **Then** 前端禁用入口并说明原因
- **And** 服务端返回 403 `CREDIT_RESTRICTED`
- **And** 不创建申请

#### Scenario: 不能发布新体验

- **Given** 用户处于信用限制
- **When** 尝试发布体验
- **Then** 前端禁用入口并说明原因
- **And** 服务端返回 403 `CREDIT_RESTRICTED`
- **And** 不创建体验

#### Scenario: 不能编辑既有内容

- **Given** 用户处于信用限制
- **When** 尝试编辑既有行程或既有体验
- **Then** 服务端返回 403 `CREDIT_RESTRICTED`
- **And** 内容不变
- **And** 前端不展示可编辑入口

#### Scenario: 不能发送聊天消息

- **Given** 用户处于信用限制且仍有历史会话
- **When** 打开聊天并尝试发送消息
- **Then** 历史消息可查看
- **And** 发送被 403 `CREDIT_RESTRICTED` 拒绝
- **And** 页面提示限制原因与自动解除说明

#### Scenario: 不能编辑资料或头像

- **Given** 用户处于信用限制
- **When** 尝试保存资料或上传头像
- **Then** 服务端返回 403 `CREDIT_RESTRICTED`
- **And** 资料与头像不变

#### Scenario: 查看与举报保留

- **Given** 用户处于信用限制
- **When** 浏览首页、详情、我的旅行、个人主页、信用状态或聊天历史，或使用举报 / 安全入口
- **Then** 均可用
- **And** 登录与退出不受影响

#### Scenario: 限制状态下并发写请求

- **Given** 用户被限制的同时有并发写请求
- **When** 请求到达
- **Then** 服务端以当前限制状态拒绝
- **And** 不因前端缓存或竞态放行

### Requirement: 限制触发的自动清理

系统 SHALL 在信用限制触发时于同一事务内完成：撤回该用户全部待处理申请；解除该用户全部未结束行程（招募中 / 已满员 / 旅行中）的已接受同行关系；自动取消该用户全部未结束的已发布行程。系统清退 MUST NOT 按退出同行扣分，MUST NOT 计入当月退出次数。已完成与已取消的历史行程与关系 MUST 保持原样。自动取消 MUST 使用系统原因「信用分低于 60，账号受限」；该原因 MUST 仅对发布者与已接受同行者可见，其他用户 MUST 只看到「已取消」。

#### Scenario: 自动撤回待处理申请

- **Given** 用户处于信用限制且存在待处理申请
- **When** 限制触发
- **Then** 全部待处理申请变为已取消 / 已撤回
- **And** 发布者不能再处理
- **And** 该用户在「我申请的」看到对应状态
- **And** 不产生退出扣分

#### Scenario: 自动解除未结束同行关系

- **Given** 用户处于信用限制且存在未结束行程的已接受同行关系
- **When** 限制触发
- **Then** 全部关系解除
- **And** 已加入人数各减少 1
- **And** 满员行程恢复为招募中
- **And** 不产生退出扣分、不计入当月次数
- **And** 已完成 / 已取消历史保留

#### Scenario: 自动取消未结束已发布行程

- **Given** 用户处于信用限制且存在招募中 / 已满员 / 旅行中的已发布行程
- **When** 限制触发
- **Then** 全部自动取消
- **And** 待处理申请取消
- **And** 已接受同行者保留但看到已取消
- **And** 聊天只读
- **And** 新申请被拒绝
- **And** 不产生退出扣分

#### Scenario: 系统取消原因可见性

- **Given** 行程因信用限制被自动取消
- **When** 发布者或已接受同行者查看详情
- **Then** 看到系统原因「信用分低于 60，账号受限」
- **When** 其他用户查看详情
- **Then** 只看到「已取消」，不看到原因与限制细节

#### Scenario: 已完成或已取消历史不受影响

- **Given** 用户处于信用限制且存在已完成 / 已取消行程
- **When** 限制触发
- **Then** 这些历史行程与关系保持原样
- **And** 不重复取消或解除

#### Scenario: 系统清退不扣分

- **Given** 限制触发自动撤回 / 解除 / 取消
- **When** 检查信用账本与当月次数
- **Then** 不新增退出扣分账本
- **And** 不增加当月退出次数
- **And** 只记录限制与关系 / 行程状态变化

### Requirement: 限制展示与自动解除

系统 MUST 在受限用户本人的个人主页展示当前分数、等级、「限制中」、限制原因「信用分低于 60」与「分数回到 60 分及以上自动解除」；MUST NOT 展示加扣分明细或历史列表。他人查看该用户时，五个信用展示面（个人主页、资料弹窗、详情发布者行、行程卡发布者行、申请者行）MUST 展示「限制中」徽标，MUST NOT 展示限制原因。用户分数回到 60 或更高时，系统 MUST 自动解除限制、记录解除时间与原因，并恢复写能力；MUST NOT 恢复原申请、同行关系或已取消行程。

#### Scenario: 本人看到原因与自动解除说明

- **Given** 用户处于信用限制
- **When** 打开自己的个人主页
- **Then** 展示当前分数、等级、「限制中」、原因「信用分低于 60」与「分数回到 60 分及以上自动解除」
- **And** 不展示逐条明细

#### Scenario: 他人看到限制徽标但不看原因

- **Given** 受限用户出现在五个信用展示面
- **When** 他人查看
- **Then** 五个展示面都显示「限制中」徽标
- **And** 不显示限制原因
- **And** 分数与等级仍按既有口径展示

#### Scenario: 分数回到 60 自动解除

- **Given** 用户处于信用限制
- **When** 一次加分或调整使其分数回到 60 或更高
- **Then** 限制记录置为已解除，记录解除时间与原因
- **And** 只读守卫解除
- **And** 用户可再次发布、申请、发体验、聊天与编辑资料

#### Scenario: 解除后不恢复关系

- **Given** 用户因限制被自动撤回申请、解除同行关系、取消行程
- **When** 分数回到 60 以上并自动解除
- **Then** 原申请、同行关系与已取消行程不恢复
- **And** 用户需重新申请或被重新接受

### Requirement: 无管理员边界与事务一致性

本变更 MUST NOT 提供任何管理员角色、后台接口、后台页面、人工核实入口、人工解除入口或人工封禁入口；任何客户端身份 MUST NOT 能直接写入限制状态。一次扣分使分数跌破 60 时，分数变化、限制记录、撤回申请、解除关系与取消行程 MUST 在同一事务内完成；任一步失败 MUST 整体回滚，MUST NOT 出现「已扣分但未限制」或「已限制但未清理」的半状态。重复触发 MUST 幂等。

#### Scenario: 无管理端与无客户端写入口

- **Given** 任意客户端身份
- **When** 尝试调用核实、解除、人工封禁或直接写限制状态的接口
- **Then** 系统不存在该类端点
- **And** 按既有未找到或未允许响应处理
- **And** 限制状态只能由分数变化驱动

#### Scenario: 触发事务一致性

- **Given** 一次扣分使分数跌破 60
- **When** 限制触发
- **Then** 分数变化、限制记录、撤回申请、解除关系、取消行程在同一事务内完成
- **And** 任一步失败则整体回滚
- **And** 重复触发幂等

### Requirement: 退出说明与证明材料

退出弹窗 MUST 将「退出原因」作为标签文字展示，MUST NOT 把标签文字作为下拉的占位项；未选择原因时「退出同行」确认按钮 MUST 不可点击。选择安全原因或不可抗力时，用户 MUST 填写退出说明（≤200 字）后才能提交；个人原因的说明 MAY 选填。三种原因均 MAY 上传证明材料，最多 3 张、单张 ≤5MB，仅支持 JPEG / PNG / WebP。证明材料 MUST 先上传获得 id，再随退出提交绑定到退出事件；文件本体 MUST 存本地磁盘，数据库只存元数据，MUST NOT 在详情页或个人主页公开展示。待核实预览 MUST 只展示「暂不扣分，待核实」，MUST NOT 展示额外的核实流程说明。

#### Scenario: 未选原因时不能提交

- **Given** 退出弹窗已打开且未选择退出原因
- **When** 查看确认按钮
- **Then** 「退出同行」不可点击
- **And** 选择任一原因后才可点击（安全原因 / 不可抗力仍需填写说明）

#### Scenario: 标签不再作为占位项

- **Given** 退出弹窗已打开
- **When** 展开退出原因下拉
- **Then** 只展示「请选择退出原因」占位与三种原因
- **And** 不出现「退出原因（必选）」选项

#### Scenario: 安全原因 / 不可抗力说明必填

- **Given** 用户选择安全原因或不可抗力
- **When** 未填写退出说明直接提交
- **Then** 确认按钮保持不可点击
- **And** 绕过界面调用返回 400 `INVALID_INPUT`
- **And** 不写退出事件、不扣分

#### Scenario: 个人原因说明可选

- **Given** 用户选择个人原因
- **When** 不填写说明直接提交
- **Then** 可以正常退出并按档位结算

#### Scenario: 证明材料数量与格式

- **Given** 用户选择任一原因
- **When** 上传证明图片
- **Then** 最多 3 张、单张 ≤5MB、仅 JPEG / PNG / WebP
- **And** 超过数量或格式不符返回 400 `INVALID_INPUT`

#### Scenario: 证据仅落库不公开

- **Given** 用户已上传证明材料并提交退出
- **When** 他人浏览行程详情或个人主页
- **Then** 不展示退出说明与证明材料
- **And** 文件本体在本地磁盘、数据库仅存元数据

#### Scenario: 待核实预览只保留一行

- **Given** 用户选择不可抗力或安全原因
- **When** 查看预计信用影响
- **Then** 只展示「暂不扣分，待核实」
- **And** 不展示「退出后进入待核实；核实前不扣分，也不计入当月次数」

#### Scenario: 本人可回看退出记录

- **Given** 用户已完成一次退出（含系统清退外的主动退出）
- **When** 在「我的旅行 → 已退出」点击「查看退出记录」
- **Then** 展示退出原因、退出说明、退出时间、信用影响与待核实状态
- **And** 有证明材料时展示缩略图，可点开看大图

#### Scenario: 退出记录仅本人可见

- **Given** 用户 A 已退出某行程
- **When** 发布者或其他同行者尝试读取该退出记录或证明材料
- **Then** 退出记录返回 404、证明材料返回 403
- **And** 不泄露原因、说明或图片

#### Scenario: 退出记录只读

- **Given** 用户已提交退出说明与证明材料
- **When** 打开自己的退出记录
- **Then** 只能查看，不提供修改、补传或删除入口

#### Scenario: 系统清退无退出记录

- **Given** 关系由信用限制自动清退（无主动退出事件）
- **When** 本人尝试查看退出记录
- **Then** 返回 404 `LEAVE_RECORD_NOT_FOUND`
- **And** 前端提示「没有可查看的退出记录」

### Requirement: 同一行程可多次退出

同一用户对同一行程退出后 MAY 再次申请；再次被接受后再次退出 MUST 正常解除当前同行关系，并按当时的档位与当月序号结算，MUST NOT 返回首次退出的旧结果。每次退出 MUST 关联到本次同行关系（application）并单独记录；同一关系重试 MUST 幂等，不重复扣分。本人查看退出记录时 MUST 列出该行程的全部退出记录（按时间倒序）。

#### Scenario: 再次加入后退出生效

- **Given** 用户已退出某行程并处于 LEFT
- **When** 重新申请并被接受后再次选择退出
- **Then** 本次同行关系被解除
- **And** 按本次退出时间与当月序号正常结算

#### Scenario: 每次退出计入当月次数

- **Given** 同一用户在同一自然月内对同一行程已退出 1 次
- **When** 再次加入后第 2 次退出
- **Then** 月序号为 2，触发翻倍档位
- **And** 不因行程相同而跳过计数

#### Scenario: 记录列出全部退出

- **Given** 用户对同一行程退出过 2 次
- **When** 打开「查看退出记录」
- **Then** 列出 2 条记录（时间倒序）
- **And** 每条包含自己的原因、说明、影响与证明材料

#### Scenario: 同一关系重试幂等

- **Given** 一次退出已成功
- **When** 同一请求重试
- **Then** 返回该次退出结果
- **And** 不新增退出事件、不重复扣分
