# trip-plans 增量规格（refine-detail-companions）

## MODIFIED Requirements

### Requirement: 查看行程详情与清晰的状态

系统 SHALL 提供行程详情视图，展示完整途经点、起止日期、计划与当前人数、发布者资料与旅行兴趣、当前同行者与状态徽标；发布者 MUST 以独立资料卡展示头像、昵称、学校 / 专业（或职业 / 城市）、简介与兴趣标签；当前同行者区 MUST 以与发布者同构的资料卡展示「除发布者以外的已接受同行者」，每张卡 MUST 展示头像、昵称、学校 / 专业（或职业 / 城市），并在非空时展示简介与兴趣标签，整卡主体 MUST 可打开该同行者的公开资料，聊天入口 MUST 为独立可聚焦控件且可见条件不变；列表 MUST NOT 重复展示发布者；只有发布者时 MUST 展示可读空态；同行者人数口径 MUST 保持包含发布者；浅色 / 深色主题与 1440 / 1024 / 768 / 390 宽度下 MUST NOT 出现横向溢出；卡片样式 MUST 复用现有设计令牌，MUST NOT 新增十六进制色值；本能力 MUST NOT 新增或修改接口字段、端点、数据库迁移与契约版本，同行者资料 MUST 复用既有 `participants` 响应；同行申请入口 MUST 仅在「招募中且未满员且非本人发布」时可用，提交行为属 REQ-003；已结束行程的游后分享区内容属 REQ-004。

#### Scenario: 查看行程详情

- **Given** 用户在首页看到某条行程
- **When** 用户进入该行程详情页
- **Then** 详情页展示完整途经点、起止日期、计划人数与当前人数、发布者简介与旅行兴趣、当前同行者与状态徽标
- **And** 发布者以独立资料卡展示，资料卡包含头像、昵称、摘要、简介与兴趣
- **And** 当前同行者区以资料卡展示全部已接受同行者

#### Scenario: 同行者资料卡展示

- **Given** 一条行程包含发布者与 2 位已接受同行者
- **When** 用户查看该行程详情页
- **Then** 当前同行者区展示 2 张同行者资料卡
- **And** 每张卡展示头像、昵称、学校 / 专业（或职业 / 城市），并在非空时展示简介与兴趣标签
- **And** 发布者 MUST NOT 出现在同行者资料卡列表中

#### Scenario: 同行者字段回退

- **Given** 某位同行者缺少学校 / 专业 / 职业 / 城市 / 简介 / 兴趣中的部分字段
- **When** 用户查看该同行者的资料卡
- **Then** 昵称后的摘要按「学校 · 专业 → 职业 → 城市」回退，四者都为空时只展示头像与昵称
- **And** 缺失的简介与兴趣标签不渲染，MUST NOT 出现空占位、悬空分隔符或 `undefined` / `null` 文本

#### Scenario: 发布者不在同行者列表重复

- **Given** 行程详情的 `participants` 包含发布者与已接受同行者
- **When** 用户查看详情页
- **Then** 发布者只在上方「发布者」资料卡出现一次
- **And** 当前同行者列表 MUST NOT 包含发布者

#### Scenario: 没有其他同行者时的空态

- **Given** 一条行程只有发布者、没有其他已接受同行者
- **When** 用户查看详情页
- **Then** 当前同行者区展示可读的空态提示
- **And** MUST NOT 展示空列表、发布者姓名或破损卡片

#### Scenario: 打开同行者公开资料

- **Given** 用户查看某位同行者的资料卡
- **When** 用户点击卡片主体（头像或资料区）
- **Then** 系统打开该同行者的公开资料弹窗
- **And** 不跳转页面、不打开聊天；关闭弹窗后回到原详情页

#### Scenario: 同行者卡片聊天入口按资格显示

- **Given** 查看者是该行程发布者或已接受同行者
- **When** 查看者查看其他同行者的资料卡
- **Then** 卡片展示独立「聊天」入口，点击进入该行程与对方的会话
- **Given** 查看者未申请、申请待处理、已拒绝或已取消
- **When** 查看者查看同行者资料卡
- **Then** 卡片 MUST NOT 展示聊天入口
- **Given** 查看者就是该同行者本人
- **When** 查看者查看自己的资料卡
- **Then** 本人卡片 MUST NOT 展示自我聊天入口

#### Scenario: 同行者人数口径与排序不变

- **Given** 一条计划 4 人、已加入 3 人（发布者 + 2 位同行者）的行程
- **When** 用户查看详情页
- **Then** 页头展示「已加入 3/4 人」，人数口径包含发布者
- **And** 同行者资料卡的顺序与后端返回顺序一致，本变更不重排

#### Scenario: 窄屏与双主题不溢出

- **Given** 用户在 1440 / 1024 / 768 / 390 宽度与浅色 / 深色主题下查看详情页
- **When** 页面渲染同行者资料卡
- **Then** 卡片正常换行或堆叠，不出现横向溢出
- **And** 聊天入口不被遮挡，资料文字保持可读

#### Scenario: 状态标识清晰

- **Given** 一条行程处于招募中、已满员或已结束中的任一状态
- **When** 用户在卡片或详情页查看该行程
- **Then** 系统以文字明确展示其当前状态
- **And** 用户据此可判断该行程是否仍可加入

#### Scenario: 同行申请入口按资格显示

- **Given** 一条招募中且未满员的他人行程
- **When** 用户查看详情页
- **Then** 系统展示可用的同行申请入口
- **Given** 行程已满员、已结束，或由当前用户发布
- **When** 用户查看详情页
- **Then** 同行申请入口被隐藏或置灰

#### Scenario: 已结束行程展示游后分享区占位

- **Given** 一条已结束的行程
- **When** 用户查看详情页
- **Then** 页面展示游后分享区
- **And** 分享内容按 REQ-004 呈现，本能力只保留展示位
