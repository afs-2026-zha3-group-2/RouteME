# 变更提案：add-trip-companions

- **需求：** REQ-003（`requirement-workspace/requirements/REQ-003-trip-companions.md`）
- **能力：** `trip-companions`（ADDED）｜ **迭代：** 2–3「发现与连接 + 沟通」｜ **规模：** L（内部两阶段交付）
- **原型：** `docs/prototype/`（`prototype.html`、`stories.html` S07–S14、`store.js`）｜ **原型冲突裁决：** 以原型为准，见 §原型对齐决议

## 问题

REQ-002 建立了行程池与状态锚点，但用户之间还无法产生真实的同行连接。本提案新增 `trip-companions` 能力：让用户按目的地、日期与兴趣看到**可解释的匹配原因**，用一句说明提交同行申请，由发布者接受或拒绝；接受后人数联动、行程自动满员，双方进入一对一文字沟通；同时提供取消/退出/举报/安全提示等最低安全能力，并在一屏内聚合「我的旅行」。

## 范围

**In scope（业务能力与页面）**

- 匹配与理由：以「我最近一条未结束的已发布行程」为参照（没有则用我的兴趣 + 当前筛选）计算匹配分；目的地相同 +50、出发日期相同 +30、相差一天 +20、共同兴趣每项 +10 且合计不超过 +20；展示一句话理由（含命中的维度，可附百分比）；无重合时给「暂无重合，可作为新方向的灵感」。
- 灵感首页与详情：候选行程展示匹配理由，默认按匹配度排序（替换 REQ-002 的「按出发日期」默认值，用户仍可切换）。
- 同行申请：填写一句说明（选填，≤120 字）提交；不能申请自己的行程、不能重复申请（已有 PENDING/ACCEPTED）、已满员/已结束不能申请；提交后状态「待处理」，申请者可在被处理前取消。
- 发布者处理：仅发布者可查看自己行程的申请列表并接受/拒绝；接受后申请变「已接受」、已加入人数 +1、申请人进入同行者列表、达到上限自动「已满员」并关闭新申请；拒绝后变「已拒绝」。
- 退出同行：已接受同行者可退出（二次确认），人数 -1、聊天关闭、行程仍招募中时恢复可申请；发布者不提供退出，提示改用结束行程。
- 一对一文字沟通：仅已匹配双方可进入；消息持久化、按发送时间升序、手动刷新或短轮询；单条 ≤500 字；已结束行程聊天只读。
- 我的旅行：分区展示我发布的、我申请的、已匹配的、已完成的行程，并在有待处理申请时给出可点击提醒。
- 最低安全能力：详情页与聊天页常驻安全提示（公共场所集合、告知亲友、不公开电话/证件/住址）；举报入口（对象为行程或用户）提交后返回明确回执；MVP 不做举报处置后台。

**Out of scope**

- 行程浏览/筛选/发布/详情基础能力、结束行程（→ REQ-002，已归档）；游后体验与参考发布（→ REQ-004）。
- 原型中的批量接受/拒绝、保存筛选、拖拽改序、撤销、编辑/删除/取消行程：MVP 不实现，记录为后续增强。
- 复杂推荐算法、附近的人、滑卡匹配、无限私聊、实时位置、导航、紧急救援。
- WebSocket 实时、已读回执、推送、语音/视频/图片消息、实名认证、信用体系。

## 原型对齐决议

原型与初版 proposal 不一致处，按下表以原型为准收口（证据：`docs/prototype/store.js`、`stories.html` S07–S14）：

| 冲突点 | 初版 proposal | 原型 | 本 change 裁决 |
|---|---|---|---|
| 匹配展示 | 可解释原因，可选百分比 | 规则计分 + 一句话原因 + 百分比；无重合也有提示 | 按原型，百分比与维度文字同时展示 |
| 匹配参照物 | 未定义 | 我最近一条未结束行程；无则兴趣 + 当前筛选 | 按原型 |
| 申请说明 | 一句说明 | 选填，≤120 字，未填显示「未填写申请说明」 | 按原型（选填） |
| 申请列表 | 发布者处理 | 仅发布者可见；支持批量 | 单条处理纳入；批量列为后续增强 |
| 接受联动 | 人数 +1、满员停收 | 同左；满员自动 FULL；双方获得聊天权限 | 按原型 |
| 取消申请 | 处理前可取消 | 取消后释放名额，发起人侧同步 | 按原型 |
| 退出同行 | 退出解除关系 | 人数 -1、聊天关闭、可再次申请；发起人不能退出 | 按原型（发起人提示改用结束行程） |
| 聊天降级 | 可降级为留言区 | 已实现一对一聊天，手动刷新 / 短轮询 | 按原型，不做 WebSocket |
| 已结束聊天 | 未定义 | 只读或提示已结束 | 只读 |
| 我的旅行 | 五个分组 | 四个 tab + 待处理提醒；可分享体验属 REQ-004 | 四个分组 + 提醒 |
| 举报 | 记录即可 | 行程/用户为目标，原因 + 说明，回执 | 按原型 |
