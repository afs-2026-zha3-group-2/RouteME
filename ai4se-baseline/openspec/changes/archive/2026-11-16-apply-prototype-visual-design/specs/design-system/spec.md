# design-system 增量规格

## ADDED Requirements

### Requirement: 设计令牌与主题映射

前端 SHALL 以一套 CSS 变量（颜色、圆角、阴影、字体、间距、断点）作为唯一视觉取值来源，并把同一组取值映射到 Ant Design 主题，使原生组件与自定义组件呈现一致；新增样式 MUST 引用令牌，不得散落硬编码色值。

#### Scenario: 令牌可用且组件跟随
- **Given** 应用已加载
- **When** 检查根元素的计算样式
- **Then** `--bg`、`--surface`、`--ink`、`--lagoon`、`--coral`、`--line`、`--r`、`--sh-1` 等令牌存在
- **And** Ant Design 的按钮、输入框、卡片、选项卡边框与文字颜色与令牌一致

#### Scenario: 配色对比度
- **Given** 浅色与深色两套主题
- **When** 正文、次要文字、状态文字落在对应背景上
- **Then** 正文与背景的对比度 ≥ 4.5:1
- **And** 饱和原色只用于填充、渐变与装饰，不直接承载正文

### Requirement: 应用外壳与导航

已进入系统的用户 SHALL 看到一个固定顶栏与主内容区；顶栏 MUST 提供品牌入口、当前身份切换与深色模式开关；宽屏 MUST 提供左侧主导航，窄屏 MUST 提供底部导航；当前页面 MUST 在导航中可辨认。

#### Scenario: 顶栏与主导航
- **Given** 用户已选择演示身份
- **When** 用户进入任一页面
- **Then** 顶栏展示 RouteMe 品牌标记与「路觅」字样
- **And** 顶栏提供身份切换与深色模式开关
- **And** 左侧导航展示「旅行灵感 / 发布行程 / 我的旅行」，当前页对应项以背景与文字双重区分

#### Scenario: 导航跳转
- **Given** 用户在首页
- **When** 用户点击「发布行程」
- **Then** 路由切换到发布页且导航高亮随之变化
- **And** 点击品牌标记回到首页

#### Scenario: 窄屏导航
- **Given** 视口宽度 ≤ 900px
- **When** 用户浏览任一页面
- **Then** 左侧导航收起、底部标签栏出现
- **And** 三个导航项仍可到达对应页面
- **And** 页面无横向滚动

#### Scenario: 键盘可达
- **Given** 用户使用键盘
- **When** 用户在页面首部按 Tab
- **Then** 可跳过导航直达主内容区
- **And** 焦点元素有可见轮廓

### Requirement: 身份进入页呈现

身份进入页 SHALL 使用原型的信息层级：品牌、主标语、价值闭环说明与 3 张身份卡；每张身份卡 MUST 展示头像、昵称、学校、简介与兴趣标签，并可作为整体被选择；页面 MUST NOT 出现注册、验证码或找回密码入口。

#### Scenario: 展示三个演示身份
- **Given** 后端返回 3 个演示账户
- **When** 用户首次进入且尚未选择身份
- **Then** 页面以卡片网格展示 3 个账户
- **And** 卡片含昵称、学校、简介、兴趣与「以某身份进入」的动作
- **And** 不出现注册相关入口

#### Scenario: 选择身份进入
- **Given** 用户停在身份进入页
- **When** 用户点击任一身份卡
- **Then** 以该身份进入旅行灵感首页
- **And** 选择结果被持久化，刷新后不再要求重新选择

### Requirement: 首页信息层级

旅行灵感首页 SHALL 以问候横幅、视图切换、筛选面板、卡片网格四层呈现；横幅 MUST 只展示接口可得的真实统计；行程卡 MUST 展示理解一条行程所需的信息，且卡片整体可点击进入详情。

#### Scenario: 问候横幅
- **Given** 用户已进入系统
- **When** 用户打开首页
- **Then** 横幅展示按时段生成的问候语与当前用户昵称
- **And** 展示「招募中的行程」与「真实游后体验」两个真实计数
- **And** 展示匹配对照说明

#### Scenario: 行程卡信息
- **Given** 首页返回至少一条行程
- **When** 用户查看卡片网格
- **Then** 每张卡展示目的地、状态文字、标题、起止日期、路线摘要、兴趣标签、发布者昵称、已加入 / 计划人数与人数进度
- **And** 卡片整体为可点击链接，进入该行程详情

#### Scenario: 筛选与空状态
- **Given** 用户设置了筛选条件
- **When** 没有行程命中
- **Then** 展示空状态说明与「清除条件」「发布行程」入口
- **And** 已应用条件仍以文字摘要可见

### Requirement: 组件外观一致性

行程卡、体验卡、状态徽标、兴趣标签、筛选胶囊、聊天气泡与表单控件 SHALL 复用统一令牌与语义类名；状态徽标 MUST 同时用文字表达状态，不得只靠颜色。

#### Scenario: 状态徽标
- **Given** 行程处于招募中、已满员或已结束
- **When** 用户在卡片或详情中查看状态
- **Then** 徽标同时展示状态文字
- **And** 徽标的语义色与文字色满足对比度要求

#### Scenario: 体验卡
- **Given** 首页存在游后体验
- **When** 用户切换到「旅行体验」视图
- **Then** 卡片展示作者、强度、正文、给后来者的建议与来源行程
- **And** 提供「查看原行程」与「参考此行程发布」入口

#### Scenario: 表单与聊天
- **Given** 用户进入发布、申请、聊天或分享页面
- **When** 用户输入并提交
- **Then** 控件视觉与其他页面一致
- **And** 校验错误仍可就地看到
- **And** 聊天气泡区分自己与他人

### Requirement: 深色模式

系统 SHALL 提供浅色与深色两种主题，并 MUST 记住用户的选择；首次访问且无历史选择时 SHOULD 跟随系统偏好。

#### Scenario: 切换与持久化
- **Given** 用户处于浅色主题
- **When** 用户点击顶栏主题开关
- **Then** 页面切换到深色主题且控件、卡片、背景同步变化
- **And** 刷新页面后仍为深色

#### Scenario: 系统偏好
- **Given** 用户从未切换过主题
- **When** 操作系统为深色偏好
- **Then** 首次进入使用深色主题

### Requirement: 响应式与动效约束

布局 MUST 在 1440px、1024px、768px 与 390px 宽度下可用且无横向溢出；动效 MUST 保持克制，并在 `prefers-reduced-motion: reduce` 下关闭位移动画。

#### Scenario: 窄屏可用
- **Given** 视口宽度为 390px
- **When** 用户浏览首页、详情与表单
- **Then** 内容单列排布且不出现横向滚动
- **And** 导航仍可到达三个主页面

#### Scenario: 减少动效
- **Given** 用户启用减少动效偏好
- **When** 用户浏览页面
- **Then** 背景漂移与卡片入场动画不播放
- **And** 功能与信息不受影响
