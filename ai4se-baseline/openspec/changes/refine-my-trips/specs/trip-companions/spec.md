# trip-companions 增量规格（refine-my-trips）

## MODIFIED Requirements

### Requirement: 我的旅行聚合与最低安全能力

系统 SHALL 提供「我的旅行」分区视图（我发布的、我申请的、已匹配的、已完成的），并以带计数的分段控件呈现，默认展示「我发布的」；四组条目 MUST 可跳转到对应行程，并按分组提供已交付的行内动作：我发布的提供查看、处理申请与（旅行中）结束行程；我申请的提供查看与（待处理）撤回；已匹配的提供与发起人沟通、查看行程与退出同行；已完成的提供查看与发表 / 修改游后体验。存在待处理申请时，系统 MUST 显示待处理总数，并给出指向**存在待处理申请的那条行程**申请处理页的可点击入口；不存在待处理申请时 MUST 显示明确说明且不渲染空入口。页面 MUST 在重新可见（标签页重新可见或窗口获得焦点）与页内动作成功后重新拉取聚合数据，使四组与待处理数量与详情页状态一致。列表 MUST 在窄屏（≤640px）把行内动作换行到条目下方，且不与内容重叠。系统 MUST 在详情页与聊天页展示安全提示，提供以行程或用户为对象的举报入口，提交后返回明确回执，且不公开电话、证件与精确住址。

#### Scenario: 分区展示我的旅行
- **Given** 用户既发布过行程也提交过申请
- **When** 用户进入我的旅行
- **Then** 系统按我发布的、我申请的、已匹配的、已完成的四个分段展示
- **And** 每个分段显示该组条数，默认选中「我发布的」
- **And** 每个条目可跳转到对应行程或申请

#### Scenario: 分组内容与计数一致
- **Given** 用户有已接受申请、已结束行程与待处理申请
- **When** 用户切换分段
- **Then** 「已匹配同行」只包含未结束且申请已被接受的他人行程
- **And** 「已完成旅行」只包含用户参加过的已结束行程
- **And** 「我申请的」包含待处理、已接受、已拒绝与已取消的申请

#### Scenario: 行内动作按分组提供
- **Given** 用户在某一分组有条目
- **When** 用户查看该行
- **Then** 我发布的行显示「查看」与「处理申请」，待处理数大于 0 时入口带数量，旅行中的行另显示「结束行程」
- **And** 我申请的行在待处理时显示「撤回」
- **And** 已匹配的行显示「与发起人沟通」「行程」「退出同行」
- **And** 已完成的行显示「发表游后体验」或「修改我的体验」与「查看」

#### Scenario: 待处理申请提醒
- **Given** 用户发布的行程存在待处理申请
- **When** 用户进入我的旅行
- **Then** 系统显示待处理总数与可点击入口
- **And** 该入口打开存在待处理申请的那条行程的申请处理页
- **And** 该行程行内的「处理申请」入口带相同的待处理数

#### Scenario: 无待处理申请
- **Given** 用户没有任何待处理申请
- **When** 用户进入我的旅行
- **Then** 系统显示「目前没有待处理的申请」
- **And** 不渲染可点击的处理入口

#### Scenario: 重新可见时同步状态
- **Given** 页面停留期间用户在详情页接受、取消或退出，或行程状态发生变化
- **When** 标签页重新可见或窗口获得焦点
- **Then** 系统重新拉取聚合数据并更新四组与待处理摘要

#### Scenario: 页内动作后同步状态
- **Given** 用户在我的旅行执行结束行程、撤回申请或退出同行
- **When** 操作成功
- **Then** 系统重新拉取聚合并更新四组与待处理摘要
- **And** 用户不需要手动刷新浏览器

#### Scenario: 分组空态给出主操作
- **Given** 用户某分组为空
- **When** 用户切换到该分段
- **Then** 系统显示该组的空态说明与一个主操作（发布行程 / 查看行程 / 发现同行者）
- **And** 其它分组仍可正常切换

#### Scenario: 窄屏动作不遮挡
- **Given** 视口宽度 ≤640px
- **When** 用户查看任一分组
- **Then** 行内动作换行到条目下方
- **And** 动作不与标题、元信息或备注重叠

#### Scenario: 安全提示常驻
- **Given** 用户查看行程详情或进入聊天
- **When** 页面涉及线下见面或联系方式
- **Then** 系统展示「公共场所集合」「把行程告知亲友」「不公开电话/证件/住址」提示
- **And** 提示不能只靠颜色或图标表达

#### Scenario: 提交举报并收到回执
- **Given** 用户正在查看行程或与某用户聊天
- **When** 用户选择举报并填写原因与说明后提交
- **Then** 系统记录该举报并返回「已收到，我们会处理」的回执
- **And** MVP 不要求举报处置闭环
