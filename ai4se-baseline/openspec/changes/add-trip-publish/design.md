# 设计：add-trip-publish

## 结论

S06 的发布链路已由 `add-trip-plans` 与 `add-offline-map-place-picker` 落地，本次不新增数据表、不新增端点；工作集中在四件事：把 S06 的验收写成可判定场景、把人数边界的唯一读法写进规格、把端到端用例对齐当前的选点控件，以及按 REQ-007 协作把目的地字段改为省市级联 + `destination_code`（契约升 0.7.0）。

## 关键取舍

### D1 计划人数的边界读法

| 方案 | 行为 | 结论 |
|---|---|---|
| 字面 `capacity ≥ 1` | `capacity = 1` 可发布，发布后立即满员（只有发布者），无法再申请 | 否决 |
| 含发布者本人，`capacity ∈ [2, 12]` | `capacity = 1` 视为越界；`joined_count` 从 1 起算 | 采用 |

理由：`joined_count` 计入发布者本人（`TripPlan.create` 初始化为 1），`openapi.yaml` 的 `TripCreateRequest.capacity` 也是 `minimum: 2`。若把下限改成 1，会同时破坏「发布即招募中」与详情页「已加入 / 计划人数」的展示语义，并让 S08 的申请入口永远不可用。story 里的「≥ 1 的整数」按「至少 1 位同行者」解释。

### D2 字段级错误由谁给出

| 方案 | 行为 | 结论 |
|---|---|---|
| 后端逐字段返回错误对象 | 需要新错误结构，契约与既有 `INVALID_INPUT` 冲突 | 否决 |
| 前端 `validateTripForm` 逐字段给出，后端只做整体拒绝 | 现有实现；契约保持 `400 INVALID_INPUT` | 采用 |

理由：契约里已有「字段级提示由前端表单给出；后端校验失败统一返回 400」的说明。后端仍然独立校验，避免绕过前端写入脏数据；前端负责可读的逐字段提示。

### D3 端到端用例如何定位选点控件

| 方案 | 行为 | 结论 |
|---|---|---|
| 按旧实现定位（`getByLabel('途经点（每行一个，至少两个）')`、`ant-select-item-option`、`checkbox`） | 选点控件替换后选择器失效，用例必失败 | 否决 |
| 按控件自身的可访问名称定位（`搜索地图地点`、`listbox 地点候选`、`button` 标签） | 与实现解耦，改样式不影响 | 采用 |

理由：`PlacePicker` 的输入框固定 `aria-label="搜索地图地点"`，候选列表 `role="listbox" aria-label="地点候选"`，兴趣标签是带 `aria-pressed` 的按钮。以语义定位比 CSS 类名稳定。

### D4 是否新增可访问名称以支撑断言

`PlacePicker` 目前多处共用同一个 `aria-label`（目的地、途经点、集合地点各一个实例）。同一表单出现三个同名输入框时，`getByLabel` 会命中多个元素。因此需要给 `PlacePicker` 增加可选的 `label` 参数，由调用方指定区分性的可访问名称；未传时保留现有默认值，不影响其它页面。

### D5 目的地字段修订（REQ-007 协作）

| 方案 | 行为 | 结论 |
|---|---|---|
| 目的地继续用 `PlacePicker`（地图城市库 16 城） | 与全国省市/港澳台细分的筛选语义不一致；发布端无法产生香港 18 区/澳门 8 堂区等目的地 | 否决 |
| 目的地改省市级联 Cascader，请求 `destination_code` | 与筛选共用同一份 6 位区划字典；途经点/集合地点保留地图选点 | 采用 |

数据底座（V10、6 位码、字典、响应字段）由 `add-destination-area-filters` 提供；本 change 只负责发布页目的地字段与目的地校验/E2E。契约版本由 0.6.0 升至 0.7.0。本 change 不归档；归档顺序为 `add-destination-area-filters` → 本 change；G1 需在目的地修订完成后重评。

### D6 R2 目的地弹出层定位（2026-11-16）

| 方案 | 行为 | 结论 |
|---|---|---|
| 依赖 antd 默认 `getPopupContainer`（body） | 实测面板被算到 `x=-5670, y=-9070`，视口内不可见，用户点不到 | 否决 |
| `getPopupContainer` 挂到字段容器，配合 `width: 100%` | 面板相对字段定位，随表单滚动；宽度与字段一致 | 采用 |

根因：该表单的触发器位于 antd `Space` + `Card` 的组合里，弹出层的测量时机拿到的滚动/边界值异常。挂到字段容器后不再依赖 body 坐标。

### D7 R2 日期默认值

| 方案 | 行为 | 结论 |
|---|---|---|
| `new Date().toISOString().slice(0, 10)` | UTC 日期，东八区在 00:00–08:00 会显示「昨天」 | 否决 |
| 本地年/月/日拼接 | 与 `<input type="date">` 的本地语义一致 | 采用 |

默认值只影响初始值，`validateTripForm` 与后端校验不变。

### D8 R2 地图投影与目的地上下文

| 方案 | 行为 | 结论 |
|---|---|---|
| `viewBox 0 0 100 100` + `preserveAspectRatio="none"` | 100×100 的省图被拉进 500×230 的容器，横向压扁 | 否决 |
| `meet` + 容器固定宽高比 | 保持地理比例，留白自然 | 采用 |
| 未选目的地也渲染全图 | 与用户目的无关，且是全图最拥挤的一面 | 否决 |
| 未选目的地不渲染；选中后按该市点位算包围盒缩放 | 地图与目的地一致，顺带解决标签重叠 | 采用 |

城市映射：广东直接用市名；香港 / 澳门二级区（香港岛、九龙、新界、澳门半岛、离岛）映射到地名库的「香港」「澳门」。

### D10 R3 字典全国化后的映射与覆盖提示

| 方案 | 行为 | 结论 |
|---|---|---|
| 继续保留 16 城切片做映射 | 与 REQ-007 的全国字典并存，出现两份数据；全国城市一律无地图且提示错误 | 否决 |
| 映射读取共享 `area/areaOptions`，只保留「代码 → 地名库城市」一层 | 单一字典来源，删掉重复省市数据 | 采用 |
| 未覆盖城市显示整张全国地名库地图 | 与「按目的地展示」冲突，用户会以为地图属于该市 | 否决 |
| 未覆盖城市不渲染地图，改为覆盖说明 | 诚实表达能力边界 | 采用 |

实现约束：

- 前端新增 `areas/gazetteerCity.ts`：`gazetteerCityForCode(code)` 用 `findCity(code)` 取名，再判断地名库是否有该城市（港澳二级区归并到「香港」「澳门」）。
- `TripCreatePage` 用 `hasDestination` 区分两种无地图状态：未选 → 「先选目的地」；已选但无覆盖 → 「该城市暂无离线点位…」。
- 后端删除 `constant/AreaConstant`、`pojo/AreaCity` 与 `TripPlanServiceImpl` 的两条未使用 import；名称派生由 `area/AreaDictionary` + `AreaNames` 承担。

### D9 R2 布局与间距

- 表单分三段：基本信息（标题 / 目的地 / 日期 / 人数）、路线（途经点）、补充信息（集合区域 / 预算 / 标签 / 说明），段标题用 `h3`。
- 同组控件统一 `width: 100%`，行间距统一 `--space-4`（16px），段间距 `--space-6`（24px）。
- 日期两个控件在窄屏（< 560px）改为单列，避免挤压。

## 风险与例外

- **风险：** 端到端用例依赖本地后端与前端同时运行，且数据库是文件型 SQLite；用例会产生真实数据。`e2e` 用例已用时间戳标题区分，残留数据不影响断言。
- **例外：** 本 change 不修改 `openapi.yaml` 版本；契约字段与边界已满足验收，仅在 `tasks.md` 中记录核对结论。
- **遗留：** 业务端点仍以 `X-User-Id` 表达身份，属 `add-user-auth` 登记的残余风险，不在本 change 处理。
