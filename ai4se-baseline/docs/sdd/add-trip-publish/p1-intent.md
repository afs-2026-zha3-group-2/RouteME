## 5. 关键裁定（提案阶段）

| 裁定 | 内容 | 理由 |
|---|---|---|
| 人数口径 | 「≥ 1 的整数」按「含发布者、至少 1 位同行者」实现，即 `capacity ∈ [2, 12]`；`capacity = 1` 越界 | 已加入人数从 1 起算；`capacity = 1` 发布即满员，无法形成同行；与契约 `minimum: 2` 一致 |
| 字段级错误归属 | 前端表单逐字段提示；后端统一 400 `INVALID_INPUT` | 契约已如此定义，避免新增错误结构 |
| 选点控件 | 保留「必须能在地图地名库搜到」的约束 | 与 `add-offline-map-place-picker` 的既定行为一致 |

## 10. R2：用户评审后的体验修复（2026-11-16）

### 输入

用户 2026-11-16 对 S06 发布页的评审：

> 目的地目前无法点击选取，出发日期和结束日期应该有默认值，是默认今天，然后这个途径点的地图太丑了，并且这个地图是要根据目的地进行展示的，如果没有目的地选择和匹配情况下，地图就不需要展示，此外，调整一下组件布局和间距等，让看起来更加自然。

### 范围

**In scope（本轮 R2）**

- 目的地控件可用：下拉面板必须在视口内可见并可点选到市；控件撑满字段宽度。
- 日期默认值：出发日期与结束日期默认今天（本地日期），用户可改；不改变既有校验。
- 途经点地图与目的地联动：未选目的地时不渲染地图；选定后只展示该市的地图与候选点。
- 地图质量：不再横向拉伸，比例与留白自然；标签不重叠。
- 布局与间距：字段分组（基本信息 / 路线 / 补充信息）、控件全宽、统一间距。

**Out of scope**

- 换地图引擎、真实地图瓦片、拖拽排序途经点。
- 集合区域控件的行为变更（仍为文本 + 可选地图）。
- 目的地字典全国化（属 `add-destination-area-filters`）。
- 后端接口、契约字段变化（R2 只改前端与用例）。

### 裁定

| 编号 | 裁定 | 理由 |
|---|---|---|
| R2-1 | 目的地弹出层用 `getPopupContainer` 挂到字段容器，控件 `width: 100%` | antd v6 在该布局下把面板算到视口外（x=-5670）；挂到字段容器后定位稳定 |
| R2-2 | 日期默认今天，用本地日期格式化（不用 `toISOString`） | 避免 UTC 时区把「今天」算成昨天/明天 |
| R2-3 | 未选目的地时不渲染地图，只给一句引导 | 地图没有上下文时信息量为零，且最丑的一面正是全图 |
| R2-4 | 选定目的地后地图缩放到该市，只列该市的候选点 | 与「按照目的地展示」一致，也顺带解决标签重叠 |
| R2-5 | 地图改用 `preserveAspectRatio="xMidYMid meet"` + 固定宽高比容器 | 原实现 `none` 会把广东压扁成一条 |
